# Kongming 文档规范

## 概述

Kongming 文档标准：让每页可检索、新人可读、对 Agent 与维护者足够精确。先遵循仓库 [AGENTS.md](../../../AGENTS.md) 与实际执行的检查，再套用本技能的工作流程。每项事实单一归属：源码、测试、包 README、指南、开发备注各自保存一类真相。本技能由 DSH 子模块的文档技能改写而来；修改 `third_party/dsh` 内文档时改用子模块自身规则（见[与 DSH 子模块文档的关系](#与-dsh-子模块文档的关系)）。

## 工作流程

对每次请求的范围按以下顺序执行。保持常见读者路径简短，但不得为减少字数而删除失败处理、归属、限制等必要契约。

1. 阅读根 `AGENTS.md`、目标文档及其描述对象（源码、配置、包清单）、导航归属（如 [docs/README.md](../../../docs/README.md)）。
2. 按"一个主要职责 + 一类读者"分类：产品快速上手、用户任务指南、贡献者教程、架构总览、包/子系统参考、决策记录、历史修复报告。
3. 放到最近的归属处：包契约放在包代码旁（`packages/kmh-*/README.md`、`bundles/*/README.md`）；跨包学习、用户与开发者材料、架构讨论放 `docs/` 的现行目录。
4. 写细节前先定义读者的起点状态、可观察结果、可能的失败与恢复路径、下一步深入方向。
5. 写 frontmatter（见下节规则），然后按用户向内容到开发者向内容的顺序写正文；结构要求见 [structure-hierarchy.md](references/structure-hierarchy.md)。
6. 核对每条论断：源码、测试、包元数据或当次实际执行；页面指示的操作要亲自运行（见下文事实核查）。先更新归属，再更新引用它的衍生文档。
7. 运行相关检查，重读完整 diff：先查正确性，再查篇幅、导航与仓库契合度。

## frontmatter 规则

Kongming 文档的 frontmatter 只保留 `description` 一个键；技能文件（SKILL.md）为 `name` 与 `description` 两个键。

- `description` 说明页面覆盖什么、读者何时打开它，一到两句具体描述，包含可检索的领域词，与相邻归属页面区分开。
- 页面标题已承担命名职责，受众由内容与落点表达，不重复进 frontmatter。
- 不引入 `kind`、`tags`、`audience` 等元数据字段：Kongming 目前没有消费这些字段的检查或检索工具。确需新增时，先提供对应的机械检查与消费方，再扩字段。

## 事实核查：测试，而非假设

文档描述产品当前行为，操作类论断唯一可接受的证据是亲自运行过。此流程对新文档，以及任何声称命令、默认值、报错或平台差异的新段落，都是强制的。

1. **先分类，再写使用或接入指引。** 读事实而非目录名：`package.json` 与入口文件判定包形态——`src/index.ts` 导出 `apply` 或默认服务的是 Cordis 插件，经 `cordis.patch.yml` 挂载行接入；纯模块 API 是库，作为依赖被引用、无独立挂载路径；`bundles/` 下的目录是 bundle 包，由 profile 声明选择。不同形态各有归属的 README 写法（见[包 README 模板](templates/package-readme.md)），不要给库写挂载配置。
2. **对当前 checkout 运行每条声称的操作。** 按文档将要展示的样子执行命令、配置片段与 profile 示例；只记录观察到的输出、警告与失败模式。若论断依赖你没有的密钥或网络，说明这一点并指名验证归属，不要断言行为。
3. **删除无法复现的内容。** 不凭记忆、类比或相邻包的 README 携带命令、字段、默认值或行为。复现失败时修正论断，而不是修改测试。
4. **修订旧文档先对照现状。** Kongming 层表述对照当前主分支代码；涉及子模块行为的表述以当前子模块版本与实际运行结果为准。

## 表述规则

这些规则决定一个章节可以写什么，适用于所有成文的读者向页面，对包 README 尤其严格。

- **概述讲"能做什么"。** 开头的概述与用户向章节描述读者能做什么——结果、收益、何时选择、主要代价——而非其角色、类型或内部身份。"插件注册了 `ctx.x` 并追加 `x/event` 记录"是身份叙述；"你可以为每条消息保存笔记且重启后保留"是能做什么。省略读者不在配置、命令或公开 API 中直接使用的源码标识。
- **开发者章节解释而非罗列。** 折叠的实现内容覆盖设计概念、架构与粗粒度数据流——足以理解包如何工作——并链接代码给出精确细节；不在折叠内罗列完整 API 目录、字段清单或复述注释文档。
- **开发备注是唯一的草稿区。** 半成品想法、待定方向、工作假设只出现在末尾开发备注，并明确标注非权威；其余章节都是成品化的当前状态描述。
- **只写当前状态。** 普通文档描述当前代码库。升级指南只描述其对应版本的变更；`docs/fixes/` 与 `docs/research/` 的历史材料按历史实现阅读，不与现行文档混排。
- **受控技术表述。** 中文文档同样要求每句有明确主语与一个主要动作，一个概念一个术语，拆分堆叠的指令与条件，保留模态与例外——"必须""可以""禁止"、时机、数字等契约词不因简化而删除或加强。细则见 [style.md](references/style.md)；完整命题规则由 [kmh-prose-standard](../kmh-prose-standard/SKILL.md) 承担。

## 质量标准

评审时使用以下定义。每个实质性章节在进入小节或穷举细节前，先有一段简短导入。

- **简洁：** 常见路径只包含达成其结果所需的事实；穷举真相保持一次直接链接或一层折叠的距离。
- **直观：** 前置概念先于依赖概念，下一个动作显而易见，标题使用读者会检索的词。
- **友好：** 读者能识别成功、行动前理解风险、从可能的失败中恢复、自行决定是否深入。
- **准确：** 每条持久论断有一个归属和与风险相称的验证路径。
- **Agent 可检索：** 稳定的标题、锚点、术语、归属与状态支持定向检索，无需装载全部语料。
- **新人可完成：** 无仓库背景的工程师经三到五个链接页面即可重建相关架构或功能。

不对穷举式参考页套用统一字数上限。衡量入口路径长度、一次检索需扫过的无关材料、最大章节、标题数量与页面体积；检索成本高时按既有领域归属拆分。

## 排查语料赘述

结构梳理之后，用最廉价的探针先查赘述清单：用 [kmh-trim-cot-leakage](../kmh-trim-cot-leakage/SKILL.md) 清理推理过程泄漏；grep 特征短语找出重复的规则，把手工维护的清单与状态盘点替换为其权威归属；从已实现的文档中移除迁移计划与将来时的规格语言。若删除某段文字会改变承诺的行为而非其解释，先提议行为变更（参照 [kmh-find-simplifications](../kmh-find-simplifications/SKILL.md)）。保留每条承重规则，最好压缩为一到三行加一条指向理由的链接；不要为了安置一次性推理而新建解释页。

## 文档落点约定

根 `AGENTS.md` 的文档规则是本技能的落点基准：

- 需要使用者或维护者知晓的前提、操作、失败处理、适用范围与维护归属，随改动写入其所属文档。
- 每项说明集中在一个位置，其他位置通过链接引用；文档记录当前行为与可验证入口。
- 命令说明以实际执行结果为依据。
- 文档按本技能与 [kmh-prose-standard](../kmh-prose-standard/SKILL.md) 组织说明。

## 与 DSH 子模块文档的关系

Kongming 后端由子模块 `third_party/dsh` 提供，两侧文档规则分工如下：

- **修改子模块内的文档**遵循子模块自己的规则：先读其 `AGENTS.md` 与文档写作规则，参照 [dsh-doc（子模块原技能）](../../../third_party/dsh/.agents/skills/dsh-doc/SKILL.md)。该技能规定双语行对齐、kind 元数据、文档网站等子模块机制；本技能不重复其内容。
- **子模块的配套检查**（翻译配对、文档门禁）按 [DSH 技能接入](../../../docs/kmh/skills.md) 的说明以子模块为工作目录运行；Kongming 自有文档不使用这些检查。
- **Kongming 文档引用子模块机制**（bundle 语义、插件形态、配置键）时，只保留读者需要的部分并链接归属（如 [Web 插件索引](../../../docs/kmh/plugin-index.md) 或上游包 README），不复制上游字段清单。

## 验证

Kongming 目前没有专门的文档检查脚本，文档改动的验证由三部分组成：

1. **链接目标存在。** 相对链接逐个核对到真实文件；引用子模块路径的链接在子模块初始化后核对。
2. **所述命令实际运行。** 按事实核查流程执行；命令在 Kongming 根目录运行，子模块专属命令按 [DSH 技能接入](../../../docs/kmh/skills.md) 的目录约定运行。
3. **伴随改动的既有检查。** 启动与配置变更运行 `pnpm test`，脚本修改运行 `pnpm lint`；推送前的检查参照 [kmh-pre-push-checks](../kmh-pre-push-checks/SKILL.md)。

最后重读完整 diff 两遍：第一遍查事实完整性，第二遍查篇幅、导航与归属。
