# 页面文风

## 概述

让页面可扫读、难以误读的页面级文风约定：短概述、受控技术表述、`-----` 分节线、保持标题可见的 `<details>` 折叠、克制的强调。包 README 的现行参考示例见 [packages/kmh-echo/README.md](../../../../packages/kmh-echo/README.md)。

## 短概述

每个成文页面以三到五句的概述开头，一段说清读者能做什么或观察到什么、为什么关心、主要运行模型与最重要的边界。细节交给目录与各章节；章节顺序与页面位置见 [structure-hierarchy.md](structure-hierarchy.md)。

## 受控技术表述

借鉴 ASD-STE100 的自查思路处理需要 Agent、译者或不熟悉领域的读者解析的文字。这是一条澄清纪律，不是认证合规；仓库不复现或校验该标准的受控词表。原文针对英文行文，中文文档按同等意图执行：

- 点名主语与动作；主语重要时用主动语态。
- 一个概念一个稳定术语，不为行文变化轮换同义词。
- 优先直接动词；有精确动词时替换名词化与含混的动词短语。
- 一句一个指令；三步以上或三个条件以上改用列表。
- 拆分分号与长从句链；每段只谈一个主题。
- 删除无依据的品质形容词与堆叠的限定语；保留原文全部事实与不确定性。

以 20 字的指令、40 字的描述作为复查提示，而非机械门禁；拆分会隐藏条件或关系时保留长句。绝不为了缩短而删除或加强"必须""可能""禁止"、时机、例外、数字等契约词。完整命题规则由 [kmh-prose-standard](../../kmh-prose-standard/SKILL.md) 承担。

## 分节分隔线

页面的主要部分之间用独立成行的 `-----` 分隔，前后各留一个空行。紧跟段落的分隔线会被解析为 Setext 标题。分隔线加在哪个部分之间由各模板规定，例如包 README 模板分隔：frontmatter → 用途章节 → 折叠实现章节 → 验证章节。

## 可折叠内容章节

开发者向细节与末尾开发备注用 GitHub 原生 `<details>`/`<summary>` 折叠。章节标题（H2 或 H3）与其 `<a id>` 锚点保持可见，只折叠标题下的内容。块内注意：`<summary>` 之后留一个空行；每行 Markdown 顶格书写（缩进内容会变成代码块）；空行之后接 `</details>`。折叠内的标题、列表、表格与链接正常解析并保留锚点。

## 强调纪律

加粗只保留给改变行为的从句或真正重要的对比。基准表格中加粗列头与每行的最优值。
