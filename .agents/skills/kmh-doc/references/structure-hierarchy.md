# 页面结构与层级

## 概述

每页先给新人一个简短前门，再展开操作或实现深度。跨包学习与工程材料放在 `docs/` 的既定层级，包契约放在包代码旁。小规则文件各自拥有一个可独立检索的要求，但不追求任意拆分。末尾的开发备注把进行中的工作上下文与上方稳定的解释隔开。

## 页面顺序

成文的读者向页面按以下顺序组织（章节名以中文书写，与 docs/ 现行文档一致）：

1. YAML frontmatter：仅 `description`（SKILL.md 另有 `name`），规则见 [SKILL.md](../SKILL.md#frontmatter-规则)。
2. H1 标题。
3. `## 概述`：三到五句，说明读者能做什么、为什么关心、运行模型与最重要的边界。
4. `## 目录`：链接本页各 H2；保持导航性而非描述性。
5. 稳定内容，从用户向使用到开发者向设计与运维细节。
6. 可选 `## 进一步探索`：面向新人的相邻主题链接。
7. 末尾 `## 开发备注`：非权威的进行中工作上下文。

不要给极小的机器所有文件、生成片段，或已由所属格式解析器定义头部的文档强套概述/目录包装；豁免在格式归属处声明，而不是产出无效文档。

## 小节递进

每个实质性 H2 以一段简短导入开头，再进入表格、代码或 H3 小节：解释本节主题与决策相关要点，不复述其完整内容。

页内按读者深度排序：

1. 基础使用：何时选择该功能、必要输入、最短安全示例、可观察的成功标志、可能的恢复方式。
2. 进阶使用：配置选择、限制、运维操作与集成行为。
3. 开发者细节：归属、生命周期、数据模型、失败模式、性能、安全与值得维护的扩展点。

把重型的开发者细节与末尾开发备注折叠进 `<details>` 块，标题保持可见（机制见 [style.md](style.md)）。折叠内容解释总体设计、主要组件架构与数据流，插件文档还需按[脚本与关键函数说明](../SKILL.md#插件的脚本与关键函数说明)逐个讲清脚本的用途、实现机制与关键函数，并链接源码。完整 API、字段与事件载荷清单链接其权威归属。开发备注是唯一允许容纳半成品想法、草稿与待定方向的位置；其余内容（含折叠内）都是成品化的当前状态描述。

穷举式类型、schema 或目录放在一段紧凑入口与稳定索引之后；一次检索需要扫过无关分组时，按既有领域归属拆分。

## 文档层级

包契约放在包代码旁：`packages/kmh-*/README.md` 与 `bundles/*/README.md` 各自承担用途、配置键、验证命令与归属链接（见[包 README 模板](../templates/package-readme.md)）。跨包学习、用户与开发者材料、架构讨论放 `docs/`，按读者与学习意图归入现行目录，而不是平铺在 `docs/` 根。

`docs/` 现行布局（权威入口为 [docs/README.md](../../../../docs/README.md)）：

```text
docs/
  kmh/            # DSH 底座接入、配置、插件与技能说明
  architecture/   # 总体架构、模块拆分与架构参考
  operations/     # 开发环境、运行、部署流程
  integrations/   # 外部系统接入文档
  spec/           # 需求包与阶段方案
  product-design/ # 设计稿与产品形态
  research/       # 调研与参考材料
  fixes/          # 历史修复报告
```

把这张树当现状索引，不是发起大规模搬家的许可。一次移动一个连贯主题，同一改动中修复所有入链；历史材料（`fixes/`、`research/`、归档目录）按历史实现阅读，不与现行文档混排。

## 小规则文件

一条可独立检索的规则、实践、示例族或决策，当它有自己的归属、变更节奏、入链或验证时，给它一个小文件；相关文件归入有描述性的层级目录。拆分会让读者为理解一个义务打开多个文件时，保持紧密耦合的规则在一起。

索引页用三到五句解释目录用途，并按目的链接直接子项；不复述每个子项的规则。

## 进一步探索

可选章节，服务读完本页还想了解相邻主题的新人。链接三到七个直接相关页面，从最近前置到更深入排序，每条用短语说明该链接带来什么。不做成全站索引。

## 开发备注归属

成文页面以开发备注收尾，但保持明确的非权威地位。进行中的假设、兼容性顾虑、粗略备选、进度指针与未决问题可以放在那里；稳定行为、必要限制与已接受的取舍属于各自的常规归属。

开发备注可以镜像或链接任务进度，但不得变成第二个可写队列。工作收尾时：沉淀持久结论，可复用的取舍移入归属文档，已解决的讨论删除；Git 历史保留旧的迭代。

## 开发备注

末尾章节刻意是成文页面最不打磨的部分，但仍有生命周期纪律。空白的开发备注写"无。"，不堆积占位文字；生成或解析器所有的格式可按具名豁免省略。
