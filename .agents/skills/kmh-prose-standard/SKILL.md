# KMH 文字规范

先写出足以保住契约的文字，再删去推理过程、重复与装饰。契约是调用方、被调用方、实现者、生产者或消费者所依赖的义务、不变量、前置条件、后置条件或兼容承诺。本技能负责编辑判断与各处必需的文字覆盖；说明的落点与验证方式见 [DSH 技能接入](../../../docs/kmh/skills.md) 的文档规范（深入子模块写作时参照 [dsh-doc](../../../third_party/dsh/.agents/skills/dsh-doc/SKILL.md)）；排查与修复推理痕迹式文字见 [kmh-trim-cot-leakage](../kmh-trim-cot-leakage/SKILL.md)。本技能是指导，不是脚本。

把 `contract`、`boundary`、`shape`、`surface`、`seam`、`gate`、`vocabulary` 当作使用前需要核对的词，而不是禁用词。先问精确的规则、API、字段集、类型、校验、时点或组件拆分是否已把事实说清，再决定用不用抽象词。当术语指向确切的技术主体（包括调用方/被调用方契约和安全或进程边界）时保留它。

类型先行：Kongming 层的 TypeScript 使用严格类型与包名导入，让类型承载它能表达的契约。注释描述代码与类型都表达不了的非显然契约或理由；不复述代码已经隐含的内容。

## 适用范围与输入

要求显式给出 `scope`。缺失时报告所需输入并停止；不要推断全仓库范围，也不要开始访谈。

接受 `mode: automatic | interactive`，默认 `automatic`。仅当用户明确要求提问或校准时进入交互模式。

`mode` 控制是否提问，不控制写入权限。审查与审计任务只报告发现、不改动；明确要求的写入、修复或精简任务执行清晰的修改。

默认把 `third_party/` 排除在发现、审查与编辑之外，即使请求的范围是整个仓库；子模块内的文字遵循子模块自己的规则（参照 [dsh-prose-standard](../../../third_party/dsh/.agents/skills/dsh-prose-standard/SKILL.md)）。不要跟踪符号链接进入其中：把排除放在包含之后，防止后续的包含把它重新纳入——例如让 ripgrep 命令以 `--glob '!third_party/**'` 结尾，给 Git 命令显式的 `:(exclude)third_party/**` pathspec。若请求的范围只包含 `third_party/`，报告没有可处理的文件。

归档的笔记快照（DSH 子模块的 `.agents/notes/archived/`）视为冻结：只为理解历史入站引用而查看确切目标，从不现代化其文字或出站链接。

把生成目录、快照与测试夹具当作派生物。编辑前追溯每个消费者：源 JSDoc 可能同时喂给生成的、模型可见的目录。先编辑拥有它的源或场景，再重新生成每个派生物。当生成器从拥有者的文字中提取摘要时，保证被提取的句子在该表面上自足。Kongming 文档当前为简体中文单语，没有双语配对负担；涉及子模块内的双语文件时遵循子模块的配对规则，不在 Kongming 层单侧修改。

## 保住完整命题

编辑前，识别段落中的每个命题。保住每个相关的：

- 行为者与动作；
- 条件、时点与顺序；
- 情态，如必须、可以、绝不；
- 负面保证与例外；
- 归属、副作用、失败模式与后果。

只有当每个事实分句都存活且结果更清晰时，才删去形容词、重复与叙述。字数更少本身不是改进。

在使用点保留完整的本地契约：调用方或维护者在该处需要的行为、失败、归属与后果。架构、理由、算法、历史或扩展示例则坚决链接到拥有它的文档。一项说明集中在一个位置，其他位置通过链接引用；必要的契约事实可以在本地重复。

当省略非显然的理由可能引起误用或错误简化时，保留它。否则说明后果并链接理由的归属文档。

## 按文字位置的必需覆盖

这不是单向的缩短。当代码、类型与结构无法传达下面的必需契约时，补写或恢复文字；这些事实在本地已显然时不加注释。文档记录当前行为与可验证入口。

- **公共 JSDoc：** 说明调用方可见的返回差异、抛出或拒绝、副作用、归属、时点、取消与持久性。Kongming 约定：函数注释说明输入、输出与失败行为。
- **内部注释：** 为非本地的结构和显然复杂的本地结构定位，包括不变量、竞争顺序、归属、安全边界与出人意料的失败行为。删除控制流叙述和代码复述。
- **模块注释：** 说明模块的角色、依赖、职责与非显然的架构选择；把架构选择链接到拥有它的解释。
- **测试：** 只解释非显然的测试设计——为什么某个夹具、断言、平台适配、真实入口路径或间接观察是必要的。删除走查与清单。
- **自有脚本（scripts/kmh.mjs 等）：** 文件顶部用中文说明功能与关键函数；函数注释说明输入、输出与失败行为。
- **操作说明（docs/operations/ 等）：** 包含前置条件、必需动作、真实入口路径、可观察的验证与简明的警告。
- **README：** 说明消费方契约：配置、语义、失败、限制与扩展点。引用由本包拥有的稳定对外文字；生成的目录与跨包的归属用链接。保留持久的缺口与维护者陷阱，不保留普通的清理清单。
- **设计笔记与复盘：** 保留独特的理由、机制、备选方案、后果、已交付的验证证据与点名的覆盖缺口。已落地的笔记用现在时陈述已交付的现实；删除计划清单，不删固定决策的证据。复盘保留事件序列、证据、因果链、影响与预防，删除重复的劝说和不建立因果的实现细节。
- **技能与 Agent 指令：** 声明行为护栏与明确的范围限制（如"是指导，不是脚本/清单"）。工作流保持简洁，并链接其事实来源。
- **示例与配置注释（launch.config.json、profiles/、bundles/ 等）：** 解释访问限制、非显然的接线或加载顺序、安全立场、回放行为、例外与易误用之处。不要叙述配置自身已经展示的条目。
- **提示词与可见文案：** 把措辞当作行为。改变模型或用户可见的文字时，必须有拥有它的行为改动与验证入口；若授权范围内没有拥有该文案的场景，保持措辞不变并报告推迟，不得悄悄并入纯文字改动。
- **诊断信息：** 指出失败的主体或路径、被违反的规则，以及非显然时的修正方式。删除内部执行叙述。

保留可检索的机制名称和有意义的情态、时态或负面强调。只规范装饰性强调。

## 工作流

1. 确认范围、模式、当前分支或 PR 基线，以及适用的 `AGENTS.md`。不要查看无关分支。
2. 判断文字前，先读根 `AGENTS.md` 的相关约定和拥有该文字的代码或文档。校准或不熟悉时读[精炼示例](references/examples.md)。
3. 检查请求的范围，而不只是最大的文件。用搜索和字数找候选，再按语义判断段落。
4. 把每个候选分类为保留、补写、精简、恢复、重组或推迟。只在任务授权改动时执行清晰的修改；不为凑删除量制造改动。
5. 先更新拥有者，再更新派生物。学到新规则后复查同类段落。
6. 运行窄范围的相关检查：配置或启动变更跑 `pnpm test`，脚本改动跑 `pnpm lint`；可见文案配合行为测试；另跑 `git diff --check`。提交时按仓库约定把代码、测试与文档分开提交。当任务范围仅为 Kongming 层时，确认最终 diff 不含 `third_party/` 路径；出现意外匹配要如实报告，而不是声称排除历史干净。
7. 报告检查过的范围、清晰的修改、有意保留、推迟的情况与实际运行过的检查。

## 边界情况

禁止未经用户同意就修改 'third_party/dsh' 代码，修改必须经过严肃仔细讨论。

只有当至少两个版本都满足完整命题规则但各自牺牲了不同的公认原则，且本技能没有解决该取舍时，才算边界情况。只有一种保命题答案的改写不是边界情况。

自动模式下，授权时执行清晰的修改并报告真实的边界情况，不提问。不为推进而削弱命题。

交互模式下，把同类段落归入同一主导原则。给出两到三个可行版本，推荐其一，并说明事实或结构差异。不要提供劣质的干扰项。使用用户要求的渠道；通过 PR 行内评论校准时，把推荐的临时版本放进 diff，把备选挂到同一行。

用户决定后，把原则和版本提炼进[示例](references/examples.md)，不带 PR 历史或评审叙述，并把学到的规则应用到范围内每个同类段落。
