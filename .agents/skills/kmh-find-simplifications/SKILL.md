# Kongming 层简化点发现

寻找能删除"被维护的义务"的改动：插件条目、配置键、脚本函数、启动器分支、测试与文档。宁要少数证据充分的候选，不要删除行数的堆积。本技能是方法论指引，不是检查清单；保持用户给定的范围，并区分"一次盘点"与"获准实施其提案"。

## 确定范围与约束

判断之前先读根 [AGENTS.md](../../../AGENTS.md)、[运行时架构](../../../docs/architecture/kongming-runtime.md)；插件功能与归属参照[插件索引](../../../docs/kmh/plugin-index.md)。涉及子模块行为的判断，先读子模块的 AGENTS.md 并按其规定执行；Kongming 技能不重复其内容（分工见[与子模块的分工](#与子模块的分工)）。

几项既定设计是本层的保护性约束：

- **DSH 能力由子模块提供。** 不要提议在 Kongming 层复刻 DSH 内部机制；新增能力走现有插件服务、事件与 effect（现行清单见插件索引）。DSH 内部的简化属于子模块范围。
- **启动器的转发契约是有意的。** 调用者工作目录、模型凭据与真实退出状态由 `scripts/kmh.mjs` 转发，KMH_HOME（默认 `.kmh`）转换为 DSH_HOME。删除或弱化这些转发都是改变既有承诺，不是简化。
- **profile 配置归 Kongming 版本控制**，会话与机器偏好位于 KMH_HOME。把部署配置搬进运行数据（或反向）是行为变更，需要作为提案写明取舍。

受保护设计内部未被使用的成员仍是候选——只要删除它们不破坏设计目的。

范围大的请求可以把独立领域分给子代理：启动器与 `scripts/` 辅助脚本；`launch.config.json` 与 profiles/、bundles/ 配置组合；`packages/kmh-*` 插件；`docs/`；`tests/`。给每个子代理有边界的领域，并要求提供消费者证据与被否决的替代方案。实质生产设施与显而易见的未用符号都要检查，不要在第一个有希望的删除后就停下。

## 搜索可删除的维护义务

用以下问题引导发现。候选的价值无法由"未用符号搜索"直接确立时，读[历史模式](references/historical-patterns.md)的相应章节校准；那些例子说明决策方式，不是当前的待删清单。

- **声明的特性有完整生效路径吗？** 追踪生产者、变换、消费端与可观察结果。一个被到处复制的字段可能没有写入者、没有读取者，或只有拒绝它的实现。搜索构造端与判别发射端，而不仅是调用点。
- **哪些区分真正改变消费者的行为？** 多个内部状态可能只需要一个面向使用者的状态或一个可用标识。保留控制授权、持久性、归属的内部区分；删除只会招致不可用选择的公开区分。
- **更小的明确行为能否删掉整个子系统？** 固定值、调用方提供的参数或显式报错，可以替代泛化的机制。写明放弃的能力与删除的机器。有真实调用方时这是行为决策而非自动否决；实施必须停留在用户授权范围内。
- **消费者能否在需要时读取权威值？** 留意被复制的缓存、失效事件后紧跟的读取等模式；派生或复用可能一并删除订阅、留存数据、过期响应处理与恢复路径。先确立观察时机要求。
- **是否把组合误当成了策略？** 可选依赖、一个 bundle 依赖声明或兄弟插件条目本身就能表达可用性，不必再写部署判定。显式配置或调用方意图操作可以替代注册表与依赖检查；所有权或完成时机不同的操作仍要分开保留。
- **谁承担完整的维护成本？** 追踪透传配置、重复的插件树、被产品使用的示例性启动包装、仅做解析的工作区，以及自带升级生命周期的安装辅助。比较被删系统与替代品的整体（含残留胶水）；移动复杂度、或加一道门保持重复定义一致，都不算删除。

## 证明可达性与权衡

先用 `rg` 再读命中。搜索精确符号、属性读写、判别值、事件与配置键、包名，同时搜索 `.method(` 与 `method(` 两种形式。测试与声明只能证明契约存在，不能证明存在实际的生产者或消费者。

Kongming 层的检查范围包括 `scripts/`、`launch.config.json`、profiles/ 与 bundles/ 的 `cordis.patch.yml` 与 `package.json`、`packages/kmh-*`、`docs/`、`tests/`，以及 KMH_HOME 内由启动器登记的链接布局。按真实入口而非目录名分类：bundle dependencies 的 `link:` 声明、patch 的挂载行、profile 的 overlay 都是动态产品配置；文档里的罗列不是固定调用方。引用 DSH 机制时核实子模块侧的真实语义，不要凭 Kongming 文档的转述断言行为。

对每个候选记录：当前归属、实际的生产/消费路径、删掉什么、留下什么、保留它的最强理由。区分三类：

- 删除不可达或无人读的行为；
- 收窄公开或产品行为，并写明明确的损失；
- 受保护的义务，或证据不足。

候选破坏被保留的义务、只是把同样的复杂度搬家、或没有实质减少时，予以否决。否决理由按所提改动的层级来读：一份过时清单或混合提案中被否决的部分，不自动否决每个独立项。重新提出前先刷新证据。小的行内改进写成代码内 TODO/FIXME 注释、随所属改动处理，不单独立项。

## 保持所有权与失败语义

对副本、冻结、校验器与回调捕获，写明值的来源、下一个所有者与信任边界。同进程的类型化调用通常借用只读值；解析器、配置装载器、队列、插件 JSON、持久文件、子进程与线上解码器拥有或校验其输入。敌意取值或替换回调的测试本身不构成需求。冻结的根不证明其子孙不可变，相等的 id 不证明对象同一。

对异步机制，把每个 promise、标志、取消路径、disposer 与预约映射到其所有者与状态转移。只在两种机制表达同一事实时合并它们。按需保留同步发布与回滚、回调封闭、首个终局仲裁、子进程归属与 dispose 至静止。持久标记可以记录真实事实，即使某个渲染端忽略它们；丢弃被打断的工作是能力损失，不是冗余日志清理。

## 仅在净减少时替换基础设施

新增包之前先搜索现有依赖与 Node 内建模块。识别替换会删除的确切实现与专属测试、其维护与传递成本，以及胶水必须保留的每个残留行为。

优先演练最可能击败替换方案的不匹配：协议截断、取消与清理、配置边界、确定性测试时钟、平台打包，以及源码入口与构建产物入口。一个覆盖了帧封装、却要求重建同样封装来实施大小限制的库，不是简化。已被接受的边缘行为变化写进提案与相关测试。不要反复证明依赖的通用规格，却漏掉针对本仓库专属 shim 的测试。

## 记录、合并与验证

文字改动遵循 [kmh-prose-standard](../kmh-prose-standard/SKILL.md)；删除复述代码或远端归属的解释时，保留本地行为、时机、所有权与失败义务。受影响的 README、配置说明与生成文件随其所属改动一起更新；文档落点遵循 [kmh-doc](../kmh-doc/SKILL.md)。

实质提案按 `Problem`、`Proposal`、`Alternatives considered`、`Acceptance criteria`、`Risks` 的骨架记录，包含具体的消费者证据、删除的维护成本、放弃的能力与可观察的验收条件。提案落入现有文档归属；同一决策更新既有记录，不为凑候选数量新建重复记录。新增或合并决策记录前，先检索 docs/ 中是否已有同主题的现行决策（supersession 检查）；子模块的对应机制由 [dsh-archive-agent-notes（子模块原技能）](../../../third_party/dsh/.agents/skills/dsh-archive-agent-notes/SKILL.md) 承担，Kongming 层没有对应归档设施，完成检索与归属更新即可。

合并其他分支的简化时，把它独立 diff 与目标基线比较，只移植受支持且不重叠的提案，合并重叠的理由。关闭他人的 PR 需要授权或对该清理的明确归属。

按改动面选择验证：脚本改动运行 `pnpm lint`；配置组合改动运行 `pnpm test`，必要时 `pnpm config:web` 核对最终配置；插件包改动运行 `pnpm build` 加 `pnpm test`；文档改动核对链接有效、命令说明与实际执行结果一致。推送前的检查选择参照 [kmh-pre-push-checks](../kmh-pre-push-checks/SKILL.md)。报告盘点范围、有依据的候选、有意义的否决或搁置、新增/合并/保留/移除的记录，以及实际运行的命令。调查范围还在扩大时保持每步可复查；不要把未验证的搜索描述为穷尽。

## 与子模块的分工

- `third_party/dsh` 内部的简化遵循子模块 AGENTS.md 与其自身流程，参照 [dsh-find-simplifications（子模块原技能）](../../../third_party/dsh/.agents/skills/dsh-find-simplifications/SKILL.md)。该技能包含子模块的 Agent Notes 骨架、归档机制与内部保护设计细节；本技能不重复其内容。
- 两层的公共结论通过链接互引，不复制条文；本技能不规定 DSH 内部的路径、命令或机制。
