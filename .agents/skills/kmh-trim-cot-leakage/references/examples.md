# 泄漏示例（few-shot）

整理自 DSH 子模块 2026-08 的全仓清理及其评审轮次（DSH 子模块示例）；除单独标注的小节外，例子均为通用编辑规则。用它们识别主导原则，而不是当作文字模板。本文件刻意引用泄漏措辞作为校准材料——[召回模式库](recall-batteries.md)排除本技能目录，这里的措辞不是在别处使用的许可。

## 死引用

### 有已提交归属物的决策序数

**泄漏：** "Slash 输入按可见目录解析 (decision 21)。"

**修复：** "Slash 输入按可见目录解析——即纯文本引用决策，归属见 [web 输入机笔记](../../../../third_party/dsh/.agents/notes/archived/architecture/2026-07-25-web-input-machine-and-slash-pipeline.md)（DSH 子模块笔记）。"

序数在 HEAD 无处解析；决策的名称与归属笔记路径可以。每个文件至少点名一次归属笔记的路径——表面支持链接就用链接——后续提及可只用可检索的名称。

### 无归属物的决策序数

**泄漏：** "注册表拒绝重复名称 (decision 7: 名称扁平，无命名空间)。"

**修复：** "注册表拒绝重复名称；名称扁平，无命名空间。"

没有已提交产物拥有 "decision 7"，所以删除引用——但它的事实分句（名称扁平）被改写为自立，而不是随它一起删除。

### 审计项编号

**泄漏：** "渲染是纯的：同样快照，同样字符串 (audit R3)。"

**修复：** "渲染是纯的：同样快照，同样字符串。"

仓库里没有审计文档；编号是会话速记，承载零命题。

### 未提交草稿的小节号

**泄漏：** "分层遵循设计 (v2 §3.2)：`src/core/` 是纯核心。"

**修复：** "分层：`src/core/` 是纯核心。"

没人提交过的草稿的 §N 不可解析。对比："按 RFC 9110 §10.1.5 转义"保留——外部标准设计上在仓库外解析，拥有自己 § 编号的已提交文档可以按小节引用。

### 计划阶段标签

**泄漏：** "`src/client/` 是壳 (T4)；P-I 迁移拥有适配器。"

**修复：** "`src/client/` 是壳；适配器在 `src/client/adapters/`。"

阶段标签索引的是从未落地的计划。用该阶段产出的东西替换标签。

## 栈与 PR 视角

### 持久文字中的栈位置

**泄漏：** "未来的远端后端实现此接口（沙箱后端是本栈后面某个 PR）。"

**修复：** "远端后端可以在不改动渲染层的情况下实现此接口。"

持久文字看不见栈。保留扩展点契约；待办工作的归宿是 PR 本身、`TODO` 或 issue。

### README 里的 "This PR"

**泄漏：** "本 PR 为会话列表添加游标分页。"

**修复：** "会话列表按游标分页。"

README 比每个 PR 都活得久；把机制陈述为当前事实。

## 变更叙述与版本戳

### 带 PR 号的战争故事

**泄漏：** "颜色以前来自没人定义的 `--widget-*` token，所以总是渲染 fallback；别名 token 修好了它 (PR #88)。"

**修复：** "颜色来自别名 token；未定义的 token 渲染 fallback。"

两个存活的事实都在——当前机制与常驻失败行为——用现在时改写。bug 的传记属于 PR 和它的笔记。

### 删除叙述

**泄漏：** "`probe` 字段随删除裁剪移除了；徽章现在骑通用的投影对。"

**修复：** "徽章使用通用的投影对。"

从没见过 `probe` 的读者从它的缺席里学不到任何东西。与被删除的过去对比的"现在"是版本戳。

### 修复的回归 → 反事实现在

**泄漏：** "这里以前会双重编码多字节标签。"

**修复：** "没有字节长度守卫，多字节标签会双重编码。"

回归钉以现在时反事实存活并点名守卫；"以前"把它钉在仓库考古上。

### 索引性版本戳

**泄漏：** "本次裁剪里批渲染是同步的；异步路径是路线图工作。"

**修复：** "批渲染是同步的。"（推迟住在调用点的 `TODO(widget-batch):`。）

"这次裁剪"/"v1"/"今天"在合并那一刻就开始变味。笔记变更叙述小节里的历史阶段名（"第一版交付了 X"）对现状安全；索引形式永远不安全。

## 评审编排

### 作为正文的评审裁决

**泄漏：** "评审中否决：缓存解析后的 spec。我们保持每次调用解析。"

**修复（笔记的"考虑过的备选"小节内）：** "**缓存解析后的 spec。** 已否决：spec 依赖每次调用的 cwd，按请求键控的缓存会服务过期的根。"

考虑过备选的体裁是合规归宿；评审者和轮次不是理由的一部分。

### 草稿序数

**泄漏：** "截至本笔记第 5 版，加载器还校验 manifest。"

**修复：** "加载器校验 manifest。"

已落地的笔记用现在时陈述已交付的现实；它自己的修订史在 git 里。

## 面向评审者的辩解

### 为 cast 辩护

**泄漏：** "这个 cast 是安全的——对象是 SDK 构造的，它只是没把 optional 声明得足够严格。"

**修复：** "SDK 构造此对象时填充了每个 optional；声明的类型比运行时保证更松。"

陈述维护者不得破坏的不变量。"它只是……"是在回答 HEAD 处没人提出的异议。若不变量在代码里可见，删掉注释。

### 诉诸评审权威

**泄漏：** "这是对的，因为评审者确认了包装顺序。"

**修复：** （删除；包装顺序已在该函数的 `@returns` 里陈述。）

正确性主张引用不变量或测试，从不引用人。

## 复述与推导

### 控制流叙述

**泄漏：** "我们先规范化标签，然后截断，然后包装。"

**修复：** （删除。）

注释下方三行代码说的是同一件事。

### 测试走查

**泄漏：** "本测试创建会话，发两条消息，等第二个回复，然后断言日志有四条。"

**修复：** "两次往返必须恰好产生四条日志——投影对共享前缀去重。"

只保留非显然的断言理由；走查复述了测试体。

## 含糊话与计划残留

### 无标记的推迟

**泄漏：** "目前大概可以直接急切渲染。"

**修复：** （删除；推迟已有 `TODO(widget-batch):` 标记。）

没有归属的含糊话是计划残留。若标记不存在，写一个（`TODO(name): coalesce per animation frame`），而不是保留含糊话。

### 模糊的容量

**泄漏：** "64 KiB 缓冲对大多数情况应该够了。"

**修复：** "64 KiB 容纳已观察到的最大帧 (48 KiB) 并有余量；更大的帧在 `decode` 里响亮地失败。"

用实际界限和超限时的失败行为替换含糊话。

## 写作语言混杂

**泄漏：** "渲染器跑在 client 端；间距见设计稿。---- 私有 ----"

**修复：** "渲染器跑在 client 侧；间距遵循 Figma frame `widget-badges`。"

工作语碎片与会话分隔符是转录残留。Figma frame 名称保留：设计上在仓库外解析的外部来源。

### 成对围栏内的写作语言混杂（DSH 子模块示例）

**两个文件里都泄漏：** verbatim 代码块内的 `// 更新这里 before returning`。

**两个文件里都修复：** `// Update this before returning.`

改一次块，把逐字节相同的围栏拷贝进两个语言文件。在中文对应物里把代码注释翻译得不同，会破坏配对契约，即使两个注释各自都通顺。

## 行为可见的候选（DSH 子模块示例）

**可疑：** 导出的 JSDoc 句子说 "available for now"，而生成器把该句子抄进模型可见目录。

**错误：** 在纯文字清理中只改写源句子，或只手改生成的目录。

**正确：** 追溯源的生成扇出，更新拥有者，重新生成每个派生物，并更新拥有它的可运行快照。GUI 字符串要包含仓库要求的行为证据。若授权范围内没有拥有它的场景，保持措辞不变并报告推迟。

## 保留项

### Issue 引用在每个表面都持久

**保留：** "上限作用于完整渲染值，含包装器（issue #1470 拥有后续工作）。"

一轮无辅助清理删掉了它，理由是 issue 引用属于笔记。方向错了：issue 在 HEAD 从任何表面都可解析，"#N 拥有后续工作"是 README 中推迟工作的合规归宿。笔记和复盘额外允许的是把*已合并 PR* 当证据引用。

### 死的名字点名不是"点名归属者"

**删除：** "widget seam 上的徽章渲染器（见 widget-rendering RFC）。"

一轮无辅助清理把它当作"按主题点名归属文档"保留。检验是可解析性，不是形式：没有已提交文件应答"widget-rendering RFC"，所以指针是死的。若存在已提交归属物就重定向到它；否则删除。

### 抑制理由

**保留（修正后）：** `// oxlint-disable-next-line no-non-null-assertion -- the one-element literal guarantees index 0.`（DSH 使用 oxlint；规则本身与工具无关。）

理由分句是必需文字。当陈述的理由是假的（原文说"上面的循环守卫证明帧存在"而那里根本没有循环）时，修正理由；绝不删除。

### 实测界限

**保留：** "深度上限（实测: 512 层 ≈ 0.15s 同步；4096 阻塞循环）。"

测量把常量钉住，防止无依据的重新调参；"实测"表明这是数据而不是猜测。

### 运行时旧/新不是变更历史

**保留：** "旧连接先排空，新连接才开始接受。"

这里的"旧"和"新"命名交接期间的两个存活运行时对象，不是仓库状态。变更叙述禁令针对仓库历史，不是生命周期词汇。

### 运行时自然时间不是版本戳

**保留：** "今天是几号？"

提示词问的是运行时时钟；"今天"不对比仓库状态。因为该文字到达模型，任何改写仍需要其拥有者行为证据。

## 矫枉过正的陷阱

下面的每个陷阱都在原清理中出现过，并在评审中被抓住。精简段落前先枚举它的命题。

### 把义务翻转成认可

**原文：** "这些直接注册是等待迁移到槽位的例外。"

**矫枉过正：** "这些直接注册是被认可的例外。"

**正确：** "这些直接注册是等待迁移到槽位的例外。"

"等待迁移"是义务；"被认可"祝福了现状。精简在缩短句子的同时翻转了它的情态。

### 把假想提升为已交付功能

**原文：** "未来的基于 IPC 的壳会子类化执行器并覆写 `spawn`。"

**矫枉过正：** "基于 IPC 的壳子类化执行器并覆写 `spawn`。"

**正确：** "假想的基于 IPC 的壳——目前不存在这样的壳——会子类化执行器并覆写 `spawn`。"

只删将来标记会把设计插图变成"该类已交付"的主张。明确标注假想，而不是仅仅去掉将来时。

### 连同记录删掉真事实

**原文：** "gate 通知叙述了检查顺序；该通知文字也是 `verify-doc-typecheck` 编译所针对的。"

**矫枉过正：** "……"（整句按叙述删除。）

**正确：** "该通知文字是 `verify-doc-typecheck` 编译所针对的。"

句子一半是叙述，另一半是承重耦合。命题共享一行时删分句，不删整句。

### 保留数字却丢掉测量来源

**原文：** "4 MiB 上限是实测的：最大的生成 `py-types` 模块是 3.1 MiB。"（`py-types` 为 DSH 子模块的生成模块。）

**矫枉过正：** "上限是 4 MiB；最大的生成 `py-types` 模块是 3.1 MiB。"

**正确：** 保留"实测"。

没有"实测"，3.1 MiB 读起来像定义而不是观察，没人会在提高上限前重新测量。
