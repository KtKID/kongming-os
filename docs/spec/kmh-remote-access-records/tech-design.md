# Remote 访问记录技术设计

在现有密码处理处取得结果，保存到当前 Home 的文件，再由插件详情按页读取。访问记录的业务处理、共享约定、界面和文案使用严格检查的 TypeScript；现有 JavaScript 入口保留原鉴权与代理流程，并调用这些模块。

依据：[spec v4](spec.md)，2026-10-22；用户本轮明确要求“按这版 spec 重写”，承接保存 8 个场景、查看 5 个场景。spec SHA-256：`eb386468ccffabb91f800d9f674965f7969ba8b78722431f45d3a67e4a2ca94c`。状态：**2026-10-23 用户确认并授权 req、dev、verify**；实施依据为本版保存与查看设计。

## 保存访问记录（feat01）

对应 [spec 的保存功能](spec.md#feat01-保存访问记录)。保存的流程为：一次显式密码提交 → 原有密码处理结果 → 构造记录 → 顺序写入文件。记录格式与文件规则依照 spec，技术层补充排序和错误传播所需的约定。

<a id="save-plan"></a>

### 取得一次密码提交的结果

`proxy.mjs` 在进入实际密码提交路径时调用 `createPasswordAttemptRecorder` 返回的记录入口。TS 模块捕获本次来源，提供 `success`、`rejected`、`limited`、`bodyTooLarge` 及提交中断、错误监听。同一上下文首次完成后结束；同 IP、同毫秒或同时到来的其他提交各有自己的上下文。已有表单、显式 URL 密码及握手密码路径共用此规则，自动登录和后续业务活动沿用原流程。

原判断位置传入请求与既有公网分类结果，TS 模块生成 `entryKind`、连接来源与结果。提交前后已有的限速拒绝、密码拒绝、成功、请求中断、大小限制及请求错误均在对应终态交付记录；密码值、Cookie、完整请求和 URL 留在原鉴权流程内。

失败原因沿用原处理处的文字或原生 `Error.message`。已有 `code` 保持原值；主动识别的密码错误、受限、中断和提交体过大分别采用 `REMOTE_LOGIN_REJECTED`、`REMOTE_LOGIN_LIMITED`、`REMOTE_LOGIN_ABORTED`、`REMOTE_LOGIN_BODY_TOO_LARGE`。这些原因在处理处定义一次，登录提示与记录引用同一来源。

### 共享记录约定

下表为正式 schema 的设计，落地后的权威位置是 `shared/access-records.ts`，类型由 schema 推导。输入、写入前、文件读取后及查询返回处使用同一约定校验。

| 字段 | 技术表示与来源 |
| --- | --- |
| `version`、`sequence` | 格式版本固定为 `1`；`sequence` 为递增整数字符串，内部按大整数比较，用于跨文件排序和分页，避免时钟变化改变历史顺序 |
| `occurredAt`、`timeZone` | 密码处理结果发生时的设备本地时间，格式为 `YYYY-MM-DDTHH:mm:ss.SSS±HH:mm`，另存当时 IANA 时区；界面显示格式沿用 spec |
| `peerAddress`、`sourceNote` | 规范化的实际连接 IP；无法确认时 IP 为 `null`，说明保留在 `sourceNote` |
| `claimedAddresses` | 可解析的转发声明地址数组，各项带 `address` 和固定为 `unverified` 的可信度标记 |
| `entryKind`、`event` | 原 Remote 判定的 `lan` 或 `public`；事件固定为 `password-attempt` |
| `outcome`、`error` | `outcome` 为 `success` 或 `failure`；失败必须具有 `{ code, desc }`，成功使用成功结构 |

记录只按白名单字段构造。JSON 编码处理换行与特殊字符，读取后的 desc 与原值逐字相同。来源说明、访问类型和界面标签分别从上述值派生。

### 文件写入与生命周期

`home` 取自当前实例的 `DSH_HOME`，其来源沿用启动器对 `KMH_HOME` 的转换；插件实例固定使用这一份 Home。本设计按一个 Host 进程管理一份 Home，文件模块持有唯一写入者，并在首次保存或查询时初始化文件状态。`save(attempt)` 返回真实写入结果，正常结果含已保存序号，失败结果含原始错误。代理按原有规则完成登录响应，异步保存的失败由文件模块接住并报告。

1. 构造并校验记录，序列化为一行 UTF-8 JSON，包含末尾换行；先检查本条实际字节数。单条超限返回 spec 指定的 `REMOTE_RECORD_TOO_LARGE`，访问文件保持原样。
2. 全部正常大小记录按结果交付先后进入同一条异步写入链，按该顺序分配递增序号，依次完成容量检查、必要的文件创建和完整写入。同一时刻由一个写入者管理当前文件。
3. 目录与文件命名、10MB 写入前判断、跨日继续使用及同日递增规则均按 spec；新文件以独占创建方式打开，名称冲突时选择下一个序号。文件权限为目录 `0700`、文件 `0600`。
4. 完整写入成功后更新可读位置。启动时从每个文件的末条完整记录重建序号及文件顺序，当前文件已满时选新文件；文件目录信息保留路径、长度与序号范围，记录正文留在文件中。
5. 卸载时先停止新访问并收齐在途密码尝试的结果，再等待写入链结束、同步并关闭文件。Home 切换由旧实例关闭、新实例加载完成；设置重置继续只操作其原有设置位置。

文件操作采用 Node 异步接口，短写继续补齐。写入中途失败时保留已有字节、关闭该写入文件，并报告原错误；恢复后的正常保存使用可继续写入的文件或新文件。读取到损坏行时明确返回解析错误。正常关闭等待已接纳的写入；断电或强制结束时，尚未完成的写入受设备与操作系统状态影响。

保存错误统一为 `{ code, desc, operation }`。原生错误保留原 code/message，缺少 code 时在发生处给出对应操作的稳定错误码；原始 desc 持续原样传递。文件模块保留当前实例最近一次保存错误及恢复状态，正常保存后仍可显示此前失败；同一错误同时交给已有宿主 logger。初始化失败保留原错误，后续保存可在条件恢复后重新初始化，Remote 继续按原规则运行。

## 查看访问记录（feat02）

对应 [spec 的查看功能](spec.md#feat02-查看访问记录)。前端只向一个记录查询方法取当前页与保存错误状态，分页位置由保存模块计算，设置内容继续由原组件持有。

<a id="view-plan"></a>

### 本机查询与分页

新增方法为 `/kmh-remote/records.list`。共享 schema 定义输入 `{ cursor?: string }` 与成功值 `{ records, nextCursor, homeLabel, saveError, recovered }`，其中 `records` 最多十条，`nextCursor` 在末页为 `null`，`saveError` 为最近保存错误或 `null`；`recovered` 表示该次错误之后已有正常写入。失败沿用现有 [RPC 信封](../../../third_party/dsh/packages/client/connection/src/rpc-schema.ts)，`error.code` 保留 code，`error.message` 和 `error.details.desc` 保留原始 desc；本机授权后的读取失败也可在 details 中附当前保存错误。

权限在读取文件前完成两层检查：Remote 代理识别并拒绝记录方法；Host 校验原始 TCP 来源为 loopback，并以 `ctx.connection.requestRejection(req)` 完成原有浏览器认证。HTTP 适配层通过服务端上下文传递来源，记录处理处仅信任此上下文；旧 RPC 路径缺少原请求上下文时返回 `REMOTE_RECORD_LOCAL_CONTEXT_REQUIRED`。原设置方法继续沿用原规则。

代理和 Host 共用方法名与路径解析约定，覆盖编码路径、路径与信封 method 一致性，以及 WebSocket 兼容入口；本机限制依据原连接来源。拒绝结果携带 code/desc，经原请求通道返回。游标和文件位置由共享 schema 校验；文件访问只限记录目录内约定名称的普通文件。部署验收同时核对公网转发目标为 Remote 代理、Host 本机入口保持既有隔离，这两项前提纳入 VIEW-05 的实际环境检查。

首次查询先等待已交付的写入完成，再记下当时最后成功保存的位置。游标是编码后的读取位置，包含当前实例标识、本次截止序号、文件名和字节偏移；校验实例、文件白名单及位置边界后使用。后续写入位于本次截止位置之后，继续翻页时按保存顺序倒读文件块，每次返回十条；客户端保存已用游标以回到上一页。刷新重新取截止位置并回到第一页，插件重载使旧游标失效并提示刷新。

目录信息按序号排列文件，按需读取正文；持久化权威为 `.log` 文件。初始化重建目录信息，写入成功后更新；查询保持只读，取消时关闭本次句柄。真实空目录返回空页，读取和解析错误返回原始错误。

### 详情界面

详情使用公开 [SegmentedTabs](../../../third_party/dsh/packages/client/ui-primitives/src/SegmentedTabs.tsx) 和现有 Button、加载及主题样式。设置面板保持挂载，通过隐藏切换保留草稿；通用设置页仍渲染原 `RemoteSettings`。访问列表内部滚动，翻页和刷新位于滚动区域外。

进入记录 Tab 或刷新时加载当前页及保存错误。读取失败保留旧列表，在列表旁显示 code/desc、此前结果标记和重试入口；首次加载失败显示错误状态，成功空页显示空态。desc 按文本保留换行，长内容在详情内滚动。切换、卸载或新请求时取消旧请求，并按本次请求序号核对响应，防止旧结果覆盖新页。
