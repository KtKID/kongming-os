# Remote 外部访问记录

让 Kongming 使用者回看其他设备访问 Remote 的情况，了解访问时间、设备与浏览器、访问入口以及验证结果。需求来源为 2026-10-22 对话中用户提出“记录外部访问设备、时间这些信息”，随后要求“走 x-spec”。本稿为待确认草案，涉及范围选择的提议集中列于文末。

## 关键约束（用户已确认）

当前尚未收到用户单独确认的关键约束条目。下列场景依据已提出的访问记录需求与现有访问方式编写；文末提议随需求评审逐项确认。

## feat01: 回看外部设备的访问记录

用户可以查看访问时间、设备及浏览器说明、来源地址、访问入口和验证结果，了解曾经发生的访问。入口位置、收录哪些访问及保存期限见文末待确认清单。

场景1: 回看一次通过验证的访问

必要性：用户要求记录外部设备及访问时间；缺少时用户无法回看设备何时访问。

- GIVEN 某个外部设备已通过 Remote 的访问验证
- WHEN 用户查看访问记录
- THEN 展示该次访问发生的年月日、时分秒及所属时区、设备与浏览器说明、来源地址、访问入口和“通过验证”的结果
- THEN 访问入口展示实际使用的地址，以及该次验证采用的局域网或公网密码类别
- THEN 显示的验证结果对应访问验证本身，后续进入页面的情况按实际可确认的信息展示

场景2: 回看密码输入错误或访问受限的尝试

必要性：现有 Remote 会拒绝错误密码并限制连续尝试；缺少对应结果会使用户把失败尝试误认为已通过验证。

- GIVEN 某个外部设备输入错误密码，或因连续尝试、访问开关关闭而受到限制
- WHEN 用户查看相应访问记录
- THEN 显示该次尝试的时间、可识别的设备及来源信息，并按实际情况标明“密码错误”“尝试过多”或“访问已关闭”
- THEN 每条记录的结果与该次尝试一致

场景3: 访问者已经登录（收录规则待确认 A）

必要性：现有 Remote 支持登录后继续访问；仅记录输密码的操作会遗漏已经登录设备的后续访问时间。

- GIVEN 某个外部设备已登录，并再次打开 Kongming 页面
- WHEN 用户回看该次访问
- THEN 展示本次打开页面的时间，并说明该设备沿用已有登录状态
- THEN 页面内持续收发消息归属于本次访问

场景4: 设备信息有限或多台设备共用地址

必要性：设备提供的信息可能有限，多台设备也可能共用同一个来源地址；缺少说明会把猜测显示成确定的设备身份。

- GIVEN 某次访问只提供浏览器或系统名称，或多台设备显示相同来源地址
- WHEN 用户查看这些访问记录
- THEN 展示实际可识别的信息，其余项标为“未知”
- THEN 页面说明设备描述用于辅助辨认，同名描述或相同来源地址可以对应多台设备

场景5: 经路由器转发后识别来源

必要性：用户当前通过域名和路由器转发访问 Remote；来源信息可能只显示转发设备，缺少说明会让用户误认访问者。

- GIVEN 外部访问经过路由器或其他转发设备
- WHEN 用户查看来源地址
- THEN 有可靠的访问者来源信息时，展示该信息并说明识别依据
- THEN 只能识别转发设备时，展示可确认的来源，并标明“看到的是转发设备地址，访问者地址未知”
- THEN 来源识别可信度由已确认的转发关系决定

场景6: 按时间回看历史

必要性：用户希望回看访问时间；记录时间混淆或重启后丢失会使历史回看结果失真。

- GIVEN 已有多次访问记录，期间用户曾关闭并重新启动 Kongming
- WHEN 用户重新查看仍在保存期限内的访问记录
- THEN 按访问发生时间从新到旧展示，日期、时区和访问结果保持可辨认
- THEN 保存期限按待确认项 C 定稿

场景7: 暂无访问记录

必要性：首次启用记录时可能还没有记录，已有功能也没有可供补录的访问历史；缺少说明会让用户误以为过去从未发生访问。

- GIVEN 访问记录功能刚开始使用，或当前保存范围内没有记录
- WHEN 用户查看访问记录
- THEN 显示“暂无访问记录”，并说明记录从该功能启用后开始收集及适用的保存范围

场景8: 读取记录失败

必要性：记录读取可能失败；显示空列表会使用户误以为当前没有访问历史。

- GIVEN 访问记录暂时读取失败
- WHEN 用户打开或刷新访问记录
- THEN 明确提示“访问记录读取失败”，已显示的内容继续保留并注明刷新失败
- THEN 用户重新打开或刷新后，可以再次查看读取结果

场景9: 记录保存失败

必要性：记录保存可能因本机空间或访问权限受限而失败；缺少提示会使用户把存在缺口的历史当作完整记录。

- GIVEN 某段时间的访问记录保存失败
- WHEN 用户查看记录功能的状态或访问记录
- THEN 明确提示保存异常及历史可能存在缺口
- THEN 记录失败时对正常访问的处理按待确认项 D 定稿

## 待确认清单（确认后移除已解决项）

- **A：记录范围与次数，关联 feat01 场景1—3。** 建议同时覆盖局域网和公网的验证成功、验证失败、受限尝试，以及已登录设备重新打开页面；每次打开页面记一次，页面内持续收发消息沿用该次访问。需确认是否接受这一范围；该选择决定列表里的时间含义和记录数量。
- **B：查看入口与查看权限，关联 feat01 全部场景。** 建议沿用现有“手机访问”设置页和 Remote 插件详情页，增加“访问记录”区域；记录仅供电脑本机使用者查看。需确认入口及查看范围，该选择影响访问者能否查看其他人的访问历史。
- **C：保存期限与清空，关联 feat01 场景6、7。** 建议保存最近 30 天，超过期限的记录自动清理；提供手动清空，清空前确认且提示记录无法恢复。期限和清空能力目前均待确认，确认后补充相应功能场景。
- **D：记录失败与敏感内容，关联 feat01 场景1、2、9。** 建议访问验证继续依照现有规则进行，记录异常在本机明确提示；记录只保存访问信息，密码和维持登录所用的秘密内容保留在既有验证环节。需确认该边界，该选择决定记录故障时的访问行为及记录可包含的内容。
