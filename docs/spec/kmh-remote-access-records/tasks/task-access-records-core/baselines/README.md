# 基线来源

`spec.md`、`tech-design.md` 保存用户回复“同意，走 req dev verify”时承接的行为和用例主定义。当前设计末尾的执行状态通过链接指向交付记录，行为和测试主定义沿用本快照。

`source/` 是开发前已有改动的五份接线文件，包含先前探针及设置修复。各文件 SHA-256 与技术设计阶段记录的文件清单逐项相同，散列保存在 `source-hashes.json`；coverage 检查器先校验快照，再计算新增或替换行。四份 Host 文件由同版本构建产物恢复，客户端文件由当前文件回退本任务两处插槽接线后恢复，均已核对散列。快照只供覆盖率审计，产品源码以包内文件为准。

`git-base.json` 固定本任务开始时的 Git 提交。新增接线范围取“相对开发前快照的新增/替换行”与“相对固定 Git 提交的新增/替换行”的交集，保持已有工作区改动及提交时恢复的原提交行各自归属；新增三个模块全量计入。
