# Remote 临时访问探针

归属：`packages/kmh-remote`；功能：[spec feat02](../spec.md#feat02-临时验证访问事件实施中)。创建：2026-10-22。状态：实施中。

## ① 需求与变更

用户同意临时访问探针方案，要求 TypeScript、qdev、保持系统稳定及注意性能；本轮再次要求“走 qdev”。承接 feat02 场景1—5、C1/C2。feat01 的正式页面与保留策略继续待确认。

修改前功能正文保存在 [可读基线](baseline-spec-before-probe.md)。新增 feat02 及 C1/C2，变更索引位于 [spec 变更记录](../spec.md#变更记录)。保留此前密码开关修复和其他已有工作区改动。

## ② 精简技术设计

- D1：新增 `host/access-probe.ts`，Zod 定义唯一事件结构，白名单提取时间、事件、Host、socket 地址、浏览器说明及来源声明。Node 原生 HTTP 完成事件记录响应结果，只有上游确实升级连接后记录实时连接开启，socket 关闭记录结束。原 JS 模块只增加可选观察回调，并隔离观察异常。覆盖场景1、2及 C1。
- D2：原生文件流独占新建 `0600` 临时文件，文件上限 5 MiB，待写入上限 64 KiB；每字段最多 512 字符，只保留来源声明中的合法地址。每条写入前检查流的待写量和文件预算；失败停用采集并只提示一次。关闭时等待流结束。覆盖场景3—5及 C1/C2。
- D3：默认关闭。插件加载时检查本机 `$DSH_HOME/kmh-remote/access-probe.enabled` 标记；标记存在才启用。输出位于现有临时目录，按次独占命名，启停只影响 Remote。构建只为新增 TS 模块添加 ESM 输出，扩展现有严格检查覆盖。覆盖场景1、5。
- 规范：R1 依赖单向，记录器只依赖 Node 与现有 Zod；R2 事件 schema 唯一；R3 单语言无需跨语言同步；R4 临时文件为事件唯一保存处；R5 统一 access-probe 命名；R6 具名容量常量；R7 原生流背压、错误隔离及生命周期回收。遵循 dev-ts、KMH 文档规范和 CI 测试可靠性规则。

## ③ 测试用例与变化

新增用例计划：

| 用例 | 场景 / 设计 | 前提、触发与预期 |
| --- | --- | --- |
| T1 | 场景1、2 / D1 | 实际临时记录只包含白名单字段，来源声明标未核实，密码与附加参数被排除，文件权限正确 |
| T2 | 场景4 / D2 | 连续事件到达，待写量与文件总量受限，丢弃计数准确 |
| T3 | 场景3 / D2 | 输出路径不可用，触发实际文件打开失败，记录停用且错误被接收 |
| T4 | 场景1、3 / D1 | 真代理与假上游完成正确、错误密码及转发，观察失败仍保持原验证结果 |
| T5 | 场景1、5 / D1 | 真 WebSocket 升级与关闭各产生对应事件，静态资源访问排除 |
| T6 | C2 / D2 | 对照关闭与开启探针的相同访问负载，记录耗时、内存、输出量及丢弃量 |

既有 Remote 全套回归沿用；新增用例数及真实执行数量在⑤核对。测试使用 `mkdtemp`、`listen(0)` 及明确关闭等待；真存储和代理保持真实路径，假上游仅代替 Kongming 业务响应。
