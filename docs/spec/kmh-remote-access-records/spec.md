# Remote 访问记录

保存局域网和公网访问时的每次密码校验结果，供电脑本机使用者在 Remote 插件详情回看。使用者每次输入并提交密码，后端处理该次密码校验后，保存一条成功或失败记录。登录、密码判断、限速和转发继续沿用原有规则。

本页为核心功能规格 v4（2026-10-22），实施与验证以本版为准。每个场景的 GIVEN/WHEN/THEN 就是一个测试用例的预期正文；全部输入与结果逐项核验，参数表逐行执行，测试以“feat 编号＋场景编号”回指。本次新增功能及接线的行、语句、函数、分支覆盖率均要求 100%；实际实现和验证结果由后续任务记录。

## feat01: 保存访问记录

每次密码提交处理完成后，按后端给出的结果保存一条记录，并持续保留全部成功和失败历史。

### 记录格式

保存内容与查看内容遵循同一份格式：

| 内容 | 格式与含义 |
| --- | --- |
| 时间 | 运行 KMH 的设备在本次校验结果发生时的本地日期、时间和时区；日期为 `YYYY-MM-DD`，时间为 `HH:mm:ss.SSS`，24 小时制，毫秒固定三位；历史保留发生时的时区 |
| IP | Remote 实际能确认的连接来源；转发方声明的地址单独标为“待核实”，实际访问者来源无法确认时明确说明 |
| 访问类型 | “局域网”或“公网”，沿用 Remote 对本次访问的判定 |
| 事件与结果 | 事件为“密码登录”，结果为“成功”或“失败” |
| code、desc | 每条失败记录具有明确错误码 `code` 和完整原始原因 `desc`；已有错误码保持原值，主动识别的失败使用稳定错误码；附加解释单独呈现 |

时间显示示例：`2026-10-22 23:08:09.007 +08:00`。访问记录禁止包含密码、Cookie 或其他登录凭据。

### 文件保存规则

记录归属当前 [KMH Home](../../kmh/runtime-records.md)，按以下规则保存：

- 目录为当前 KMH Home 下的 `logs/.kmh-remote/`；首次保存时创建所需目录。
- 内容沿用 UTF-8、每行一条完整 JSON 记录；读取后各项内容保持原值。
- 单文件上限为 10MB，暂沿用草案默认值 10,000,000 字节。写入前按“现有文件字节数＋本条完整待写内容字节数”判断，包含换行等分隔内容；合计超过上限时先创建新文件，再保存本条。
- 文件名取创建当天日期，暂沿用 `YYYY-MM-DD.log`；同日后续文件依次使用 `YYYY-MM-DD_1.log`、`YYYY-MM-DD_2.log`。日期变化后，有剩余容量的现有文件继续使用；同名已有文件保持原内容。
- 全部已保存历史持续保留；关闭、重载、重启、切换文件及重置访问设置后，已有记录继续存在。记录管理操作为查看、翻页和刷新。

### 场景1: 每次密码提交按结果保存一条记录

- GIVEN 使用者通过局域网或公网触发密码输入并提交密码
- WHEN 后端处理该次密码校验并给出下表中的结果
- THEN 每次提交各保存一条记录，时间、IP、访问类型和结果符合记录格式
- THEN 失败记录的 code、desc 与后端给出的原始失败一致

两类访问入口分别执行下列参数：

| 后端处理结果 | 保存结果 |
| --- | --- |
| 密码校验通过 | 一条成功记录 |
| 密码错误 | 一条失败记录，保留对应 code、desc |
| 密码提交受限 | 一条失败记录，保留对应 code、desc |
| 密码提交或校验过程发生错误 | 一条失败记录，保留对应 code、desc |

### 场景2: 重复及同时提交分别保存

- GIVEN 多次密码提交来自相同 IP、发生在同一毫秒，或同时到达后端
- WHEN 后端分别处理这些提交，结果包含成功和失败
- THEN 记录数量等于实际提交次数，每次提交对应一条独立记录
- THEN 每条记录各自保留当次时间、来源和结果

### 场景3: 密码提交之外的活动保持记录数量

- GIVEN 已有 N 条记录
- WHEN 使用者执行下表中的活动
- THEN 活动结束后记录数量仍为 N
- THEN 随后重新提交一次密码并由后端处理后，新增一条对应结果的记录

| 活动 |
| --- |
| 打开密码输入页，停留或仅输入文字 |
| 使用有效登录状态刷新或重新打开页面 |
| 按既有设置免密进入 |
| 加载页面资源、收发消息、建立或关闭连接 |

### 场景4: 记录格式在特殊输入下保持完整

- GIVEN 本次密码校验具有已知时间、来源、访问类型和结果
- WHEN 保存并重新读取该条记录
- THEN 保存内容与读取内容符合记录格式，并满足下表预期

| 输入条件 | 预期 |
| --- | --- |
| 上午、下午、午夜，毫秒分别为 000、001、999 | 日期时间准确，小时为 00—23，毫秒固定三位 |
| 保存后设备改变时区或时钟回拨 | 旧记录保持原时间和时区，新记录采用发生时的设备时间和时区 |
| 转发连接同时带有实际连接来源和转发方声明地址 | 来源分别展示，声明地址标为待核实，访问类型沿用 Remote 原判定 |
| 实际访问者来源无法确认 | 保留可确认来源，并明确说明未知部分 |
| 失败 desc 含中文、换行、引号、反斜杠等特殊字符 | code 与读取后的 desc 逐字保持原值，附加解释独立呈现 |
| 提交包含密码及已有登录凭据 | 记录内容限于约定的访问摘要 |

### 场景5: 历史归属当前 Home 并持续保留

- GIVEN 当前 KMH Home 及其中已有的访问历史已知
- WHEN 分别执行下表中的操作，再产生一次密码提交并由后端处理
- THEN 既有记录在各自 Home 中保持原内容，当前 Home 可回看自己的全部历史
- THEN 新记录保存到当前 Home 的 `logs/.kmh-remote/`，目录首次使用时自动创建

| 操作 |
| --- |
| 首次使用全新 Home |
| 关闭并重新启用、重载 Remote，或重启 KMH |
| 在各有自己历史的 Home A、Home B 之间切换后启动 |
| 查看、翻页、刷新或重置原有访问设置 |
| 历史超过 30 天，或文件数、累计容量继续增长 |

### 场景6: 按实际字节数在写入前分文件

- GIVEN 当前文件、同日已有文件及本条完整待写内容的实际字节数已知，本条大小在 10MB 以内
- WHEN 保存记录
- THEN 按下表处理，每条记录完整保存一次，已有文件保持原内容，新建文件名称唯一
- THEN 中文及特殊字符按实际保存字节数计算，各访问文件按 10MB 上限控制大小

| 条件 | 预期 |
| --- | --- |
| 现有文件加本条内容为上限减一字节 | 继续保存到现有文件 |
| 现有文件加本条内容恰等于上限 | 继续保存到现有文件 |
| 现有文件加本条内容为上限加一字节 | 先创建新文件，再将本条完整写入新文件 |
| 单条内容恰等于上限，现有文件分别为空或已有内容 | 空文件直接保存；已有内容时先创建新文件，再完整保存本条 |
| 多条同时到来的记录合计超过剩余容量 | 各条按写入前规则保存到相应文件，条数完整、名称唯一 |
| 同日再次创建文件，包括重启后创建 | 使用当天日期及可用递增序号，保留所有同名已有文件 |
| 日期改变而现有文件仍有容量 | 继续使用现有文件及原文件名 |

### 场景7: 单条记录超过 10MB 时明确提醒

- GIVEN 一条完整待写内容自身超过 10MB，包含记录分隔所需字节；分别覆盖首次保存和已有文件两种状态
- WHEN 准备保存该条记录
- THEN 拒绝保存该条内容，已有访问文件的内容和大小保持原样，本条触发的新建访问文件数量为零
- THEN 插件详情显示 `REMOTE_RECORD_TOO_LARGE`，desc 说明实际字节数和允许上限
- THEN 随后的正常大小记录继续按保存规则处理

### 场景8: 保存失败明确报告

- GIVEN 创建记录目录、创建或打开访问文件、写入记录时发生错误
- WHEN 本次密码提交结果需要保存
- THEN 插件详情显示该保存错误的 code、完整原始 desc 和本次保存失败的状态
- THEN 已经成功保存的历史继续保留，原有 Remote 登录和访问按既有规则处理
- THEN 故障恢复后，后续密码提交结果继续保存，已报告的保存失败保持可辨认

## feat02: 查看访问记录

电脑本机使用者通过 Remote 插件详情查看当前 Home 的访问记录，按密码校验结果发生先后从新到旧回看全部历史。

### 场景1: 在插件详情查看记录

- GIVEN 电脑本机使用者按既有授权打开 Remote 插件详情，当前 Home 已有成功和失败记录
- WHEN 切换到“访问记录”子 Tab
- THEN 按记录格式展示时间、IP、访问类型、事件和结果，失败记录完整显示 code、原始 desc
- THEN 列表按校验结果发生先后从新到旧展示，时钟回拨后的记录仍保持实际发生顺序
- THEN 切回“访问设置”后，原有设置内容与输入草稿继续保留

### 场景2: 当前 Home 暂无记录

- GIVEN 当前 Home 的记录读取成功，记录条数为零
- WHEN 打开访问记录
- THEN 显示“暂无访问记录”，说明当前 Home 和正式记录开始范围
- THEN 翻页按钮处于边界状态

### 场景3: 每页十条、滚动、翻页与刷新

- GIVEN 当前 Home 的记录分布在多个日期或文件中，记录总数分别为 1、10、11、20、21
- WHEN 使用者滚动列表并依次翻页
- THEN 列表区域独立滚动，每页最多十条，末页显示实际剩余条数，上一页和下一页的边界状态准确
- THEN 本次回看的全部记录依次可达，各页集合完整且每条只出现一次
- WHEN 回看期间产生新记录，使用者继续翻页，随后点击刷新
- THEN 继续翻页保持本次回看的集合及顺序；刷新后回到第一页并展示新增记录

### 场景4: 读取失败显示原始原因

- GIVEN 打开、读取或解析访问记录时发生错误，界面可能已有上次成功读取的列表
- WHEN 使用者打开或刷新记录
- THEN 显示该错误的 code 与完整原始 desc，明确说明本次读取失败
- THEN 已显示列表继续保留并标示为此前结果，原有文件保持原内容
- THEN 使用者可在故障恢复后重新刷新并查看记录

### 场景5: 查看权限限定电脑本机

- GIVEN 使用者分别从电脑本机、局域网入口和公网入口尝试查看访问记录
- WHEN 发起查看操作
- THEN 电脑本机经过既有授权可查看当前 Home 的记录
- THEN 局域网和公网入口收到明确的查看受限结果及 code、desc，访问记录内容保持仅对本机授权使用者可见

## 开发备注

2026-10-23 用户同意本版规格及技术设计，确认文件细则：时间采用运行 KMH 的设备，10MB 为 10,000,000 字节，文件扩展名为 `.log`，同日后续序号从 `_1` 起。技术方案与逐场景测试安排见[技术设计草案](tech-design.md)。
