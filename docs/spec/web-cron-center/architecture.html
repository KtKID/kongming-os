说明

  • P0 链路：M1 + M2 + M3 + M4 + M6 + M7 + M8 + M9 + M10。最小可用要 9 个模块同时落地。
  • P1 增强：M5（WS 实时推送）+ WS frame 扩展。没有这两个用户也能用，但要手动刷新看新结果。
  • P2 协作：FileDrawer（既有），通过 M10 与 cron 抽屉互斥。
  • 实线 →：强依赖（编译期 / 运行期必须）
  • 虚线 ⤳：弱依赖（订阅 / 协调 / 调起）

实施顺序

  1. T1：M1 + M2 + WS frame 扩展（含 PoC 验证 list_recent_runs 性能）
  2. T2：M3 + M4 + M5
  3. T3：M6 + M7 + M10（必须一起做，互斥协调依赖）
  4. T4：M8（任务列表 + 行）
  5. T5：M9（日志区）
  6. T6：红点 + 实时推送整合 + e2e 验证
T4 与 T5 可并行；T6 必须最后做，作为收口测试。详见 90-task-map.md。
