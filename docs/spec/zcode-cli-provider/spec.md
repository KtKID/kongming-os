# 使用本机 ZCode 模型运行 KMH Agent

用户通过可独立分享的 `@kmh/zcode-cli` 插件，在 KMH 使用本机官方 ZCode CLI 中的模型。KMH 管理发送时机与结果投影，CLI 管理原生上下文、工具与内部回合；模型从登录账号的动态目录选择，默认取目录首选，思考等级为高。实施推进至人工账号授权时停下，通知用户完成登录。

## 当前实现与规格差异

当前模型调用使用 CLI 原生会话中继，完整使用契约见[包说明](../../../packages/zcode-cli/README.md)。feat01 场景1 的 KMH 提示与宿主 read 工具接入仍待实现；该场景保留为需求目标。CLI 会话的创建、复用、恢复、权限映射与停止由原生协议驱动；请求监督的现状及后续目标见[监督说明](../../research/zcode-cli-request-supervision.md)。旧实施报告按其记录日期的协议阅读。

## feat01: KMH 提示与文件读取

本节场景1定义 KMH 提示与宿主工具的待实现目标；当前会话使用 CLI 原生工具。

场景1: 完整提示与 read 循环

- GIVEN 账号可用，用户在现有模型选择器选择 ZCode
- WHEN 用户请求读取文件
- THEN 模型收到 KMH 当前系统提示和 read 工具，可选提示模块提供“你是 kmh agent，底层是 zcode cli 里的模型”的身份说明，KMH 读取文件并将结果交给模型继续响应

场景2: 模型默认选择

- GIVEN 用户已完成账号登录并查看 ZCode 模型选项
- WHEN 打开模型选择或发送任务
- THEN 可选模型来自登录账号的动态目录（官方模板与服务端模型列表的交集，官方模板缺失时按端点返回倒序），默认选中目录首选，思考等级为高；重新登录后目录随新账号刷新

场景3: 会话默认输出上限

- GIVEN 会话未指定最大输出长度
- WHEN KMH 向 CLI 发送模型请求
- THEN CLI 原生会话管理输出上限；插件以 defaultMaxTokens（默认 1M token）生成个人配置中的模型校验上限规则，会话发送使用原生协议支持的字段。连通探测单独传入输出上限 1。

场景4: 请求异常

- GIVEN 请求包含首版尚未支持的内容，或 CLI 请求超时
- WHEN 模型接入处理该请求
- THEN 显示明确错误，超时进程结束

## feat02: 官方账号登录

用户通过官方授权页完成自己的账号接入。

场景1: 获取授权入口

- GIVEN 用户尚未登录
- WHEN 点击微信 / BigModel 登录，或使用 Z.ai 渠道
- THEN 页面展示完整的官方授权链接和二维码，以及等待授权状态；国内账号的官方页面提供微信登录，原有 Z.ai 渠道继续有效

场景2: 取消与重试

- GIVEN 授权正在进行
- WHEN 用户取消后重新登录
- THEN 旧进程结束，页面显示新尝试的状态，旧尝试无法取消或覆盖新尝试

场景3: 授权完成与退出

- GIVEN 官方授权已经完成
- WHEN 用户查看账号或退出
- THEN 页面显示已登录，退出后插件账号资料清理完成并显示未登录

场景4: 授权失败

- GIVEN 官方程序缺失、账号资料损坏、登录失败、输出异常或等待超时
- WHEN 用户登录或读取状态
- THEN 页面显示可操作的失败状态，原有账号资料保留，敏感凭据受到保护

场景5: 人工登录交接

- GIVEN 自动实施和可自动完成的验证已经结束
- WHEN 下一步需要真人账号授权
- THEN 停止自动操作并通知用户完成授权，真实模型调用的结果在授权后验收

## feat05: 会话工作目录跟随

带会话身份的模型请求在会话自己的工作目录中拉起官方 CLI。

场景1: 会话目录命中

- GIVEN 宿主已挂载 sessions 服务，请求携带会话身份且该会话头部记录了工作目录
- WHEN 插件处理该模型请求
- THEN 官方 CLI 子进程的工作目录与请求中的 workspace 标识均为该会话目录

场景2: 回落启动目录

- GIVEN 请求不带会话身份，或宿主未挂载 sessions 服务，或会话不在库中，或会话目录已被删除
- WHEN 插件处理该模型请求
- THEN 子进程与 workspace 标识回落到插件配置的 cwd，请求不因此失败

场景3: 账号操作不跟随

- GIVEN 用户在插件内登录、退出或测试连接
- WHEN 插件拉起官方 CLI
- THEN 这些进程始终使用插件配置的 cwd

## feat06: 复用桌面端登录

插件数据目录没有账号时只读借用桌面端官方登录。

场景1: 桌面端已登录

- GIVEN 桌面端 `~/.zcode/v2/credentials.json` 存在同套餐凭据
- WHEN 用户查看账号状态或发起模型请求
- THEN 插件读取该凭据并显示已登录，凭据来源显示为复用桌面端登录，桌面端文件保持不变

场景2: 桌面端重新登录

- GIVEN 插件正在借用桌面端凭据
- WHEN 桌面端重新登录更新了凭据文件
- THEN 插件随下次读取自动使用新凭据

场景3: 借用失败

- GIVEN 桌面端凭据缺失、格式变化或密钥不匹配
- WHEN 用户查看账号状态
- THEN 显示未登录且不报错，在插件内登录一次后写入插件数据目录并优先于借用

场景4: 退出范围

- GIVEN 插件正在借用桌面端凭据
- WHEN 用户在插件内退出账号
- THEN 只清除插件数据目录的凭据，随后状态回到借用桌面端登录，桌面端登录不受影响

## feat03: 现有插件管理区

用户在现有 Web 插件管理区查看账号与模型连接。

场景1: 初始状态

- GIVEN 用户已进入 KMH Web
- WHEN 在现有插件列表打开 kmh/zcode-cli
- THEN 在现有插件配置区显示账号、默认模型、思考等级、模型连接状态和登录按钮，点击登录后二维码在该区内展开

场景2: 最小连通测试

- GIVEN 用户已完成账号登录
- WHEN 点击测试连接
- THEN 从登录完成后的测试操作开始计时，向当前模型发送最小 ping 请求，使用空工具列表、默认输出上限 1、该模型支持的 `low` 思考等级和独立的 15 秒超时；成功后显示模型请求已验证，超时显示 ZCODE_PROBE_TIMEOUT 并保留登录状态；登录授权使用自己的时限和 ZCODE_LOGIN_TIMEOUT；登录进行中调用探测显示 ZCODE_LOGIN_REQUIRED，官方返回提示时一并显示经过凭据过滤的提示

场景3: 页面访问保护

- GIVEN 页面请求缺少宿主授权，或来自其他来源
- WHEN 请求账号操作
- THEN 宿主拒绝访问，账号凭据保持受保护

## feat04: 独立分享

使用者可将插件包导出，交给其他 KMH 使用者安装。

场景1: 分享编译包

- GIVEN 插件构建完成
- WHEN 将插件导出安装
- THEN 包包含 provider、可选完整提示模块和现有插件区的账号控件，安装者使用自己的官方 CLI 与账号

场景2: 与既有配置共存

- GIVEN 用户继续使用常规 KMH Web
- WHEN 加载插件
- THEN 原有 Agent 预设和工具注册保持有效，ZCode 仅筛选自己的 CLI 请求工具；加载插件后用户通过现有模型选择器选择 ZCode
