# x-music 服务插件 v0.1

为 KMH Web 编写第四个"服务插件"——x-music（包名建议 `@kmh/xmusic`）。**第一阶段只做一条链路：侧边栏注册一个按钮，点击后在主区内嵌打开 x-music 的 Web 端**（本机 60070 上那张能搜歌、点播、看听歌数据并在浏览器里出声的管理面板，x-music 自称 Dashboard / Web Receiver，用户端口表称 Board）。面板地址先用插件配置的默认值。助手工具接入（MCP）、插件详情配置表单、打不开时的超时提示与系统浏览器兜底，都是**后续阶段**，按用户逐阶段确认排期（见[阶段划分](#阶段划分)）。做法沿用 [MadeMe](../mademe-plugin-v0.1/spec.md)、[Infra](../kmh-infra-plugin-v0.1/spec.md)、[Token 分析](../aggregated-token-analysis-view-v0.1/spec.md)三个服务插件已验证的形态，不新造一套；范围遵循剃刀法则——如无必要，勿增实体。判断依据与全部证据见同目录[调查记录](findings.md)。

## feat01: 侧边栏出现 x-music 入口

插件把一个按钮注册到框架侧边栏并设置显示名。侧边栏本身是框架的功能，插件**只注册、不改动**；按钮注册后按侧栏现有机制显示（展开态图标加名字、收起态悬停提示、停用插件即消失、选中态），这些均为框架自身行为，本插件不做也不测。

场景1: 启用后可见
- GIVEN 用户已安装并启用 x-music 插件
- WHEN 用户打开或刷新 KMH Web
- THEN 侧边栏出现入口：显示名"x-music"（英文界面同名），排在现有服务插件入口之后

## feat02: 点击内嵌打开 x-music 面板

用户点击侧边栏的 x-music 入口，在主区内嵌打开 x-music 的 Web 端，与 KMH 会话互不干扰。

场景1: 正常打开（第一阶段）
- GIVEN 插件已启用，x-music 的 Web 端正在运行，主区显示会话
- WHEN 用户点击 x-music 入口
- THEN 主区从会话切换为 x-music 管理面板（地址取插件配置的默认值），入口呈选中态；面板里的搜歌、点播、听歌数据全部由 x-music 提供，KMH 不另加内容

场景2: 切走再切回（第一阶段，预期行为）
- GIVEN 主区显示 x-music 面板，面板里正在播一首歌
- WHEN 用户回到会话，之后再次点击 x-music 入口
- THEN 主区回到 x-music 面板，按当前地址**重新加载**——iframe 技术内嵌网页切走再切回必定刷新，页面内状态与播放不保留（WebKit/Safari、Chrome 均如此，与 MadeMe、Infra 面板一致；用户已知此行为，第一阶段按预期处理）

场景3: 面板打不开（第二阶段）
- GIVEN x-music 的 Web 端没有运行，或配置的地址无法访问、拒绝被内嵌
- WHEN 用户点击 x-music 入口
- THEN 主区切入面板并显示加载中；超过配置的面板加载超时（默认 8 秒）仍未加载出来时，显示"x-music 可能无法内嵌打开"的提示，提示里带上正在尝试的地址与可能原因，并指向"在系统浏览器打开"按钮
- THEN 面板工具栏始终提供"在系统浏览器打开"按钮，不必等提示出现
- THEN KMH 的会话与其他插件照常可用，不受本面板打不开的影响

场景4: 更改面板地址（第二阶段，依赖 feat04）
- GIVEN 用户在插件详情中改了面板地址并保存
- WHEN 用户再次点击 x-music 入口
- THEN 按新地址加载面板

场景5: 面板里出声与浏览器的自动播放拦截（第一阶段，行为说明，不开发）
- GIVEN 主区显示 x-music 面板
- WHEN 用户在面板里点击播放，或手机等其他端把歌推到这台浏览器播放
- THEN 用户自己点播放的，面板直接出声；被其他端推送起播而浏览器拦下自动播放时，面板里出现 x-music 自带的"点击解锁声音"提示，用户点一下即出声；KMH 不另加提示

场景6: x-music 的其他部件没起（第一阶段，行为说明，不开发）
- GIVEN x-music 的 Web 端在运行，但 music-core 或手机网关没有运行
- WHEN 用户点击 x-music 入口
- THEN 面板照常打开；页面内关于服务不可用的提示由 x-music 自己给出，KMH 不另做判断、不另加提示

## feat03: 助手使用 x-music 工具（第二阶段）

x-music 对外开放的助手工具接进助手，用户在会话里直接让助手搜歌、放歌、控制播放、查收听记录、做新歌入库。接入由 KMH Web 配置里的一条接入项承担，不经本插件装配；配置落点、核对与停用方式在实现时写入 [Web 配置](../../../profiles/kmh-web/README.md)。

场景1: 会话中点播
- GIVEN 接入项已声明，x-music 正在运行，用户在新建的会话里
- WHEN 用户让助手"放一首某某的歌"
- THEN 助手先搜歌再点播，歌声从 Mac 本机的播放引擎出，不经过主区面板里的 x-music 页面；面板里若正在播别的歌，两边各放各的、互不打断（x-music 的已知行为）

场景2: 搜歌与收听记录
- GIVEN 同上
- WHEN 用户让助手找一首歌、看最近听了什么、或问某首歌听过几次
- THEN 助手给出跨源搜歌结果（标题、歌手、时长、来源、能否播放）、按时间倒序的收听记录，或单曲的播放次数与播完次数

场景3: x-music 没在运行
- GIVEN 接入项已声明且工具已经出现过，但 x-music 当前没有运行
- WHEN 用户让助手放歌或查记录
- THEN 助手明确回答 x-music 未运行、需要先启动（x-music 的工具自己会返回"x-music 未运行，请先执行 xm start"），不把它说成"没有这首歌"或"没有记录"

场景4: x-music 在 KMH 之后才启动
- GIVEN KMH Web 启动时 x-music 还没有运行
- WHEN 用户在会话里让助手放歌
- THEN 助手暂无 x-music 工具可用（工具不出现，无法调用）；用户启动 x-music 后重启 KMH Web，工具出现

场景5: 仅新建会话可见
- GIVEN 接入项刚声明并重启了 KMH Web
- WHEN 用户在重启前就已存在的会话里让助手放歌
- THEN 助手在该旧会话里没有 x-music 工具；新建会话后可用

场景6: 停用插件不影响工具
- GIVEN 接入项已声明且工具可用
- WHEN 用户停用 x-music 插件
- THEN 侧边栏入口与面板消失，但助手的 x-music 工具仍在；要停掉工具，需从 Web 配置里移除接入项并重启 KMH Web

场景7: 入库类工具
- GIVEN 接入项已声明且工具可用
- WHEN 用户让助手"把刚传到 NAS 的新歌入库"
- THEN 助手能执行 x-music 的入库工具；涉及清理残留文件的那一个，x-music 自身要求先预览清单、用户确认后才执行删除，助手按这个两步流程走

## feat04: 在插件详情中填写配置（第二阶段）

用户在 x-music 插件详情中查看和填写面板地址与面板加载超时。

场景1: 查看与修改
- GIVEN x-music 插件已安装
- WHEN 用户打开 x-music 插件详情
- THEN 详情页直接显示全部配置项：面板地址（默认 `http://127.0.0.1:60070`）、面板加载超时（默认 8 秒）；每项带默认值，可修改并保存；保存后立即生效，不需要重启 KMH

场景2: 无效地址
- WHEN 用户填入格式无效的面板地址并保存
- THEN 提示"地址格式不正确"且不保存，原地址继续有效

场景3: 停用后配置保留
- GIVEN 插件已启用并已改过配置
- WHEN 用户停用该插件，之后再重新启用
- THEN 入口与面板恢复，配置项显示的仍是停用前填的内容

## 已知限制

- 第一阶段没有插件详情配置表单：面板地址用插件配置的默认值（`http://127.0.0.1:60070`），要改地址需编辑 profile 配置或等第二阶段的 feat04。
- iframe 内嵌切走再切回必定刷新、页面内状态与播放不保留（feat02 场景2，用户已知此行为）。
- 60070 当前由 x-music 自己的开发服务器提供页面，响应头允许被内嵌；x-music 若改用其他方式托管页面，需复测能否内嵌。
- 内嵌面板不保留 x-music 页面内的播放状态；x-music 的 Web 端不需要登录，没有登录态问题。
- （第二阶段起）助手工具的接入配置不在插件详情页：改接入地址或停用工具需编辑 Web 配置并重启 KMH Web。
- （第二阶段起）x-music 需先于 KMH Web 启动；工具仅新建会话里可见；12 个工具整体接入不能挑选，其中入库工具带"确认后删除"能力（取舍见待确认 6）。
- （第二阶段起）助手点播的声音从 Mac 本机播放引擎出，不经面板里的页面，两边各放各的。

## 已解决（2026-10-18 用户确认）

- **第一阶段范围**：只做"点按钮 → 打开内嵌网页"，先跑通链路（剃刀法则：如无必要勿增实体）。
- **feat01 定位**：只是把按钮注册到框架并设置名字；侧边栏的展示与交互是框架功能，不能改也不测。
- **iframe 切走切回刷新**：用户已知这一行为；第一阶段按预期行为处理，写进 feat02 场景2。

2026-10-18 第二轮（开发前拍板）：

- **命名**：按待确认 3 的默认值实现——包 `@kmh/xmusic`、目录 `packages/kmh-xmusic`、实例 `kmh-xmusic`、侧栏显示名"x-music"。
- **面板打不开不做特殊处理**：x-music 的 Web 端未运行或地址不可达时，面板内就是浏览器对该 iframe 的原生呈现；插件不计时、不提示、不加兜底按钮。C2 的提示与"在系统浏览器打开"仍属第二阶段。
- **插件未启用即无入口**：框架行为，插件不做事、不测。
- **实现范围只在插件包内**：功能代码全部在 `packages/kmh-xmusic`；包外只做接入登记（profile 依赖与实例、根 `package.json` 的 filter 列表、运行时测试的包清单、文档索引），不改任何既有功能代码。
- **第一版不做 MCP**：feat03 整体留第二阶段，第一阶段不声明 `mcp-xmusic` 实例。
