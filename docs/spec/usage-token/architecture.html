关键设计点

  • 架构边界：.importlinter Contract usage-token-encapsulation 强制；未通过 lint 不能 merge
  • 外部 API 表面 ≤ 6 个：record_run_usage / get_thread_summary / get_last_run_snapshot / to_ws_frame / context_window / context_usage_pct
  • channel ≠ backend_kind：前者是 token 语义（anthropic / openai），后者是 transport 路由（claude_code / codex / generic_chat）；映射规则在 manager 内部
  • ThreadMetadata 透明 dict 落盘：cumulative_usage: dict[str, Any] 不直接持 TokenUsage 类型，避免外部模块通过 ThreadMetadata 间接接触内部模型
  • 前端 codegen：仅生成公共 DTO（UsageFrame / Snapshot / Summary），内部 TokenUsage 不暴露
  • v7→v8 lazy upgrade：沿用现存懒升级风格，按 backend_kind 启发式映射；幂等保证
