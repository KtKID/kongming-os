# kmh-team 第一版实现约束

本文保存本次需求讨论已确认的实现约束，功能与验收场景以[需求规格](spec.md)为准。当前阶段交付需求文档；技术设计、任务拆解和运行验收属于后续阶段。

## 插件归属与参考范围

团队功能由 KMH 自有插件 `kmh-team` 提供。入口、配置弹窗、详情页设置、团队身份、消息路由和群聊呈现均由该插件负责。后续技术设计可以划分内部模块，用户面对一个 `kmh-team` 插件。

DSH Agent Teams 的范围限定为源码与安全机制参考。禁止挂载或调用 DSH Agent Teams 的运行时、工具和团队 UI；首版复用现有 subagent、模型、会话、存储与客户端扩展能力。可参考身份校验、请求去重、取消清理与持久恢复的处理方式。参考资料为 [DSH Agent Teams 中文说明](../../../third_party/dsh/packages/experimental/agent-team/README.zh.md)。

## 身份、会话与触发

固定 Agent 配置长期保存，可以由用户配置创建，也可以由主 Agent 创建。同一配置可用于多个团队。每个团队会话由 KMH 主 Agent 自动作为 owner 加入，产品中的身份名称为 `team-owner`。owner 区域仅允许选择模型，角色配置列表与成员加入／移除列表仅包含其他 Agent。角色配置的长期身份与每次执行使用的会话身份分别记录。

普通用户消息交给 owner。仅当用户提交有效的团队成员点名时，被点名成员才创建执行会话并接收本次上下文。未被点名的固定成员保持静默，禁止向其投递群消息、预先建立执行会话或因 owner／其他成员的正文提及而唤醒。跨团队的上下文分别归属各自会话。

首版允许通过已有 subagent 能力执行被点名成员。每次有效点名使用新的 fresh 执行上下文，成员模型沿用本团队 owner 的所选模型，工具和 skill 继承 owner，并遵循既有操作范围。先前成员会话作为独立执行记录保留，当前调用仅接收本次选定的群聊上下文。运行记录应保留本次角色、触发消息和执行结果，供停止、失败处理和恢复使用。[现有 fresh subagent 说明](../../../third_party/dsh/packages/subagent/subagent-spawn-in-process/README.zh.md)供后续技术设计核对。

## 上下文与结果展示

默认传递最近 20 条群聊可见消息，数量由 `kmh-team` 插件详情页配置。上下文包含本团队已提交的用户消息、已完成的 Agent 回复及其发言者信息，计数包含本次点名消息，提交时确定本次窗口。一条消息可点名多位成员，每位成员接收同一窗口一次。模型实际收到的上下文必须保存在本次执行记录中，完整功能规则见[需求规格](spec.md)。

被点名成员完成后，完整回复进入团队群聊并保留实际发言者身份。工具调用、参数、执行结果和详细运行状态保存在执行记录中。群中展示隐藏仅影响呈现，模型调用与工具执行继续遵循现有记录和权限机制。

## 头像下的工作标记

owner 或成员实际执行任务期间，头像下只显示“工作中”。工作标记分别归属团队会话与回应者，依据各任务的实际开始和结束更新；等待开始时头像保持普通显示，模型请求或单次工具步骤结束时持续显示标记，该回应者在当前团队的全部实际执行任务完成、失败或确认停止后清除标记。

任务开始和结束的记录必须关联各自的任务身份。较早任务的延迟或重复通知只影响对应任务；同一回应者仍有其他实际执行的任务时继续显示“工作中”。同一固定 Agent 在不同团队的标记分别显示。切换会话、重新连接和刷新页面时恢复实际执行状态，进程重启后已中断的任务清除工作标记。相应验收场景由规格 feat06、feat08 定义。
