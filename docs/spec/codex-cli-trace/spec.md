# 在会话内查看 Codex CLI 执行记录

用户在 KMH 当前会话的标签栏打开 Codex Trace，查看这段对话对应的 Codex CLI 执行过程：每轮输入与回复、每次模型响应的 token 用量、工具参数与结果、技能调用、文件操作、耗时和原始记录。记录来自本机已经保存的 CLI 文件，已有历史可以回看，新增记录随文件更新出现。

功能由独立插件 `codex-cli-trace` 提供，沿用 KMH 的会话与 Web 界面，第一版读取 CLI 已保存的记录，提供展示、随文件更新刷新和导出。当前已有静态效果图，正式插件的技术方案已确认，开发任务已拆解。

功能范围依据用户于 2026-10-15 提供的流程图及“对齐信息就走 x-tech-design”确认：执行链由 Web 经 codex-cli 接入插件调用 CLI，CLI 保存本地会话记录；查看链由 trace 读取对应记录，在当前会话内展示和导出。具体布局、刷新参数与导出文件格式在同目录技术设计中提出，技术设计状态单独记录。

## feat01: 独立启停执行记录查看器

用户可以单独启用或关闭查看器，使用本机保存的历史记录。

场景1: 独立启用

- GIVEN KMH Web 可以使用，本机保存了 Codex CLI 会话记录和对应会话的关联信息
- WHEN 用户单独启用 codex-cli-trace，并打开对应会话
- THEN 用户可以进入执行记录标签，查看已经保存的内容

场景2: CLI 接入插件已经关闭

- GIVEN 用户保留了会话关联与 CLI 历史，Codex CLI 接入插件当前处于关闭状态
- WHEN 用户打开对应会话的执行记录标签
- THEN 已保存的历史仍可查看，页面标明最近记录时间

场景3: 关闭查看器

- GIVEN 用户正在 KMH 查看某个会话
- WHEN 用户关闭 codex-cli-trace
- THEN 新增标签从会话标签栏移除，用户仍可使用原有会话界面

场景4: 记录位置暂时不可读取

- GIVEN 查看器已启用，保存记录的位置暂时不可访问
- WHEN 用户打开执行记录标签
- THEN 页面显示读取失败的原因和重试入口；已经展示的历史继续保留，并标明最后一次成功读取时间

## feat02: 在当前会话内进入执行记录

用户沿用现有会话导航，打开和切换 Codex Trace。

场景1: 打开新增标签

- GIVEN 用户已经打开一个 KMH 会话，查看器已启用
- WHEN 用户查看会话的标签栏并点击 Codex Trace
- THEN 新增标签与“对话”“轨迹”“上下文”同级，主体区域展示当前会话对应的执行记录，现有会话标题继续可见

场景2: 切换会话

- GIVEN 用户正在查看会话 A 的执行记录，会话 B 也有对应的 CLI 历史
- WHEN 用户切换到会话 B 并打开 Codex Trace
- THEN 页面明确显示会话 B，时间线、统计与详情均来自会话 B

场景3: 当前会话尚无对应记录

- GIVEN 当前会话没有对应的 Codex CLI 历史
- WHEN 用户打开 Codex Trace
- THEN 页面显示“当前会话暂无 Codex CLI 记录”，原有会话标签继续可用

场景4: 会话对应关系存在歧义

- GIVEN 保存的信息暂时无法唯一确定当前会话对应哪份 CLI 历史
- WHEN 用户打开 Codex Trace
- THEN 页面显示“暂时无法确定这段会话对应的 CLI 记录”和重试入口，统计与时间线保持待确认状态

场景5: 窄窗口查看详情

- GIVEN 用户在窄窗口中打开时间线
- WHEN 用户选中一条执行记录
- THEN 详情以适应当前窗口的方式展开，用户可以返回原时间线并保留查看位置

## feat03: 回看和切换历史回合

用户按自己发送的任务选择回合，查看每轮的独立执行过程。

场景1: 切换已完成回合

- GIVEN 当前会话有测试问候和翻译文件两个已完成回合
- WHEN 用户分别选择这两个回合
- THEN 页面分别显示对应的用户输入、模型响应、工具记录、用量、耗时和最终回复，所选回合始终明确可见

场景2: 打开仍在追加记录的回合

- GIVEN 当前会话有一个结束状态尚未保存的回合
- WHEN 用户打开 Codex Trace
- THEN 默认展示该回合和最新已保存内容，记录明确提供执行状态时显示该状态，结束状态缺失时显示“结束状态待确认”

场景3: 当前会话全部结束

- GIVEN 当前会话有多个已完成回合，用户尚未选择本次查看的回合

场景5: 当前文件的部分记录缺失

- GIVEN 当前会话的 CLI 文件仍可读取，其中部分记录缺失
- WHEN 用户打开回合列表

## feat04: 查看逐响应与当前回合的用量

用户可以查看每次模型响应的 token 明细，以及当前回合的汇总。

场景1: 查看逐响应用量

- GIVEN 某次模型响应保存了完整用量
- WHEN 用户选中该响应
- THEN 详情显示输入、缓存读取、缓存写入、输出、推理输出和总 token 数，以及该响应的记录标识

场景2: 理解明细口径

- GIVEN 用户查看输入、缓存、输出和推理的数值
- WHEN 用户查看用量说明
- THEN 页面明确说明缓存属于输入的细分、推理属于输出的细分；汇总沿用所展示原始记录的口径

场景3: 查看回合汇总

- GIVEN 当前回合保存了多次模型响应和工具执行
- WHEN 用户查看概览
- THEN 显示当前回合的模型响应次数、工具调用次数、输入与输出明细、总用量和缓存输入占比；工具失败的调用计入调用次数，并可查看失败状态

场景4: 重复发现同一响应

- GIVEN 同一条响应记录在重新读取时再次出现
- WHEN 页面刷新统计
- THEN 该响应在明细中出现一次，其用量在当前回合的合计中计算一次

场景5: 用量缺失或只保存部分明细

- GIVEN 某次响应的用量缺失，或仅提供了部分明细
- WHEN 用户查看该响应与回合概览
- THEN 已知数值正常显示，缺失项显示“未记录”，汇总注明“部分用量”；原始记录明确给出的 0 显示为 0

场景6: 一次模型响应发起多个工具调用

- GIVEN 同一次模型响应发起了多个工具调用
- WHEN 用户查看这组记录及回合概览
- THEN 工具调用分别列出，模型响应及其用量按该次响应计算一次

用户可以从统计或执行条目回到已有证据，识别当前文件的记录范围、缺失信息和读取异常。

场景1: 查看条目来源

- GIVEN 用户选中一条模型响应或工具记录
- WHEN 用户打开“原始记录”
- THEN 页面展示对应原文、所属会话和回合、来源文件、记录位置及已有标识，用户可以复制需要核查的内容

场景2: 查看已有记录范围

- GIVEN 当前会话已读取一部分记录
- WHEN 用户打开记录范围说明
- THEN 分别说明当前文件中对话、工具、技能、用量和耗时的已有证据，标明已记录、部分记录、未记录或暂未识别的项目

场景3: 原始文件与已展示内容发生变化

- WHEN 用户继续核对原文
- THEN 页面显示当前内容的来源文件、记录位置及读取时间；内容变化时提示重新读取，后续核对依据当前文件

场景4: 某条记录损坏

- GIVEN 同一份历史中有完整可读条目，也有已确认损坏的条目
- WHEN 用户打开时间线与记录范围
- THEN 完整条目继续可查，损坏位置及其造成的覆盖缺口有明确说明，相关汇总标为部分记录

## feat11: 导出当前会话的审计记录

用户可以把当前会话对应的已有 CLI 记录保存为文件，供离开页面后继续核查。

场景1: 导出当前会话

- GIVEN 当前会话对应的 CLI 文件已有可读记录
- WHEN 用户点击“导出记录”并保存文件
- THEN 用户得到当前会话的审计记录文件，包含对应 CLI 文件中已有的回合、模型和推理等级、用量汇总及明细、消息、工具参数与结果、技能调用、耗时、来源原文和记录范围说明；页面明确显示导出的会话及范围

场景2: 页面处于筛选状态

- GIVEN 用户正在查看其中一个回合或使用搜索、“仅异常”，页面只显示部分条目
- WHEN 用户点击“导出记录”
- THEN 页面明确说明导出范围为当前会话对应的已有 CLI 记录，保存文件覆盖本次导出截止时点的完整记录，回合选择、搜索和类别筛选仅影响页面查看

场景3: 导出仍有新增记录的会话

- GIVEN 当前会话的源文件仍可能新增记录
- WHEN 用户导出当前会话
- THEN 文件注明本次导出的截止时间和结束状态待确认，内容覆盖该时点已读取的记录，后续新增内容可通过再次导出获取

场景4: 历史存在缺口或截短

- GIVEN 当前文件有用量缺失、返回内容截短或损坏记录
- WHEN 用户导出当前会话
- THEN 文件保留已有内容和对应的缺口说明，汇总的覆盖范围与页面一致

场景5: 暂无可导出记录

- GIVEN 当前会话尚无已确认对应的 CLI 记录，或读取尚未成功
- WHEN 用户查看导出入口
- THEN 页面说明当前暂无可导出记录及其原因，记录就绪后导出入口恢复可用

场景6: 导出失败

- GIVEN 用户已经发起当前会话的导出
- WHEN 文件准备或保存失败
- THEN 页面提示失败原因并提供重试方式，原时间线、筛选条件和已选详情保持可见

场景7: 记录内容较长

- GIVEN 当前会话包含长工具结果，页面使用摘录显示
- WHEN 用户导出当前会话
- THEN 导出文件保留相应的已保存内容，页面显示摘录与源记录中的截短分别标明
