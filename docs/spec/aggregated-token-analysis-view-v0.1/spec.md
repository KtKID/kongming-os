# 聚合 Token 分析视图 v0.1

为 KMH Web 编写第三个"服务插件"——聚合 Token 分析视图（英文名 Aggregated Token Analysis View）：安装并启用后，侧边栏按现有样式出现"Token 分析"入口（图标加名字，不改图标轨与侧栏现有交互），点击在主区内嵌打开 x-token 提供的聚合 Token 分析页。页面汇总多个渠道的 token 消耗与分布，这也是名字里"聚合"的由来；x-token 侧后续会把它演化成 token 成本分析与异常分析工具。本插件自始至终只负责展示：不计算、不汇总、不保存、不改写任何 token 数据，页面内容全部由 x-token 提供，x-token 升级页面后 KMH 侧不需要改动。页面不需要登录。本版按剃刀法则只做三件事——侧栏入口、内嵌打开、在插件详情里填配置（页面地址与页面加载超时两项，全部带默认值）；兄弟插件有而这里没有的（刷新后记住视图、测试连接、工具栏与"在系统浏览器打开"按钮、把能力接入助手）都是有意不做，见文末确认记录。做法沿用 [MadeMe](../mademe-plugin-v0.1/spec.md) 与 [Infra](../kmh-infra-plugin-v0.1/spec.md) 两个服务插件已验证的"侧栏入口 + 内嵌页"形态，不新造一套。

## feat01: 侧边栏出现"Token 分析"入口

用户启用插件后，在现有侧边栏中看到并识别"Token 分析"入口。

场景1: 启用后可见
- GIVEN 用户已安装并启用聚合 Token 分析视图插件
- WHEN 用户打开或刷新 KMH Web
- THEN 侧边栏出现入口：展开态显示插件自带的图标和名称"Token 分析"，排在 MadeMe、Infra 之后，样式与现有侧栏条目一致

场景2: 收起态提示
- GIVEN 侧边栏处于收起状态
- WHEN 鼠标悬停在"Token 分析"图标上
- THEN 显示"Token 分析"名称提示

场景3: 停用即消失
- GIVEN 插件已启用
- WHEN 用户停用或卸载该插件
- THEN "Token 分析"入口从侧边栏消失；若其页面正在主区显示，主区回到会话

## feat02: 点击内嵌打开聚合 Token 分析页

用户点击侧边栏的"Token 分析"入口，在主区内嵌打开 x-token 的聚合 Token 分析页，与 KMH 会话互不干扰。

场景1: 正常打开
- GIVEN 插件已启用，x-token 正在运行，主区显示会话
- WHEN 用户点击"Token 分析"入口
- THEN 主区从会话切换为聚合 Token 分析页（地址取插件配置），首次打开显示加载中，入口呈选中态；页面里各渠道的 token 消耗与分布由 x-token 提供，KMH 不另加任何数字或图表

场景2: 返回会话后再回来
- GIVEN 主区显示聚合 Token 分析页
- WHEN 用户通过新建会话或点击会话列表回到会话，之后再次点击"Token 分析"入口
- THEN 主区回到聚合 Token 分析页，按当前地址重新加载

场景3: 页面打不开
- GIVEN x-token 没有运行，或配置的地址无法访问、拒绝被内嵌
- WHEN 用户点击"Token 分析"入口
- THEN 主区切入页面并显示加载中；超过配置的页面加载超时（默认 8 秒）仍未加载出来时，显示"页面可能无法打开"的提示，提示里带上正在尝试的地址与可能原因（x-token 未运行或地址无效）
- THEN KMH 的会话与其他插件照常可用，不受本页面打不开的影响

场景4: 更改页面地址
- GIVEN 用户在插件详情中改了页面地址并保存
- WHEN 用户再次点击"Token 分析"入口
- THEN 按新地址加载页面

场景5: x-token 升级页面内容
- GIVEN x-token 侧把页面从用量与分布扩展为成本分析、异常分析（地址不变）
- WHEN 用户点击"Token 分析"入口
- THEN 看到的就是扩展后的页面；KMH 侧不需要升级插件，也不需要改任何配置

## feat03: 在插件详情中填写配置

用户在插件详情中查看和填写页面地址与页面加载超时。

场景1: 查看与修改
- GIVEN 插件已安装
- WHEN 用户打开聚合 Token 分析视图插件的详情
- THEN 详情页直接显示全部配置项：页面地址（默认 `http://localhost:60010/_svc/x-token/`）、页面加载超时（默认 8 秒）；每项带默认值，可修改并保存；保存后立即生效，不需要重启 KMH

场景2: 无效地址
- WHEN 用户填入格式无效的页面地址并保存
- THEN 提示"地址格式不正确"且不保存，原地址继续有效

场景3: 停用后配置保留
- GIVEN 插件已启用并已改过配置
- WHEN 用户停用该插件，之后再重新启用
- THEN 入口与页面恢复，配置项显示的仍是停用前填的内容

场景4: 保存失败显示原文
- GIVEN 宿主拒绝配置写入，或保存请求发生传输异常
- WHEN 用户保存配置
- THEN 表单显示宿主或传输层返回的原文错误，保留用户填写的草稿
- THEN 成功保存后错误消失，页面使用宿主接受的新配置
