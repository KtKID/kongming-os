# 使用本机 Codex 模型运行 KMH Agent

用户通过可独立分享的 Codex CLI 插件，在 KMH 使用本机官方 Codex 模型。KMH 管理提示、技能、KMH 工具执行与用户审批，并负责会话推进；Codex 执行选中的原生工具并保留自己的对话历史。普通新建 KMH 会话采用创建时的工具配置，后续续聊恢复该会话对应的 Codex 原生会话和原工具配置。用户可以同时使用两类工具，在 KMH 查看原生工具的实时进度、结果和待审批操作。账号沿用本机 Codex 登录，模型从官方目录选择，两边各自保存会话记录并保持对应。用户已有的 Codex 配置保持原样，用户配置的 MCP 工具继续可见，本机钩子在 KMH 回合内保持禁用。

本页涵盖原生工具的选择、并存、进度与审批，以及已确认的原生会话恢复规则。原生图片生成已有实现，feat10 补充产物与尺寸验收要求。任务完成记录保留为对应交付时的记录；2026-10-13 更新的关键约束和场景构成本次验收依据，现有决策与任务按关联约束编号对齐。实施记录见 [decisions.md](decisions.md)。

## feat01: KMH 提示与工具执行

模型使用 KMH 提供的身份、提示与该会话确定的工具目录处理用户任务，KMH 工具按 KMH 权限执行，选中的原生工具按其来源执行，结果用于继续完成任务。

场景1: 完整提示与工具循环

- GIVEN 账号可用，用户在现有模型选择器选择 Codex 模型
- WHEN 用户发送任务
- THEN 模型收到 KMH 当前提示与该会话确定的工具目录，请求 KMH 工具时按现有权限链执行并回传结果，模型继续生成直到给出最终回复；过程中用户看到流式正文、可提供的推理内容和用量

场景2: 工具执行期间保持等待

- GIVEN 模型已请求工具且工具正在执行
- WHEN 工具执行耗时较长
- THEN 生成保持挂起等待结果，对话不中断，工具完成后模型从结果处继续

场景3: 工具超时结果回传

- GIVEN 模型请求的工具带有 KMH 侧执行时限
- WHEN 工具执行超时
- THEN 超时作为该次工具的结果回传给模型，模型据此继续响应；不存在无结果的自动续推

场景4: 模型与推理等级选择

- GIVEN 用户已完成账号登录并查看 Codex 模型选项
- WHEN 打开模型选择或发送任务
- THEN 可选模型来自官方目录的分页返回，默认选中目录首选，推理等级只能选模型声明的可选值；模型能否实际访问以连接测试结果为准

场景5: 请求异常

- GIVEN 请求包含尚未支持的内容，或推理超过时限
- WHEN 模型接入处理该请求
- THEN 显示明确错误，本回合进程结束

## feat02: 工具与技能隔离

默认使用 KMH 工具与技能，并保留已接入的原生图片生成能力。用户可逐项选择其余原生工具，原生技能单独选择；工具来源与执行权限保持清楚。

场景1: 默认能力集合

- GIVEN 用户采用默认选择
- WHEN 用户普通新建使用 Codex 的 KMH 会话并发送任务
- THEN 模型可使用 KMH 工具、KMH 技能和原生图片生成；命令执行、文件修改、查看图片、网络搜索等其余原生能力按用户选择开放，原生技能默认关闭；用户配置的 MCP 工具继续可见，本机钩子保持禁用

场景2: 原生技能显式调用接管

- GIVEN 原生技能保持关闭，官方 CLI 自带技能目录存在
- WHEN 用户在输入中使用“$技能名”式调用
- THEN 不触发 Codex 原生技能，技能内容由 KMH 自己的技能体系提供

场景3: 选择原生工具并与 KMH 工具并存

- GIVEN 用户在插件详情页选择命令执行、文件修改等受支持的原生工具
- WHEN 用户普通新建使用 Codex 的 KMH 会话并发送首条消息
- THEN 模型可使用选中的原生工具和 KMH 工具，每次调用显示来源，两类工具各自执行一次；同名工具按来源正确选择，KMH 工具继续遵循 KMH 权限，原生操作需要审批时由 KMH 用户决定

场景4: 工具配置修改只影响普通新建会话

- GIVEN 已创建的会话甲选择了工具 A、B、C
- WHEN 用户在工具配置中关闭 C，继续会话甲，并普通新建会话乙
- THEN 会话甲继续使用 A、B、C 和原 Codex 原生会话；会话乙使用 A、B 并建立自己的原生会话；工具来源与执行权限各自保持清楚

场景5: 裁剪配置应用失败

- GIVEN 本会话所选能力的限制未能应用
- WHEN 回合准备模型接入
- THEN 显示明确错误并结束本次准备；用户修正运行条件后可恢复原会话重试，需要调整工具选择时修改配置并普通新建 KMH 会话

场景6: 能力不可用

- GIVEN 用户选择的原生工具受到本机版本、账号、模型或部署条件限制
- WHEN 查看能力列表或发起任务
- THEN 显示该项不可用及已知原因，任务开始前明确告知能力缺口，已有选择保持可查看

场景7: 旧开关配置

- GIVEN 用户已保存旧的原生工具总开关配置
- WHEN 升级后打开插件详情页
- THEN 显示旧配置对应的实际能力选择与尚待接入的项目，用户可逐项调整；默认关闭的旧配置保留原生图片生成与 KMH 工具的现有使用方式

场景8: 原生技能独立选择

- GIVEN 原生技能选择与工具选择分别保存，会话正在进行
- WHEN 用户修改原生技能选择并继续该会话
- THEN 原生技能按既有规则在下一回合使用新选择；该会话的工具选择和原生会话绑定继续保持

## feat03: 持续对话与会话绑定

同一 KMH 会话的多个回合共享同一个 Codex 原生会话和该会话确定的工具选择，两边各自留存记录；同一会话内回合串行执行，官方 CLI 的工作目录跟随 KMH 会话的工作目录。

场景1: 首次创建与后续恢复

- GIVEN 用户普通新建使用 Codex 模型的 KMH 会话
- WHEN 用户发送首条消息
- THEN 使用创建该 KMH 会话时确定的工具配置建立 Codex 原生会话，保存该原生会话的标识和工具选择；后续回合恢复同一原生会话，Codex 记住此前对话内容

场景2: 重启后继续

- GIVEN KMH 重启，或上一回合结束后进程已退出
- WHEN 用户在同一会话继续对话
- THEN 按保存的原生会话标识和工具选择恢复原会话，完整提交新增输入；Codex 续用原生历史和压缩结果，历史保持单份，既有消息、工具结果和图片继续保留，用户可接着原任务对话

场景3: 标题生成走独立临时会话

- GIVEN 会话需要标题生成等辅助模型请求
- WHEN 辅助请求发生
- THEN 使用独立临时会话完成，业务对话的原生历史保持完整

场景4: 压缩由 Codex 原生处理

- GIVEN 会话上下文接近上限
- WHEN Codex 在 thread 内完成原生压缩
- THEN 模型侧上下文自动续用压缩结果，KMH 侧历史与差分基线不受影响，对话不中断；KMH 侧发起的压缩请求被明确拒绝

场景5: 会话分叉

- GIVEN 用户对一个使用 Codex 的会话执行分叉，分叉携带分叉点前的历史上下文
- WHEN 分叉会话发起回合
- THEN 分叉创建新的原生会话绑定，沿用源会话的工具配置，并由 Codex 继承分叉点前的原生历史；历史保持单份，原会话的绑定、工具选择与历史保留

场景6: 编辑或重发历史消息

- GIVEN 用户对一个使用 Codex 的会话编辑或重发历史消息
- WHEN 该消息及其后的内容被改写
- THEN 按编辑点分叉创建新的原生会话绑定，沿用源会话的工具配置，由 Codex 继承编辑点前的原生历史并接收改写后的输入；历史保持单份，原绑定保留

场景7: 原生会话缺失

- GIVEN 绑定记录指向的原生会话在 Codex 目录中已不存在
- WHEN 用户继续该会话
- THEN 显示明确的恢复错误并保留旧会话记录，用户可普通新建 KMH 会话开始新的 Codex 对话

场景8: 回合结束自动回收

- GIVEN 一个回合已完成或已终止
- WHEN KMH 完成回合收尾
- THEN 官方 CLI 进程关闭输入并退出，不残留后台进程

场景9: 工具配置或目录变化后继续老会话

- GIVEN 已有会话保存了原生会话标识和工具选择，之后 KMH 或 Codex 工具配置、目录或名称展示发生变化
- WHEN 用户继续该会话
- THEN 按保存的标识恢复原生会话，继续使用该会话原有工具选择；普通新建会话使用最新配置；原有工具实际不可用时明确说明原因，恢复失败按场景7处理

场景10: 长消息与原生历史完整保留

- GIVEN 用户在原生会话中已产生长消息、工具结果或图片，正在同一 KMH 会话续聊
- WHEN 用户发送新的长消息并在进程重启后继续
- THEN 本轮新增输入完整到达 Codex，此前的原生历史和压缩结果继续保留，消息尾部的任务条件与已有工具结果可用于后续回答

场景11: 工具记录能力受限时继续原会话

- GIVEN 已有会话可以恢复，当前 Codex 版本提供的详细工具记录有限
- WHEN 用户在同一 KMH 会话继续任务
- THEN 恢复原绑定的 Codex 会话和原工具选择，按实际收到的信息显示工具进度、结果或已知的记录限制，对话历史继续保持

## feat04: 官方账号登录与退出

用户经官方授权页登录自己的 Codex 账号，凭据由官方 CLI 保存与刷新；登录状态依据本地凭据判断，不发起请求验证。

场景1: 本地凭据免登录

- GIVEN 用户 ~/.codex 已保存 Codex 登录凭据
- WHEN 用户查看账号状态
- THEN 显示已登录，不要求重新授权，状态检查不发起模型请求；凭据是否真实可用以测试连接结果为准

场景2: 登录

- GIVEN 本地没有可用凭据
- WHEN 点击登录
- THEN 打开官方授权页并显示等待状态，授权完成后页面显示已登录

场景3: 登录取消

- GIVEN 授权正在进行
- WHEN 用户取消登录
- THEN 本次尝试终止，回到未登录状态，可重新发起

场景4: 登录失效与重新登录

- GIVEN 本地凭据存在但已失效
- WHEN 发起模型请求或点击测试连接
- THEN 显示登录失效的明确提示，重新登录后恢复可用；仅查看状态不触发失效判定

场景5: 退出账号

- GIVEN 用户已登录
- WHEN 在详情页点击退出账号
- THEN Codex CLI 账号退出并显示未登录，页面说明该操作作用于本机官方 Codex CLI 账号；验收不执行真实退出，以实现检查为准

## feat05: 插件详情页

用户在现有 Web 插件管理区查看 Codex 接入状态并做连接测试。

场景1: 信息展示

- GIVEN 用户已进入 KMH Web
- WHEN 打开 kmh/codex-cli 插件页
- THEN 显示官方 CLI 版本、账号状态、凭据来源、默认模型、推理等级和最近一次连接测试结果，提供登录、测试连接与退出账号入口，以及工具配置和独立的原生技能选择；启用 Tools Selector 时可视化编辑 KMH 与 Codex 原生工具开关；账号状态依据本地凭据判断，打开页面不发起模型请求，真实可用性以测试连接结果为准

场景2: 调整原生工具与技能选择

- GIVEN 用户已打开插件详情页，列表显示当前选择与每项可用状态
- WHEN 用户调整原生工具或技能选择
- THEN 新选择立即保存并显示；工具选择明确标注“仅普通新建会话生效”，已创建会话保留原工具选择；原生技能继续按 feat02 场景8 的独立规则生效

场景3: 测试连接

- GIVEN 用户已完成登录
- WHEN 点击测试连接
- THEN 用当前选择的模型在独立临时会话中执行短文本请求，成功显示验证通过，失败显示原因，完成后临时会话与进程回收

场景4: 版本不支持

- GIVEN 本机官方 CLI 版本低于插件声明支持的最低版本，或找不到官方 CLI
- WHEN 用户打开详情页或发起登录
- THEN 显示明确的版本提示与处理指引

场景5: Tools Selector 独立启停

- GIVEN 用户已保存 Codex 工具配置并创建了会话，Tools Selector 已启用
- WHEN 用户关闭或卸载 Tools Selector，继续已有会话，并通过 Codex 配置修改工具开关后普通新建会话
- THEN 已有会话仍恢复原 Codex 会话和原工具选择；普通新建会话使用修改后的配置；再次启用 Tools Selector 时显示 Codex 当前保存的工具配置

## feat06: 停止与故障恢复

用户可随时停止生成，各类故障有独立提示与恢复路径。

场景1: 停止生成

- GIVEN 生成、工具执行或用户审批等待正在进行
- WHEN 用户点击停止
- THEN 工具执行与模型生成中止，待审批操作随本回合取消，显示已停止；回合终止后进程清理，迟到的审批答复按过期处理

场景2: 故障分类提示

- GIVEN 发生用户取消、超时、登录失效、协议错误或进程意外退出
- WHEN 故障发生
- THEN 每类故障显示独立错误码与可读说明，登录状态与既有会话记录不被破坏

场景3: 中途崩溃后恢复

- GIVEN 回合进行中插件或宿主崩溃
- WHEN 下次继续该会话
- THEN 已完成的消息与工具结果按两边日志识别；工具结果不确定的调用记录恢复状态，不重复执行有副作用的操作

场景4: 清理超时兜底

- GIVEN 回合终止后进程未在时限内退出
- WHEN 清理超时发生
- THEN 进程经现有子进程托管机制强制回收，用户看到本回合已结束的明确状态

场景5: 查看连接重试并结束等待

- GIVEN 连接失败，系统正在自动尝试恢复
- WHEN 用户查看会话状态或点击停止
- THEN 会话直接显示正在重试及失败原因；停止及时结束等待。恢复输出后显示正常状态，超过请求时限后显示超时，用户可再次发送

## feat07: 独立分享

使用者可将插件包导出，交给其他 KMH 使用者安装使用。

场景1: 分享安装包

- GIVEN 插件构建完成
- WHEN 将插件导出并在其他 KMH 安装
- THEN 包含模型接入入口、详情页入口和类型声明，运行依赖为公开包名，安装者使用自己的官方 CLI 与账号

场景2: 版本基线与自定义路径

- GIVEN 官方 CLI 以声明版本为支持基线
- WHEN 使用者本机安装其他受支持版本或位于自定义路径
- THEN 可通过配置指定可执行文件路径，插件按声明行为工作

场景3: 与既有配置共存

- GIVEN 用户继续使用常规 KMH Web
- WHEN 加载插件
- THEN 原有 Agent 预设和工具注册保持有效，用户通过现有模型选择器选择 Codex 模型

场景4: 不依赖宿主私有改动

- GIVEN 宿主运行官方发布的 DSH 版本，未包含任何 KMH 私有底层改动
- WHEN 安装并加载插件
- THEN 模型对话、账号操作、详情页与测试连接完整工作，插件对宿主的全部接入经公开插件服务完成

## feat08: 查看原生工具实时进度

用户在 KMH 对话中查看原生工具的开始、执行过程和最终结果，区分工具执行与模型思考。

场景1: 命令与文件操作

- GIVEN 用户启用了原生命令执行或文件修改
- WHEN 模型执行这些工具
- THEN 对话显示工具来源、操作摘要、执行中状态及结果；命令输出随执行更新，文件修改显示可提供的变更内容，失败显示原因

场景2: 其他原生工具与 MCP 工具

- GIVEN 模型使用已选中的查看图片、网络搜索或用户配置的 MCP 工具
- WHEN 工具提供阶段、过程输出或结果
- THEN 对话按实际提供的信息更新同一次调用，结果与来源可查看；原生执行信息展示时该操作保持单次执行

场景3: 长时间执行且缺少细节

- GIVEN 原生工具正在执行，其服务仅提供开始和结束信息
- WHEN 用户等待结果
- THEN 持续显示执行中与已等待时间，进度描述以已收到的信息为准；图片生成按这个规则显示等待状态

场景4: 并发与重复信息

- GIVEN 一个回合中多个工具同时执行或重复收到同一次调用的信息
- WHEN 用户查看进度
- THEN 每次调用保持独立的操作记录，同一次调用的更新合并到原记录，完成结果各自对应原操作

场景5: 刷新与重新打开

- GIVEN 用户已经收到工具进度或完成结果
- WHEN 刷新页面、重新打开会话或重启 KMH
- THEN 已保存的操作记录与结果可重新查看，查看记录保持单次执行；缺少结束确认的调用显示状态待确认

场景6: 工具失败与连接中断

- GIVEN 工具执行失败、用户停止回合或连接意外中断
- WHEN 对话更新操作状态
- THEN 分别显示失败、停止或状态待确认；已有输出保留，后续处理沿用 feat06 的恢复规则

## feat09: 决定原生工具审批

原生工具的审批与执行范围跟随 KMH 会话的权限模式：请求审批、帮我审批与完全权限对应官方 CLI 的同名三档。请求审批档下，原生工具需要额外权限或用户输入时，KMH 展示真实操作并等待用户决定。

场景1: 批准单次操作

- GIVEN 权限模式为请求审批，原生工具请求命令执行、文件修改或额外权限
- WHEN 用户查看并批准请求
- THEN KMH 显示工具来源、操作内容、目标位置、申请权限与授权范围；批准仅覆盖当前请求，原生工具随后执行并继续任务

场景2: 拒绝操作

- GIVEN 原生操作等待用户决定
- WHEN 用户拒绝
- THEN 该操作标记为已拒绝，模型收到拒绝结果并可继续完成任务，其他已授权操作保持原权限

场景3: 用户输入与外部工具确认

- GIVEN 原生工具或 MCP 工具请求用户填写信息、选择选项或完成外部授权
- WHEN 用户查看请求并答复或取消
- THEN KMH 展示问题或授权目的，答复用于对应请求继续执行，取消按该请求的取消或拒绝结果处理

场景4: 停止、重复答复与过期请求

- GIVEN 审批等待期间用户停止回合，或同一请求收到多次答复
- WHEN 系统处理答复
- THEN 同一次请求只采用一次有效决定，已停止回合的审批显示过期，其他会话与回合保持各自的授权

场景5: 缺少审批入口或请求类型未支持

- GIVEN 当前部署没有可用的用户审批入口，或请求的审批类型尚待接入
- WHEN 原生工具申请权限
- THEN 操作保持未执行，显示所缺能力及原因；模型收到明确的拒绝或失败结果，用户可调整任务或部署

场景6: 权限模式映射

- GIVEN 用户在 KMH Web 权限设置中将原“工作区内修改”改为请求审批，或选择新增的帮我审批、完全权限
- WHEN Codex 模型回合开始
- THEN 三档映射官方 CLI 的同名模式：请求审批时需要额外权限的原生操作产生用户审批请求（场景1–5 流程）；帮我审批时沙箱内允许的操作直接执行，额外权限请求由 Codex 自动审查，通过后执行、拒绝后返回结果；完全权限时不经沙箱与审批直接执行；仅可查看保持只读；进行中的回合按其开始时的模式完成

## feat10: 验收已有图片生成产物

用户继续使用已接入的原生图片生成，能够查看、保存图片并看到实际像素尺寸；尺寸要求从简处理，不另建改尺寸交付管线。

场景1: 图片完成与保存

- GIVEN 用户请求生成图片
- WHEN 原生图片生成完成且 KMH 收到产物
- THEN 对话显示可预览和保存的图片及实际像素尺寸，重新打开会话仍可查看产物；多张图片各自对应生成记录

场景2: 尺寸要求从简

- GIVEN 用户明确要求 256×256 等像素尺寸
- WHEN 生成产物的实际尺寸与要求不同
- THEN 对话如实显示实际尺寸与要求尺寸，完成状态反映实际交付，不自动另存改尺寸副本

场景3: 产物接入失败

- GIVEN Codex 已生成图片，但 KMH 获取、保存或展示产物失败
- WHEN 对话展示生成结果
- THEN 显示生成成功与 KMH 产物接入失败这两项状态及可用的恢复入口，保留已有原生产物
