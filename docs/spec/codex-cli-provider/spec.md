# 使用本机 Codex 模型运行 KMH Agent

用户通过可独立分享的 `@kmh/codex-cli` 插件，在 KMH 使用本机官方 Codex CLI 中的模型。KMH 管理技能、工具权限与工具执行，并负责回合与步骤推进；Codex 保留内部模型续推与原生历史管理。默认只使用 KMH 的工具与技能，可在插件详情页开启原生 Codex 工具与技能。模型从官方目录选择，账号经官方授权页登录，两边各自保存会话记录并按绑定对应。首个支持基线为本机调研验证所用的官方 CLI 0.160.0。插件只经公开插件服务接入宿主，不依赖对 DSH 底层的私有改动。Codex 数据目录（CODEX_HOME）与 KMH 数据目录保持一致，不使用用户全局 ~/.codex；一切隔离配置经进程启动参数注入，仅影响单次调用，禁止修改任何 Codex 配置文件。

## feat01: KMH 提示与工具执行

模型使用 KMH 提供的身份、系统提示和工具目录处理用户任务，工具由 KMH 执行并回传结果继续生成。

场景1: 完整提示与工具循环

- GIVEN 账号可用，用户在现有模型选择器选择 Codex 模型
- WHEN 用户发送任务
- THEN 模型收到 KMH 当前系统提示与工具目录，请求工具时 KMH 按现有权限链执行并把结果回传，模型继续生成直到给出最终回复；过程中用户看到流式正文、推理内容和用量

场景2: 工具执行期间保持等待

- GIVEN 模型已请求工具且工具正在执行
- WHEN 工具执行耗时较长
- THEN 生成保持挂起等待结果，对话不中断，工具完成后模型从结果处继续

场景3: 工具超时结果回传

- GIVEN 模型请求的工具带有 KMH 侧执行时限
- WHEN 工具执行超时
- THEN 超时作为该次工具的结果回传给模型，模型据此继续响应；不存在无结果的自动续推

场景4: 模型与推理等级选择

- GIVEN 用户已完成账号登录并查看 Codex 模型选项
- WHEN 打开模型选择或发送任务
- THEN 可选模型来自官方目录的分页返回，默认选中目录首选，推理等级只能选模型声明的可选值；模型能否实际访问以连接测试结果为准

场景5: 请求异常

- GIVEN 请求包含尚未支持的内容，或推理超过时限
- WHEN 模型接入处理该请求
- THEN 显示明确错误，本回合进程结束

## feat02: 工具与技能隔离

默认不使用 Codex 自带的工具与技能，模型可见的工具和技能内容全部来自 KMH；用户可在插件详情页开启原生工具与技能的使用。

场景1: 原生工具关闭（默认）

- GIVEN 开关保持默认关闭，插件开始一个回合
- WHEN 拉起官方 CLI
- THEN 模型目录按裁剪后的集合提供，Code Mode、协作等原生工具不出现在模型可见能力中，模型实际使用的工具全部来自 KMH

场景2: 原生技能显式调用接管

- GIVEN 开关保持默认关闭，官方 CLI 自带技能目录存在
- WHEN 用户在输入中使用“$技能名”式调用
- THEN 不触发 Codex 原生技能，技能内容由 KMH 自己的技能体系提供

场景3: 开启原生工具与技能

- GIVEN 用户在插件详情页开启该开关
- WHEN 新回合开始
- THEN 模型可使用 Codex 原生工具与技能，KMH 的工具与技能同时可用，两者并存且各自按原有方式执行

场景4: 中途变化下一回合生效

- GIVEN 会话进行中开关状态或 KMH 工具表、技能发生变化
- WHEN 当前回合结束、下一回合开始
- THEN 新回合按最新的工具与技能配置启动，模型看到更新后的能力集合

场景5: 裁剪配置应用失败

- GIVEN 开关关闭，本回合启动时工具或技能的隔离配置未能应用
- WHEN 回合准备模型接入
- THEN 回合启动失败并显示明确错误，不进入可能混用原生能力的生成

## feat03: 持续对话与会话绑定

同一 KMH 会话的多个回合共享同一个 Codex 原生会话，两边各自留存记录；同一会话内回合串行执行。

场景1: 首次创建与后续恢复

- GIVEN KMH 会话首次使用 Codex 模型
- WHEN 首个回合开始
- THEN 创建持久化的 Codex 原生会话并立即记录绑定，后续回合恢复同一会话，Codex 记住此前对话内容

场景2: 重启后继续

- GIVEN KMH 重启，或上一回合结束后进程已退出
- WHEN 用户在同一会话继续对话
- THEN 恢复原绑定的原生会话并继续，上下文不丢失；既有内容不重复投递，用 token 用量衡量的上下文长度随对话正常增长而非翻倍；Codex 原生会话保存在 KMH 数据目录下 Codex home 的默认 sessions 目录

场景3: 标题生成走独立临时会话

- GIVEN 会话需要标题生成等辅助模型请求
- WHEN 辅助请求发生
- THEN 使用独立临时会话完成，业务对话的原生历史保持完整

场景4: 压缩两边同步

- GIVEN 会话上下文接近上限，触发压缩
- WHEN Codex 完成原生压缩
- THEN 压缩后的内容全量回传，KMH 用它覆盖本地对话历史，两边保持一致，压缩后可继续对话

场景5: 会话分叉

- GIVEN 用户对一个使用 Codex 的会话执行分叉，分叉携带分叉点前的历史上下文
- WHEN 分叉会话发起回合
- THEN 分叉创建新的原生会话绑定，同样携带分叉点前的历史上下文，原会话的绑定与历史不受影响

场景6: 编辑或重发历史消息

- GIVEN 用户对一个使用 Codex 的会话编辑或重发历史消息
- WHEN 该消息及其后的内容被改写
- THEN 等同于从该点分叉：创建新的原生会话绑定并携带编辑点前的历史上下文，原绑定保留

场景7: 原生会话缺失

- GIVEN 绑定记录指向的原生会话在 Codex 目录中已不存在
- WHEN 用户继续该会话
- THEN 显示明确的恢复错误，用户可开新会话或重新建立绑定

场景8: 回合结束自动回收

- GIVEN 一个回合已完成或已终止
- WHEN KMH 完成回合收尾
- THEN 官方 CLI 进程关闭输入并退出，不残留后台进程

## feat04: 官方账号登录与退出

用户经官方授权页登录自己的 Codex 账号，凭据由官方 CLI 保存与刷新；登录状态依据本地凭据判断，不发起请求验证。

场景1: 本地凭据免登录

- GIVEN KMH 数据目录下 Codex home 已保存登录凭据
- WHEN 用户查看账号状态
- THEN 显示已登录，不要求重新授权，状态检查不发起模型请求；凭据是否真实可用以测试连接结果为准；用户全局 ~/.codex 的既有登录不自动带入

场景2: 登录

- GIVEN 本地没有可用凭据
- WHEN 点击登录
- THEN 打开官方授权页并显示等待状态，授权完成后页面显示已登录

场景3: 登录取消

- GIVEN 授权正在进行
- WHEN 用户取消登录
- THEN 本次尝试终止，回到未登录状态，可重新发起

场景4: 登录失效与重新登录

- GIVEN 本地凭据存在但已失效
- WHEN 发起模型请求或点击测试连接
- THEN 显示登录失效的明确提示，重新登录后恢复可用；仅查看状态不触发失效判定

场景5: 退出账号

- GIVEN 用户已登录
- WHEN 在详情页点击退出账号
- THEN Codex CLI 账号退出并显示未登录，页面说明该操作作用于本机官方 Codex CLI 账号；验收不执行真实退出，以实现检查为准

## feat05: 插件详情页

用户在现有 Web 插件管理区查看 Codex 接入状态并做连接测试。

场景1: 信息展示

- GIVEN 用户已进入 KMH Web
- WHEN 打开 kmh/codex-cli 插件页
- THEN 显示官方 CLI 版本、账号状态、凭据来源、默认模型、推理等级和最近一次连接测试结果，提供登录、测试连接与退出账号入口，以及是否使用原生 Codex 工具与技能的开关（默认关闭，即使用 KMH 的工具与技能）；账号状态依据本地凭据判断，打开页面不发起模型请求，真实可用性以测试连接结果为准

场景2: 切换原生工具与技能开关

- GIVEN 用户已打开插件详情页，开关显示当前配置
- WHEN 用户切换开关
- THEN 新状态立即保存并显示，正在进行的回合不受影响，下一回合按新状态生效

场景3: 测试连接

- GIVEN 用户已完成登录
- WHEN 点击测试连接
- THEN 用当前选择的模型在独立临时会话中执行短文本请求，成功显示验证通过，失败显示原因，完成后临时会话与进程回收

场景4: 版本不支持

- GIVEN 本机官方 CLI 版本低于插件声明支持的最低版本，或找不到官方 CLI
- WHEN 用户打开详情页或发起登录
- THEN 显示明确的版本提示与处理指引

## feat06: 停止与故障恢复

用户可随时停止生成，各类故障有独立提示与恢复路径。

场景1: 停止生成

- GIVEN 生成或工具执行正在进行
- WHEN 用户点击停止
- THEN 工具执行与模型生成同时中止，显示已停止，回合终止后进程清理

场景2: 故障分类提示

- GIVEN 发生用户取消、超时、登录失效、协议错误或进程意外退出
- WHEN 故障发生
- THEN 每类故障显示独立错误码与可读说明，登录状态与既有会话记录不被破坏

场景3: 中途崩溃后恢复

- GIVEN 回合进行中插件或宿主崩溃
- WHEN 下次继续该会话
- THEN 已完成的消息与工具结果按两边日志识别；工具结果不确定的调用记录恢复状态，不重复执行有副作用的操作

场景4: 清理超时兜底

- GIVEN 回合终止后进程未在时限内退出
- WHEN 清理超时发生
- THEN 进程经现有子进程托管机制强制回收，用户看到本回合已结束的明确状态

## feat07: 独立分享

使用者可将插件包导出，交给其他 KMH 使用者安装使用。

场景1: 分享安装包

- GIVEN 插件构建完成
- WHEN 将插件导出并在其他 KMH 安装
- THEN 包含模型接入入口、详情页入口和类型声明，运行依赖为公开包名，安装者使用自己的官方 CLI 与账号

场景2: 版本基线与自定义路径

- GIVEN 官方 CLI 以声明版本为支持基线
- WHEN 使用者本机安装其他受支持版本或位于自定义路径
- THEN 可通过配置指定可执行文件路径，插件按声明行为工作

场景3: 与既有配置共存

- GIVEN 用户继续使用常规 KMH Web
- WHEN 加载插件
- THEN 原有 Agent 预设和工具注册保持有效，用户通过现有模型选择器选择 Codex 模型

场景4: 不依赖宿主私有改动

- GIVEN 宿主运行官方发布的 DSH 版本，未包含任何 KMH 私有底层改动
- WHEN 安装并加载插件
- THEN 模型对话、账号操作、详情页与测试连接完整工作，插件对宿主的全部接入经公开插件服务完成
