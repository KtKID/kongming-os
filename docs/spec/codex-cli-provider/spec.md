# 使用本机 Codex 模型运行 KMH Agent

用户通过可独立分享的 Codex CLI 插件，在 KMH 使用本机官方 Codex 模型。KMH 管理提示、技能、KMH 工具执行与用户审批，并负责会话推进；Codex 执行选中的原生工具并保留自己的对话历史。用户可以同时使用两类工具，在 KMH 查看原生工具的实时进度、结果和待审批操作。账号沿用本机 Codex 登录，模型从官方目录选择，两边各自保存会话记录并保持对应。用户已有的 Codex 配置保持原样，用户配置的 MCP 工具继续可见，本机钩子在 KMH 回合内保持禁用。

本次更新的交付范围是其余原生工具的选择、并存、进度与审批。原生图片生成已有实现，feat10 补充产物与尺寸验收要求。原有 feat01–feat07 的任务完成记录保留为原交付记录；本页新增和修订的场景按新要求验收。实现依据与实施顺序见 [decisions.md](decisions.md#2026-10-07-扩展需求与拟实施方案)。

## feat01: KMH 提示与工具执行

模型使用 KMH 提供的身份、提示与工具目录处理用户任务，KMH 工具按 KMH 权限执行，选中的原生工具按其来源执行，结果用于继续完成任务。

场景1: 完整提示与工具循环

- GIVEN 账号可用，用户在现有模型选择器选择 Codex 模型
- WHEN 用户发送任务
- THEN 模型收到 KMH 当前提示与工具目录，请求 KMH 工具时按现有权限链执行并回传结果，模型继续生成直到给出最终回复；过程中用户看到流式正文、可提供的推理内容和用量

场景2: 工具执行期间保持等待

- GIVEN 模型已请求工具且工具正在执行
- WHEN 工具执行耗时较长
- THEN 生成保持挂起等待结果，对话不中断，工具完成后模型从结果处继续

场景3: 工具超时结果回传

- GIVEN 模型请求的工具带有 KMH 侧执行时限
- WHEN 工具执行超时
- THEN 超时作为该次工具的结果回传给模型，模型据此继续响应；不存在无结果的自动续推

场景4: 模型与推理等级选择

- GIVEN 用户已完成账号登录并查看 Codex 模型选项
- WHEN 打开模型选择或发送任务
- THEN 可选模型来自官方目录的分页返回，默认选中目录首选，推理等级只能选模型声明的可选值；模型能否实际访问以连接测试结果为准

场景5: 请求异常

- GIVEN 请求包含尚未支持的内容，或推理超过时限
- WHEN 模型接入处理该请求
- THEN 显示明确错误，本回合进程结束

## feat02: 工具与技能隔离

默认使用 KMH 工具与技能，并保留已接入的原生图片生成能力。用户可逐项选择其余原生工具，原生技能单独选择；工具来源与执行权限保持清楚。

场景1: 默认能力集合

- GIVEN 用户采用默认选择，插件开始一个回合
- WHEN 用户发送任务
- THEN 模型可使用 KMH 工具、KMH 技能和原生图片生成；命令执行、文件修改、查看图片、网络搜索等其余原生能力按用户选择开放，原生技能默认关闭；用户配置的 MCP 工具继续可见，本机钩子保持禁用

场景2: 原生技能显式调用接管

- GIVEN 原生技能保持关闭，官方 CLI 自带技能目录存在
- WHEN 用户在输入中使用“$技能名”式调用
- THEN 不触发 Codex 原生技能，技能内容由 KMH 自己的技能体系提供

场景3: 选择原生工具并与 KMH 工具并存

- GIVEN 用户在插件详情页选择命令执行、文件修改等受支持的原生工具
- WHEN 新回合开始
- THEN 模型可使用选中的原生工具和 KMH 工具，每次调用显示来源，两类工具各自执行一次；同名工具按来源正确选择，KMH 工具继续遵循 KMH 权限，原生操作需要审批时由 KMH 用户决定

场景4: 中途变化下一回合生效

- GIVEN 会话进行中原生工具选择、原生技能选择或 KMH 工具与技能发生变化
- WHEN 当前回合结束、下一回合开始
- THEN 新回合使用最新能力集合，保留已有对话上下文与正确的工具来源；正在执行的回合按其开始时的选择完成

场景5: 裁剪配置应用失败

- GIVEN 本回合启动时所选能力的限制未能应用
- WHEN 回合准备模型接入
- THEN 显示明确错误并结束本次准备，用户可调整选择后重试

场景6: 能力不可用

- GIVEN 用户选择的原生工具受到本机版本、账号、模型或部署条件限制
- WHEN 查看能力列表或发起任务
- THEN 显示该项不可用及已知原因，任务开始前明确告知能力缺口，已有选择保持可查看

场景7: 旧开关配置

- GIVEN 用户已保存旧的原生工具总开关配置
- WHEN 升级后打开插件详情页
- THEN 显示旧配置对应的实际能力选择与尚待接入的项目，用户可逐项调整；默认关闭的旧配置保留原生图片生成与 KMH 工具的现有使用方式

## feat03: 持续对话与会话绑定

同一 KMH 会话的多个回合共享同一个 Codex 原生会话，两边各自留存记录；同一会话内回合串行执行，官方 CLI 的工作目录跟随 KMH 会话的工作目录。

场景1: 首次创建与后续恢复

- GIVEN KMH 会话首次使用 Codex 模型
- WHEN 首个回合开始
- THEN 创建持久化的 Codex 原生会话并立即记录绑定，后续回合恢复同一会话，Codex 记住此前对话内容

场景2: 重启后继续

- GIVEN KMH 重启，或上一回合结束后进程已退出
- WHEN 用户在同一会话继续对话
- THEN 恢复原绑定的原生会话并继续，上下文不丢失；既有内容不重复投递，用 token 用量衡量的上下文长度随对话正常增长而非翻倍；Codex 原生会话保存在用户 ~/.codex 的默认 sessions 目录，以来源标识区分插件回合

场景3: 标题生成走独立临时会话

- GIVEN 会话需要标题生成等辅助模型请求
- WHEN 辅助请求发生
- THEN 使用独立临时会话完成，业务对话的原生历史保持完整

场景4: 压缩由 Codex 原生处理

- GIVEN 会话上下文接近上限
- WHEN Codex 在 thread 内完成原生压缩
- THEN 模型侧上下文自动续用压缩结果，KMH 侧历史与差分基线不受影响，对话不中断；KMH 侧发起的压缩请求被明确拒绝

场景5: 会话分叉

- GIVEN 用户对一个使用 Codex 的会话执行分叉，分叉携带分叉点前的历史上下文
- WHEN 分叉会话发起回合
- THEN 分叉创建新的原生会话绑定，同样携带分叉点前的历史上下文，原会话的绑定与历史不受影响

场景6: 编辑或重发历史消息

- GIVEN 用户对一个使用 Codex 的会话编辑或重发历史消息
- WHEN 该消息及其后的内容被改写
- THEN 等同于从该点分叉：创建新的原生会话绑定并携带编辑点前的历史上下文，原绑定保留

场景7: 原生会话缺失

- GIVEN 绑定记录指向的原生会话在 Codex 目录中已不存在
- WHEN 用户继续该会话
- THEN 显示明确的恢复错误，用户可开新会话或重新建立绑定

场景8: 回合结束自动回收

- GIVEN 一个回合已完成或已终止
- WHEN KMH 完成回合收尾
- THEN 官方 CLI 进程关闭输入并退出，不残留后台进程

场景9: 工具目录变化后续聊

- GIVEN 已有会话的 KMH 工具目录或工具名称展示方式发生变化
- WHEN 用户继续该会话或从该会话分叉
- THEN 新回合使用最新工具目录并保留可恢复的历史，工具调用交给对应来源；恢复失败时显示明确原因和重新建立会话的入口

## feat04: 官方账号登录与退出

用户经官方授权页登录自己的 Codex 账号，凭据由官方 CLI 保存与刷新；登录状态依据本地凭据判断，不发起请求验证。

场景1: 本地凭据免登录

- GIVEN 用户 ~/.codex 已保存 Codex 登录凭据
- WHEN 用户查看账号状态
- THEN 显示已登录，不要求重新授权，状态检查不发起模型请求；凭据是否真实可用以测试连接结果为准

场景2: 登录

- GIVEN 本地没有可用凭据
- WHEN 点击登录
- THEN 打开官方授权页并显示等待状态，授权完成后页面显示已登录

场景3: 登录取消

- GIVEN 授权正在进行
- WHEN 用户取消登录
- THEN 本次尝试终止，回到未登录状态，可重新发起

场景4: 登录失效与重新登录

- GIVEN 本地凭据存在但已失效
- WHEN 发起模型请求或点击测试连接
- THEN 显示登录失效的明确提示，重新登录后恢复可用；仅查看状态不触发失效判定

场景5: 退出账号

- GIVEN 用户已登录
- WHEN 在详情页点击退出账号
- THEN Codex CLI 账号退出并显示未登录，页面说明该操作作用于本机官方 Codex CLI 账号；验收不执行真实退出，以实现检查为准

## feat05: 插件详情页

用户在现有 Web 插件管理区查看 Codex 接入状态并做连接测试。

场景1: 信息展示

- GIVEN 用户已进入 KMH Web
- WHEN 打开 kmh/codex-cli 插件页
- THEN 显示官方 CLI 版本、账号状态、凭据来源、默认模型、推理等级和最近一次连接测试结果，提供登录、测试连接与退出账号入口，以及原生工具逐项选择和独立的原生技能选择；账号状态依据本地凭据判断，打开页面不发起模型请求，真实可用性以测试连接结果为准

场景2: 调整原生工具与技能选择

- GIVEN 用户已打开插件详情页，列表显示当前选择与每项可用状态
- WHEN 用户调整原生工具或技能选择
- THEN 新选择立即保存并显示，页面说明下一回合生效；正在进行的回合保持原选择

场景3: 测试连接

- GIVEN 用户已完成登录
- WHEN 点击测试连接
- THEN 用当前选择的模型在独立临时会话中执行短文本请求，成功显示验证通过，失败显示原因，完成后临时会话与进程回收

场景4: 版本不支持

- GIVEN 本机官方 CLI 版本低于插件声明支持的最低版本，或找不到官方 CLI
- WHEN 用户打开详情页或发起登录
- THEN 显示明确的版本提示与处理指引

## feat06: 停止与故障恢复

用户可随时停止生成，各类故障有独立提示与恢复路径。

场景1: 停止生成

- GIVEN 生成、工具执行或用户审批等待正在进行
- WHEN 用户点击停止
- THEN 工具执行与模型生成中止，待审批操作随本回合取消，显示已停止；回合终止后进程清理，迟到的审批答复按过期处理

场景2: 故障分类提示

- GIVEN 发生用户取消、超时、登录失效、协议错误或进程意外退出
- WHEN 故障发生
- THEN 每类故障显示独立错误码与可读说明，登录状态与既有会话记录不被破坏

场景3: 中途崩溃后恢复

- GIVEN 回合进行中插件或宿主崩溃
- WHEN 下次继续该会话
- THEN 已完成的消息与工具结果按两边日志识别；工具结果不确定的调用记录恢复状态，不重复执行有副作用的操作

场景4: 清理超时兜底

- GIVEN 回合终止后进程未在时限内退出
- WHEN 清理超时发生
- THEN 进程经现有子进程托管机制强制回收，用户看到本回合已结束的明确状态

## feat07: 独立分享

使用者可将插件包导出，交给其他 KMH 使用者安装使用。

场景1: 分享安装包

- GIVEN 插件构建完成
- WHEN 将插件导出并在其他 KMH 安装
- THEN 包含模型接入入口、详情页入口和类型声明，运行依赖为公开包名，安装者使用自己的官方 CLI 与账号

场景2: 版本基线与自定义路径

- GIVEN 官方 CLI 以声明版本为支持基线
- WHEN 使用者本机安装其他受支持版本或位于自定义路径
- THEN 可通过配置指定可执行文件路径，插件按声明行为工作

场景3: 与既有配置共存

- GIVEN 用户继续使用常规 KMH Web
- WHEN 加载插件
- THEN 原有 Agent 预设和工具注册保持有效，用户通过现有模型选择器选择 Codex 模型

场景4: 不依赖宿主私有改动

- GIVEN 宿主运行官方发布的 DSH 版本，未包含任何 KMH 私有底层改动
- WHEN 安装并加载插件
- THEN 模型对话、账号操作、详情页与测试连接完整工作，插件对宿主的全部接入经公开插件服务完成

## feat08: 查看原生工具实时进度

用户在 KMH 对话中查看原生工具的开始、执行过程和最终结果，区分工具执行与模型思考。

场景1: 命令与文件操作

- GIVEN 用户启用了原生命令执行或文件修改
- WHEN 模型执行这些工具
- THEN 对话显示工具来源、操作摘要、执行中状态及结果；命令输出随执行更新，文件修改显示可提供的变更内容，失败显示原因

场景2: 其他原生工具与 MCP 工具

- GIVEN 模型使用已选中的查看图片、网络搜索或用户配置的 MCP 工具
- WHEN 工具提供阶段、过程输出或结果
- THEN 对话按实际提供的信息更新同一次调用，结果与来源可查看；原生执行信息展示时该操作保持单次执行

场景3: 长时间执行且缺少细节

- GIVEN 原生工具正在执行，其服务仅提供开始和结束信息
- WHEN 用户等待结果
- THEN 持续显示执行中与已等待时间，进度描述以已收到的信息为准；图片生成按这个规则显示等待状态

场景4: 并发与重复信息

- GIVEN 一个回合中多个工具同时执行或重复收到同一次调用的信息
- WHEN 用户查看进度
- THEN 每次调用保持独立的操作记录，同一次调用的更新合并到原记录，完成结果各自对应原操作

场景5: 刷新与重新打开

- GIVEN 用户已经收到工具进度或完成结果
- WHEN 刷新页面、重新打开会话或重启 KMH
- THEN 已保存的操作记录与结果可重新查看，查看记录保持单次执行；缺少结束确认的调用显示状态待确认

场景6: 工具失败与连接中断

- GIVEN 工具执行失败、用户停止回合或连接意外中断
- WHEN 对话更新操作状态
- THEN 分别显示失败、停止或状态待确认；已有输出保留，后续处理沿用 feat06 的恢复规则

## feat09: 决定原生工具审批

原生工具需要额外权限或用户输入时，KMH 展示真实操作并等待用户决定。

场景1: 批准单次操作

- GIVEN 原生工具请求命令执行、文件修改或额外权限
- WHEN 用户查看并批准请求
- THEN KMH 显示工具来源、操作内容、目标位置、申请权限与授权范围；批准仅覆盖当前请求，原生工具随后执行并继续任务

场景2: 拒绝操作

- GIVEN 原生操作等待用户决定
- WHEN 用户拒绝
- THEN 该操作标记为已拒绝，模型收到拒绝结果并可继续完成任务，其他已授权操作保持原权限

场景3: 用户输入与外部工具确认

- GIVEN 原生工具或 MCP 工具请求用户填写信息、选择选项或完成外部授权
- WHEN 用户查看请求并答复或取消
- THEN KMH 展示问题或授权目的，答复用于对应请求继续执行，取消按该请求的取消或拒绝结果处理

场景4: 停止、重复答复与过期请求

- GIVEN 审批等待期间用户停止回合，或同一请求收到多次答复
- WHEN 系统处理答复
- THEN 同一次请求只采用一次有效决定，已停止回合的审批显示过期，其他会话与回合保持各自的授权

场景5: 缺少审批入口或请求类型未支持

- GIVEN 当前部署没有可用的用户审批入口，或请求的审批类型尚待接入
- WHEN 原生工具申请权限
- THEN 操作保持未执行，显示所缺能力及原因；模型收到明确的拒绝或失败结果，用户可调整任务或部署

## feat10: 验收已有图片生成产物

用户继续使用已接入的原生图片生成，能够查看、保存图片，并核对实际尺寸是否满足要求。

场景1: 图片完成与保存

- GIVEN 用户请求生成图片
- WHEN 原生图片生成完成且 KMH 收到产物
- THEN 对话显示可预览和保存的图片及实际像素尺寸，重新打开会话仍可查看产物；多张图片各自对应生成记录

场景2: 明确像素尺寸

- GIVEN 用户明确要求 256×256 等像素尺寸
- WHEN 生成产物的实际尺寸与要求不同
- THEN 在具备且已获授权的尺寸处理能力时，保留原图并另存符合要求的交付图；交付图经实际尺寸核对后报告完成

场景3: 尺寸处理不可用

- GIVEN 用户指定的尺寸与产物不同，且尺寸处理能力不可用或执行失败
- WHEN 回复生成结果
- THEN 显示实际尺寸、要求尺寸及尚未满足的条件，现有原图可保存，完成状态反映实际交付结果

场景4: 产物接入失败

- GIVEN Codex 已生成图片，但 KMH 获取、保存或展示产物失败
- WHEN 对话展示生成结果
