# Web 会话轨迹时间线

让使用 Kongming Web 的开发者在任意会话（含已结束的历史会话）中，一键查看这场对话「到底发生了什么」：每一轮的用户输入、模型思考与回复、工具调用按发生顺序和真实耗时铺开成账本 + 时间线，可点开任何一步看完整输入、输出、耗时与 token 消耗，快速定位慢在哪一步、错在哪一次调用。

数据来源说明：时序、耗时、token 与工具入参出参来自事件日志（trace.jsonl）；用户输入全文、模型回复与思考全文、系统提示词全文来自会话记录（session 真源）——事件日志里的消息是脱敏摘要（防爆磁盘），正文只在会话记录里，两源在轨迹投影中融合。

## feat01: 打开会话轨迹视图

用户在会话页切换到「轨迹」页签，看到这场会话从头到尾的完整执行轨迹；历史会话同样可回放。

场景1: 查看已完成会话的轨迹
- GIVEN 一个已有多轮对话（含模型回复与工具调用）且已结束的会话
- WHEN 用户打开该会话并切换到「轨迹」页签
- THEN 显示完整轨迹视图：顶部为总览统计、中间为时间线总览、下方为调用明细列表，内容覆盖会话内每一次运行的每一轮

场景2: 新会话无轨迹
- GIVEN 一个刚创建、尚未发送任何消息的会话
- WHEN 用户切换到「轨迹」页签
- THEN 显示空态提示「暂无轨迹数据」，并引导用户回到对话页发送第一条消息

场景3: 轨迹数据不完整
- GIVEN 会话有聊天记录，但轨迹记录缺失或部分内容损坏
- WHEN 用户切换到「轨迹」页签
- THEN 可读出的轨迹部分正常展示；读不出的损坏片段以「记录损坏」占位条目显示在原有位置（保留序号与时间信息，内容不可展开），页面顶部提示「轨迹数据不完整」，整体视图不中断

场景4: 会话正在运行中
- GIVEN 会话正在执行（模型回复或工具调用进行中）
- WHEN 用户切换到「轨迹」页签
- THEN 展示截至目前已发生的轨迹，并在统计区标注「进行中」；本版不自动追加新内容，用户手动刷新后看到最新轨迹

场景5: 会话已不存在
- GIVEN 用户通过历史入口打开一个已被删除的会话的轨迹
- WHEN 页面尝试加载轨迹
- THEN 提示「会话不存在或已删除」，并提供返回会话列表的入口

## feat02: 浏览调用明细账本

用户按时间顺序浏览每一条轨迹记录：谁说的、做了什么、花了多久、花了多少 token、有没有出错。

场景1: 正常浏览明细
- GIVEN 轨迹包含多轮，每轮含用户输入、模型回复、若干工具调用
- WHEN 用户查看明细列表
- THEN 每条记录一行，显示：序号（#N）、角色标识与配色（用户 / 模型 / 工具 / 系统）、单行摘要、该条耗时、模型行的 token 数；记录按轮次分组，每组带轮次头（轮次号 + 该轮起止时间）

场景2: 轮次分组展开与收起
- GIVEN 明细列表按轮次分组展示
- WHEN 用户点击某一轮的轮次头（或使用「轮次」一键展开 / 收起全部）
- THEN 该轮（或全部轮次）的记录折叠为一行摘要（轮次号、耗时、包含几次工具调用），再次点击恢复展开

场景3: 工具调用组展开与收起
- GIVEN 同一轮内有多条工具调用
- WHEN 用户使用「调用」一键展开 / 收起全部工具调用
- THEN 所有工具调用记录在「显示完整明细」与「只显示计数摘要」之间切换

场景4: 失败的调用一眼可见
- GIVEN 某次工具调用执行出错
- WHEN 用户浏览明细列表
- THEN 该条记录带错误标识（红色 + 错误图标），摘要直接显示错误信息要点

场景5: 超长轨迹流畅滚动
- GIVEN 一条包含数百条记录的长会话轨迹
- WHEN 用户连续滚动明细列表
- THEN 滚动流畅，页面不卡顿、不整页重绘

场景6: 系统提示词记录
- GIVEN 会话物化过系统提示词（任意会话均满足）
- WHEN 用户查看明细列表
- THEN 账本最前的「会话信息」分组下有一条系统提示词记录（绿色系统图标 + 字数摘要），点开详情可看系统提示词全文；没有事件日志的老会话也能看到这条记录与用户输入记录

## feat03: 查看时间线总览（时长视角）

用户在时间线总览上以「时长」视角查看每一步的耗时分布，一眼定位最耗时的一步；其他视角本版不做，记录备查。

场景1: 时长视角（本版唯一视角）
- GIVEN 轨迹已加载
- WHEN 用户查看时间线
- THEN 每条记录渲染为一段横条，条长按该条自身耗时比例绘制（耗时越长条越长），一眼看出最耗时的一步；无耗时的记录（如系统提示）以最小占位宽度显示

场景2: 三泳道分区
- GIVEN 时间线展示中
- WHEN 用户查看时间线
- THEN 记录按角色分三个泳道上下排列：用户 / 系统输入在最上泳道，模型思考与回复在中泳道，工具执行在最下泳道；同一时刻发生了什么在各泳道时间对齐

场景3: 点选联动定位
- GIVEN 时间线与明细列表同时可见
- WHEN 用户点击时间线上任意一段横条
- THEN 明细列表滚动到对应记录并高亮选中，详情面板同步切换为该记录

待做（本版不做，后续版本补充）：
- 序列视角：每条记录等宽排列，突出调用先后顺序与轮次边界，不体现耗时差异
- 实际时间视角：横轴为真实时间，每条横条的位置与长度对应它真实发生的时间段；模型等待用户输入的空闲间隔在时间轴上留白可见

## feat04: 检查单条记录详情

用户点开任意一条轨迹记录，查看这一步的完整输入、输出与性能指标。

场景1: 查看工具调用详情
- GIVEN 用户在明细列表或时间线中选中一条工具调用记录
- THEN 详情面板显示：工具名、完整输入参数（可读的参数内容）、完整输出结果、错误信息（若失败）、开始时间与耗时、所属轮次

场景2: 查看模型回复详情
- GIVEN 用户选中一条模型回复记录
- THEN 详情面板显示：完整回复文本、思考 / 推理内容（若模型提供了）、token 明细（输入 / 输出 / 思考，以及命中缓存的部分）、首字耗时（从请求发出到第一个字返回的毫秒数）、所属轮次与运行

场景3: 查看用户输入详情
- GIVEN 用户选中一条用户输入记录
- THEN 详情面板显示该轮完整的用户输入内容

场景4: 超长内容折叠展示
- GIVEN 某条记录的输出内容非常长
- WHEN 用户查看详情面板
- THEN 默认截断展示前一段内容并提供「展开全部」，点击后完整显示

场景5: 查看系统提示词详情
- GIVEN 用户选中系统提示词记录
- THEN 详情面板显示系统提示词全文（超长同样默认截断 + 展开全部）

## feat05: 搜索轨迹记录

用户用关键词快速过滤轨迹，定位到提到某文件名、某工具、某报错的那一步。

场景1: 搜索命中
- GIVEN 轨迹中有工具调用读取了 `src/core/runner.py`
- WHEN 用户在搜索框输入「runner.py」
- THEN 明细列表只保留内容匹配的记录（匹配范围含：记录摘要、工具名、输入参数、输出结果、错误信息），命中词高亮；时间线同步只显示匹配记录

场景2: 搜索无命中
- GIVEN 轨迹中没有任何内容包含「数据库」
- WHEN 用户搜索「数据库」
- THEN 显示「没有匹配的记录」，搜索词保留在搜索框内

场景3: 清空搜索恢复
- GIVEN 当前搜索过滤生效中
- WHEN 用户清空搜索框
- THEN 明细列表与时间线恢复完整轨迹，选中状态与分组展开状态保持不变

## feat06: 查看轨迹总览统计

用户在轨迹页顶部一眼看到这场会话的规模与结局。

场景1: 查看汇总统计
- GIVEN 轨迹加载完成
- THEN 统计区显示：会话状态（进行中 / 完成 / 失败 / 取消）、总耗时、总轮次、工具调用总次数、token 总量（输入与输出分开）

场景2: 多次运行分段
- GIVEN 会话中用户先后发送过多次消息（即包含多次运行）
- WHEN 用户查看轨迹
- THEN 轨迹按运行分段展示（每段带运行序号与各自的状态、起止时间、耗时、token 汇总），统计区默认显示整段会话的汇总

## feat07: 工具调用输入参数完整可见

用户在聊天页和轨迹页都能看到工具调用真实的输入参数，而不是空白。

场景1: 聊天页工具卡片显示入参
- GIVEN 模型发起一次带参数的工具调用（如读取某个文件路径）
- WHEN 用户查看聊天页的工具卡片
- THEN 卡片显示真实输入参数（如具体路径），参数内容可展开查看

场景2: 轨迹详情显示入参
- GIVEN 同一次工具调用出现在轨迹中
- WHEN 用户选中该条记录查看详情
- THEN 详情面板展示与实际执行一致的完整输入参数
