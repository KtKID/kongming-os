核心架构原则

  • evolution 子系统频道无关：src/evolution/ 不 import src/web/*（claude_evidence_selector → jsonl_history 单点白名单）
  • EvolutionManager 唯一门面：频道方只通过 enabled / notify_user_message / register_event_route / unregister_event_route 4 个 API 接入
  • TranscriptProvider Protocol 解耦数据源：每个频道实现自己的 Provider，EvolutionManager 不知道是 claude/codex/native
  • EvolutionEventBus 按 thread_id 路由：reviewer 发的事件统一进 bus，bus 根据 event.run_id 解析 thread_id 找对应频道 sink
  • mini ToolRegistry 内部装配：manager 自己装 evolution_write 工具，频道方零感知
  • 总开关：config.evolution.learning.enabled 控制 manager.enabled，disabled 时所有 API 都是 no-op
