# 查看 Codex 额度并随所选模型显示剩余额度

用户在 KMH Web 的现有 Codex CLI 插件详情页查看账号剩余额度、重置时间、额外 Credits 和可用重置卡。在会话中，输入框旁默认显示当前所选 Codex 模型对应的剩余额度，用户可以调整显示方式与提醒阈值。输入框附近的额度展示跟随当前会话已确认选择的模型来源；首次打开、切换模型、切换会话和重新连接后均采用当前选择。

本期覆盖额度查看、常驻显示和低额度提醒；重置卡提供查看能力。累计使用统计与热力图、每周额度去向、重置卡使用操作和 ZCode 额度查询分别留作后续需求。后续接入其他模型来源的额度时，输入框同一位置按当前模型来源展示对应额度。本期的账号与会话行为继续遵循 [Codex CLI provider 规格](../codex-cli-provider/spec.md)。

## 界面呈现

详情页采用统一设置卡片、表单行、控件和主题配色，各周期的名称、剩余数值、进度条与重置时间保持清晰对齐。输入框常驻额度采用统一工具栏按钮，详情浮层沿用统一圆角、阴影和图标；浅色、深色与窄窗口保持可读并适应视口。

## feat01: 在现有 Codex CLI 详情页查看额度和重置时间

用户在设置中的 Codex CLI 插件详情页查看各周期额度，并确认这些数值的更新时间。

场景1: 查看完整额度

- GIVEN 用户已登录 Codex，账号提供短周期和每周额度
- WHEN 用户打开“设置 → 插件 → Codex CLI”
- THEN 现有详情页出现额度区块，各周期显示名称、剩余百分比、剩余进度条、重置日期时间和距离重置的时长；区块显示最近成功更新时间和刷新入口，现有账号、版本和连接测试信息继续可用

场景2: 账号提供部分周期

- GIVEN 账号仅提供每周额度，或提供其他时长的额度周期
- WHEN 用户查看额度区块
- THEN 按账号实际提供的周期展示，并明确标注每个周期的时长

场景3: 首次读取和读取失败

- GIVEN 用户打开详情页时尚无可展示的额度
- WHEN 额度正在读取，或读取失败
- THEN 正在读取时显示加载状态；读取失败时显示简短原因与重试入口，读取成功后显示实际额度；单次读取最多等待 30 秒，超时显示“额度读取超时”并结束加载；冷却等待时显示“状态待更新”和下次可刷新时间

场景4: 刷新已有额度

- GIVEN 额度区块已有一次成功读取的结果
- WHEN 用户点击刷新
- THEN 刷新期间原数值继续可见；成功后数值和更新时间一同更新；失败时保留原数值与原更新时间，并提示刷新失败及重试入口

场景5: 登录状态变化

- GIVEN 用户尚未登录 Codex，或查看期间退出了 Codex 账号
- WHEN 用户查看详情页
- THEN 额度区块提示“登录 Codex 后查看额度”并提供现有登录入口；登录成功后展示当前账号额度，退出后原账号数值从额度区块移除

场景6: 到达显示的重置时间

- GIVEN 某个额度周期已到显示的重置时间
- WHEN 用户继续查看该周期额度
- THEN 该周期提示正在确认重置后的额度；确认成功后显示实际剩余额度与新的重置时间，确认失败时保留原更新时间并提示状态待更新

## feat02: 在详情页查看 Credits 和重置卡

用户在额度区块附近查看账号额外 Credits、消费上限和可用重置卡。

场景1: 查看 Credits

- GIVEN 账号提供额外 Credits 信息
- WHEN 用户查看 Codex CLI 插件详情页
- THEN 展示实际余额或无限额状态；账号提供消费上限时同时展示已用量、上限及重置时间；到期日期采用账号明确提供的日期

场景2: 查看可用重置卡

- GIVEN 账号提供可用重置卡数量和详情
- WHEN 用户查看重置卡区域
- THEN 展示可用数量，各卡片显示账号提供的名称与有效期；本期卡片提供查看能力

场景3: 数量为零与信息待提供

- GIVEN 账号明确返回 Credits 余额或重置卡数量为零，或者相关信息暂未提供
- WHEN 用户查看对应区域
- THEN 已确认的零值明确显示为零；暂未提供的项目标明“账号暂未提供”；重置卡仅有数量时保留该数量，并将详情标为“详情暂不可用”

场景4: 附加信息读取失败

- GIVEN 周期额度已有有效结果，Credits 或重置卡详情读取失败
- WHEN 用户查看详情页
- THEN 已有周期额度继续可见，读取失败的区域显示原因与重试入口；此前已读取的附加信息保留原更新时间

## feat03: 输入框额度跟随当前会话所选模型

输入框额度与模型选择器显示的当前模型来源保持一致，用户切换模型或会话后可以立即看到对应结果。

场景1: 首次打开已选择 Codex 的会话

- GIVEN 当前会话已确认选择来自 codex-cli 的模型，输入框额度显示已开启
- WHEN 用户首次打开会话、刷新网页，或恢复连接
- THEN 输入框旁自动展示 Codex 额度；已有新鲜额度时直接显示，否则显示加载状态并在读取成功后更新，用户可以直接继续输入

场景2: 切换到其他模型来源

- GIVEN 输入框旁正在显示 Codex 额度
- WHEN 用户成功选择来自 zcode-cli 或其他来源的模型
- THEN Codex 额度与 Codex 低额度提醒立即从该输入框移除；本期其他来源的额度能力留待接入，该额度展示位置收起

场景3: 切回 Codex

- GIVEN 当前会话已选择其他来源的模型
- WHEN 用户成功切换到来自 codex-cli 的模型
- THEN 输入框旁立即显示 Codex 额度或其加载状态；读取成功后显示当前模型对应额度，整个过程随模型选择完成而生效

场景4: 同一模型名称来自不同来源

- GIVEN Codex 和其他模型来源都提供名称相同的模型
- WHEN 用户切换这两个来源下的同名模型
- THEN 输入框按已选择的模型来源决定额度归属，Codex 额度仅随 codex-cli 来源显示

场景5: 切换 Codex 内部模型

- GIVEN 当前会话选择了一个 Codex 模型，账号可能提供多个独立额度分组
- WHEN 用户成功切换到另一个 Codex 模型
- THEN 输入框展示新模型对应的额度；共享额度的模型显示同一账号额度，独立额度的模型显示其对应分组；新模型额度尚待确认时显示加载状态

场景6: 切换会话

- GIVEN 会话甲选择了 Codex，会话乙选择了其他来源的模型
- WHEN 用户在两个会话之间切换，或分别打开两个会话
- THEN 每个会话的输入框采用各自已确认的模型选择，只有会话甲显示 Codex 额度；新建会话按其实际默认模型决定展示

场景7: 模型切换失败

- GIVEN 当前会话已有一个确认成功的模型选择及其对应额度展示
- WHEN 用户尝试切换模型且切换失败
- THEN 输入框额度继续对应最终保留的模型选择，模型切换失败原因由现有模型选择界面展示

场景8: 连续切换与较晚返回的额度

- GIVEN 用户连续切换模型或会话，较早发起的 Codex 额度读取仍在进行
- WHEN 较早的额度结果在切换之后返回
- THEN 输入框始终对应当前会话最终确认的模型来源与额度分组；旧结果只在仍匹配当前选择时用于展示

场景9: 模型来源待确认或额度读取失败

- GIVEN 当前模型来源尚待确认，或者已选择 Codex 但额度读取失败
- WHEN 用户查看输入框
- THEN 模型来源待确认时额度展示位置收起；已确认选择 Codex 且读取失败时显示“额度暂不可用”及重试入口，此前有效数值可以保留并标明更新时间；读取超时使用“额度读取超时”，冷却中的空快照显示“状态待更新”

场景10: Codex 登录状态变化

- GIVEN 当前会话已选择 Codex，用户尚待登录或刚退出 Codex 账号
- WHEN 用户查看输入框
- THEN Codex 额度位置显示登录提示并可进入现有登录入口；原账号数值随退出移除，登录成功后展示当前账号额度

## feat04: 调整常驻显示方式并接收低额度提醒

用户在 Codex CLI 插件详情页调整输入框额度显示方式，以及短周期与每周额度的提醒阈值。

场景1: 默认显示与低额度颜色

- GIVEN 用户首次使用额度展示功能并选择了 Codex 模型
- WHEN 用户查看输入框或额度显示设置
- THEN 常驻显示默认采用百分比；账号提供两个周期时同时显示短周期和每周剩余百分比；短周期和每周额度的默认提醒阈值分别为 20%，剩余额度低于阈值时，详情页对应进度条变红，输入框对应的额度百分比或进度条同时变红；提醒采用颜色变化表达

场景2: 显示方式与设置保存

- GIVEN 用户正在查看额度显示设置
- WHEN 用户选择百分比、进度条或关闭显示
- THEN 当前会话按新选择更新，关闭时输入框额度和对应提醒一起收起；刷新网页或重启后继续采用成功保存的选择，详情页额度始终可查看

场景3: 狭窄输入框

- GIVEN 账号提供多个额度周期，输入框空间较窄
- WHEN 用户查看常驻额度
- THEN 优先显示剩余百分比最低的周期及其名称；用户悬浮或点击后可查看全部周期的剩余额度与重置时间

场景4: 调整提醒阈值

- GIVEN 用户在详情页启用了额度提醒
- WHEN 用户分别调整短周期与每周额度的提醒阈值
- THEN 用户可以在插件详情页分别设置“短周期剩余额度低于 xx%”和“每周剩余额度低于 xx%”；每个阈值接受 1–100 的整数，并分别应用于相应周期；非法值在输入位置提示允许范围，原先成功保存的阈值继续生效

场景5: 低于阈值时变红

- GIVEN 额度提醒已开启，额度结果在最近五分钟内成功更新且对应周期仍有效
- WHEN 某个周期的剩余百分比低于其提醒阈值
- THEN 详情页对应进度条变红；当前会话选择了 Codex 且常驻显示已开启时，输入框对应的额度百分比或进度条同时变红，重复刷新保持同一颜色结果

场景6: 额度过期或重置后更新

- GIVEN 额度结果已超过五分钟，或显示的周期已到重置时间
- WHEN 用户继续查看额度
- THEN 展示该结果的更新时间和待更新状态，低额度提醒等待有效结果确认；新的周期成功确认后按新额度判断提醒

场景7: 关闭提醒

- GIVEN 常驻额度显示已开启，低额度提醒正在展示
- WHEN 用户关闭额度提醒
- THEN 常驻数值继续显示，详情页和输入框的额度恢复普通颜色；重新开启后按当前有效额度和已保存阈值判断颜色

场景8: 设置保存失败

- GIVEN 用户正在修改显示方式或提醒设置
- WHEN 保存失败
- THEN 设置区域保留用户草稿并显示失败原因与重试入口；详情页和输入框继续采用原先成功保存的设置，保存成功后再采用新设置

场景9: 阈值边界与额度恢复

- GIVEN 额度提醒已开启，某个周期的提醒阈值为 20%
- WHEN 该周期有效剩余额度分别为 20%、19% 和恢复到 21%
- THEN 20% 时采用普通颜色，19% 时变红，恢复到 21% 时恢复普通颜色；详情页和符合展示条件的输入框采用相同的判断
