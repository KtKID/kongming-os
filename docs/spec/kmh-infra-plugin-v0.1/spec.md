# kmh-infra 服务插件 v0.1

为 KMH Web 编写第二个"服务插件"——kmh-infra：安装并启用后，侧边栏按现有样式出现 Infra 入口（图标加名字"Infra"，不改图标轨与侧栏现有交互），点击在主区内嵌打开本机的 x-dash 面板；同时把 x-infra 的服务查询能力接入助手，会话里可以直接问"本机现在有哪些服务在跑""某个服务现在什么状态"。插件以可独立导出的组合包形式分发，任何 DSH Web 都能经插件页安装启停；x-dash 面板地址、Python 位置、x-infra-mcp 所在目录、暗号所在的环境变量名都收在插件详情里填写。本版本只做查询，不提供任何启停或修改服务的操作。做法上沿用 [MadeMe 服务插件](../../../packages/kmh-mademe/README.md)已验证的形态，不新造一套。

## 前置依赖（已解除）

feat03 依赖 `x-infra-mcp` 能作为标准 MCP 服务被接入。设计阶段核对时它不具备这一能力（没有 `initialize` 握手、响应不带 `jsonrpc` 字段、工具结果不是 `content` 数组），不合规点与验收方式见[协议不合规报告](../../../reports/x-infra-mcp-protocol-compliance.md)。该问题已由 x-infra 侧修复；2026-10-16 复核，报告里的客户端层验收已通过（连接成功、两个工具可见、工具结果形状正确）。feat03 因此不再阻塞，其余 feat 始终不受影响。

## feat01: 侧边栏出现 Infra 入口

用户启用 kmh-infra 后，在现有侧边栏中看到并识别 Infra 入口。

场景1: 启用后可见
- GIVEN 用户已安装并启用 kmh-infra
- WHEN 用户打开或刷新 KMH Web
- THEN 侧边栏出现 Infra 入口：展开态显示插件自带的图标和名称"Infra"，样式与现有侧栏条目一致

场景2: 收起态提示
- GIVEN 侧边栏处于收起状态
- WHEN 鼠标悬停在 Infra 图标上
- THEN 显示"Infra"名称提示

场景3: 停用即消失
- GIVEN kmh-infra 已启用
- WHEN 用户停用或卸载该插件
- THEN Infra 入口从侧边栏消失；若其面板正在主区显示，主区回到会话

场景4: 状态记忆
- GIVEN 用户正在查看 Infra 面板（入口处于选中态）
- WHEN 用户刷新页面
- THEN 入口仍在，且主区恢复显示 Infra 面板

## feat02: 点击内嵌打开 x-dash 面板

用户点击侧边栏的 Infra 入口，在主区内嵌打开 x-dash 面板，与 KMH 会话互不干扰。

场景1: 正常打开
- GIVEN kmh-infra 已启用，x-dash 正在运行，主区显示会话
- WHEN 用户点击 Infra 入口
- THEN 主区从会话切换为 x-dash 面板（地址取插件配置），首次打开显示加载中，入口呈选中态

场景2: 返回会话后再回来
- GIVEN 主区显示 x-dash 面板
- WHEN 用户通过新建会话或点击会话列表回到会话，之后再次点击 Infra 入口
- THEN 主区回到 x-dash 面板，按当前地址重新加载

场景3: 面板打不开
- GIVEN x-dash 没有运行，或配置的地址无法访问、拒绝被内嵌
- WHEN 用户点击 Infra 入口
- THEN 主区切入面板并显示加载中；超过配置的加载超时（默认 8 秒）仍未加载出来时显示"面板可能无法打开"的提示（可能原因：面板未运行或地址无效），并给"在系统浏览器打开"按钮
- THEN 面板工具栏始终提供"在系统浏览器打开"按钮，不必等提示出现

场景4: 更改面板地址
- GIVEN 用户在插件详情中改了 x-dash 面板地址并保存
- WHEN 用户再次点击 Infra 入口
- THEN 按新地址加载面板

场景5: 面板需要登录
- GIVEN x-dash 面板要求登录
- WHEN 用户在面板内登录或退出
- THEN KMH 会话与其他内容不受影响；面板的登录状态由浏览器保留，刷新 KMH Web 后仍在

## feat03: 助手查询本机服务

插件把 x-infra 的服务查询能力接入助手，用户在会话里直接问本机服务的情况。

场景1: 查全部服务
- GIVEN kmh-infra 已启用，x-dash 正在运行，暗号已按配置提供
- WHEN 用户问本机现在有哪些服务
- THEN 助手列出已登记的服务，每项给出名字、状态（在线／离线／出错／未监控／暂未知）与上次检查时间；结果里的地址不含问号之后的登录凭证

场景2: 查单个服务
- GIVEN 同上
- WHEN 用户问某个具体服务现在什么状态
- THEN 助手给出该服务的登记信息，并附一次现场健康检查的结果；未被监控的服务不发起现场检查

场景3: 面板没在运行
- GIVEN kmh-infra 已启用，但 x-dash 没有运行
- WHEN 用户问本机有哪些服务
- THEN 助手明确回答面板没有在运行、因此查不到，并说明这不代表没有服务登记

场景4: 身份校验失败
- GIVEN kmh-infra 已启用，但暗号未提供，或与面板不一致
- WHEN 用户问本机有哪些服务
- THEN 助手明确回答"身份校验错误"，而不是回答"没有服务"
- THEN 面板内嵌打开不受影响

场景5: 名字不存在或有重名
- GIVEN 服务登记表里没有某个名字，或同一名字登记了多次
- WHEN 用户问这个名字的服务
- THEN 没有该名字时，助手明确回答查不到这个名字；有重名时，助手给出第一个并说明存在重名

场景6: 没给名字
- WHEN 用户要求查一个具体服务但没说名字
- THEN 助手提示需要提供服务名字，不返回任何服务的详情

场景7: 停用后失效
- GIVEN kmh-infra 已停用
- WHEN 用户在会话里让助手查本机服务
- THEN 助手不再有这类能力可用

## feat04: 在插件详情中填写配置

用户在 kmh-infra 插件详情中查看和填写不确定的配置项，并可测试面板连通性。

场景1: 查看与修改
- GIVEN kmh-infra 已安装
- WHEN 用户打开 kmh-infra 插件详情
- THEN 详情页直接显示全部配置项：x-dash 面板地址、暗号所在的环境变量名、Python 位置、x-infra-mcp 所在目录、把服务查询能力接入助手的开关，以及插件用到的每个功能性数值（面板加载超时、连通性探测超时、单次查询等待上限）；每项带默认值，可修改并保存

场景2: 无效地址
- WHEN 用户填入格式无效的面板地址并保存
- THEN 提示"地址格式不正确"且不保存

场景3: 测试面板连通性
- GIVEN 面板地址为格式有效的地址（已保存或草稿均可）
- WHEN 用户点击"测试连接"
- THEN 显示探测中状态，数秒内给出结果：可达（含耗时）或不可达／超时

场景4: 暗号环境变量名留空或环境里没有
- GIVEN 用户把暗号所在的环境变量名留空，或填了一个环境里不存在的名字
- WHEN 用户打开面板、并在会话里让助手查本机服务
- THEN 面板照常打开；助手查询时回答"身份校验错误"，并在配置项附近给出应该填什么的提示

场景5: 改地址后助手也换过去
- GIVEN 用户在插件详情中改了 x-dash 面板地址并保存
- WHEN 用户在会话里让助手查本机服务
- THEN 助手按新地址查询，不需要重启 KMH

## feat05: 把插件交给别人用

这个插件是可分享的一条整体：别人装上并填好本机情况后，入口、面板与助手查询一起可用。

场景1: 别人装上就能用
- GIVEN 使用者拿到这个插件包并安装、启用
- WHEN 使用者打开 KMH Web，并按其本机情况填好 x-dash 地址、Python 位置、x-infra-mcp 所在目录与暗号环境变量名
- THEN 侧边栏出现 Infra 入口，面板能打开本机的 x-dash，助手能查询本机服务

场景2: 停用
- GIVEN kmh-infra 已启用并已填好本机配置
- WHEN 使用者停用该插件
- THEN Infra 入口、面板与助手的查询能力一起消失，已填的配置保留

场景3: 重新启用
- GIVEN kmh-infra 处于停用状态且此前填过配置
- WHEN 使用者重新启用该插件
- THEN 入口、面板与助手查询能力恢复，配置仍是停用前填的内容

## 变更记录

- 2026-10-16（用户修正）：暗号取值来源由"KMH 进程环境"改为**插件自行解析**——挂载与配置变更时，先以登录交互 shell 模拟用户终端会话读取 `tokenEnvVar` 指定的变量（暗号的真实存放处，与 x-dash 同源），取不到再回退 KMH 进程环境。动机：插件级关注点不得扩大影响范围到 Web 服务的启动方式——Web 以任何环境启动都不需要预先注入暗号，暗号轮换不需要重启服务（保存任一配置即重取）。C1 的约束不变：暗号仍只以变量名进配置，取值不落任何被跟踪文件、不进日志。实现见 [tech-design 变更记录](tech-design.md#变更记录)与 `packages/kmh-infra/src/token.ts`。
