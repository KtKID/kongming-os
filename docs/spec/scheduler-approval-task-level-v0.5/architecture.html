改动一览（按性质而非按"模块"）

改动编号性质位置大致改动量
① 数据字段 + 1 枚举 scheduler/domain.py（ApprovalMode + TaskExecutionPolicy.approval_mode + resolve_effective_mode helper）
config_loader/models.py（SchedulerApprovalConfig.mode）
scheduler/store.py（schema v4→v5 迁移）		 ~50 行
② 装配点（函数内改动） scheduler/execution_bridge.py:427-435（_drive_runner 构造 wrapper 5 行） ~10 行
③ 核心：dataclass 改造（唯一的类） scheduler/safety_wrapper.py（ScheduleApprovalProvider 加字段 + 改 decide() 方法） ~80 行（含分流逻辑 + metadata 装饰 + 单测）
④ 调用点（各 1 行） wrapper 内 event_sink.emit(...)
bridge 内 store.append_audit(...)		 ~10 行

关键不变量

hard_block 永远不可绕：ScheduleApprovalProvider.decide() 第一步就是 if decision_class == "hard_block": return decision，trust 模式下也透传 rejected。这是用户拍板的核心安全边界，所有改动都不得破坏。
规则真源单一：本 spec 不重新实现安全决策，只在 SafetyGatedApproval 返回的 decision 上做"是否转 approved"的二次裁决。HardBlock / Boundary / Trust / Consent 四段链路在 inner 内部完整跑完，wrapper 只看 decision_class 标签做二选一。
默认行为不变：① 引入的新字段都给默认值（approval_mode=None / mode="fail_closed"），现有部署升级到 v0.5 后行为完全一致；只有用户显式声明 trust 才进入新路径。
