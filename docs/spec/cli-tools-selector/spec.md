# 在 Codex 插件详情页查看与切换工具开关

用户在 KMH Web 的 Codex CLI 插件详情页里，看到这个插件会交给 Codex 的 KMH 工具（逐个列出）和 Codex 原生能力（命令执行、文件修改、查看图片、联网搜索四项，每项注明它覆盖的 Codex 工具名），每一项当前开还是关，并直接在页面上切换。切换立即保存，只对之后普通新建的 Codex 会话生效；已经在进行的会话保持创建时的选择。这个界面由独立插件 `cli-tools-selector` 提供，第一版只适配 codex-cli；工具配置的读取、过滤后交给 Codex、会话恢复仍由 Codex CLI 插件自己负责，选择器关掉或卸载后 Codex 一切照旧。

第一版只做"看得见、切得动、存得上"。原生能力按插件真正能控制的粒度列出：Codex 自己保留的计划工具和用户在 Codex 里配置的 MCP 工具不在开关清单里，由 Codex 自身设置决定。

本 spec 承接 [Codex CLI provider](../codex-cli-provider/spec.md) 已确认的 C1、C4 与 feat05 场景 1、2、5。阶段 A（解除对已删除 DSH 包的依赖、执行点落回 Codex CLI 插件）已交付，见 [修复报告](../../../reports/fix/fix-report-20261014-155635.md)。

## feat01: 查看工具开关清单

用户打开 Codex CLI 插件详情页，看到这个插件会交给 Codex 的工具和能力及其当前开关。

场景1: 正常展示

- GIVEN 用户已进入 KMH Web，Codex CLI 插件已加载，选择器已启用
- WHEN 打开 kmh/codex-cli 插件详情页
- THEN 在现有账号、版本、连接测试信息之后出现“工具开关”区块：“KMH 工具”一列逐个列出工具名、一句说明和当前开关；“Codex 原生能力”一列列出命令执行、文件修改、查看图片、联网搜索四项及其当前开关，每项注明覆盖的 Codex 工具名（如命令执行覆盖 exec_command、write_stdin、shell_command）；区块顶部标注“修改仅对普通新建会话生效”

场景2: 原生能力读不到

- GIVEN 本机官方 CLI 版本未经核实，或读取 Codex 原生能力失败
- WHEN 用户打开详情页
- THEN “KMH 工具”列正常显示；“Codex 原生能力”列显示失败原因和“重新读取”入口，用户修正运行条件后点击重新读取即可刷新

场景3: 未适配的插件

- GIVEN 用户打开其他 CLI 插件（如 kmh/zcode-cli）的详情页
- WHEN 查看页面
- THEN 不出现“工具开关”区块，页面其余内容不受影响

场景4: 清单加载失败

- GIVEN Codex CLI 插件未就绪或清单读取出错
- WHEN 用户打开详情页
- THEN “工具开关”区块显示失败原因和“重试”入口，不显示空清单冒充“没有工具”

## feat02: 切换并保存

用户在清单上直接打开或关闭某一项，结果立即保存。

场景1: 切换成功

- GIVEN 清单已正常显示
- WHEN 用户点击某一项的开关
- THEN 开关立即变为新状态并提示“已保存，仅普通新建会话生效”

场景2: 保存失败

- GIVEN 用户切换了某个开关，但保存没有成功
- WHEN 保存失败
- THEN 开关恢复为原状态，提示“保存失败：原因”，不出现“看起来已切换、实际未保存”的情况

场景3: 已有会话不受影响

- GIVEN 用户已经有一个使用 Codex 的会话在进行，之后在详情页关闭了该会话正在使用的某个工具
- WHEN 用户继续该会话，再普通新建一个 Codex 会话
- THEN 旧会话里 Codex 仍能使用创建时选中的那些工具；新会话里 Codex 不再收到被关闭的工具

场景4: 首次使用

- GIVEN 用户第一次打开带选择器的详情页，之前只用过旧的粗粒度设置
- WHEN 页面加载
- THEN 清单按旧设置显示：KMH 工具默认全部开启，原生能力按旧设置显示；用户之后的切换以清单为准

## feat03: 选择器独立启停

选择器可以单独关闭或卸载，Codex CLI 插件的工具行为不依赖它。

场景1: 关闭选择器

- GIVEN 用户已保存工具配置并创建了会话
- WHEN 用户在插件管理区关闭或卸载选择器，继续已有会话，再普通新建会话
- THEN Codex 详情页不再出现“工具开关”区块；已有会话仍恢复原 Codex 会话和原工具选择；新建会话按当前保存的配置创建

场景2: 重新启用

- GIVEN 选择器关闭期间用户通过配置文件修改过工具开关
- WHEN 用户重新启用选择器并打开详情页
- THEN 清单显示 Codex 当前保存的配置，与配置文件一致

## 第一版不做

以下内容来自上一版实现的设计，用户未提出，按 C5 移出第一版；需要时另立 feat：固定状态与原因展示、联动组展示、待核实状态、新增工具标记、暂时不可用工具的保留展示、整列全部开启或关闭、其他 CLI 插件（如 zcode-cli）的适配。
