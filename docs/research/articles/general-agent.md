# 一个最简单的通用 Agent 框架应该具备什么

AI 不只是聊天了。它开始替你做事——读文件、写代码、发消息、查数据库。

这件事有一个名字：**Agent（智能代理）**。

但 Agent 和 Agent 不一样。有人做聊天机器人，有人做编程助手，有人想做"什么都干"的通用 Agent。这篇文章聊最后一种——如果你要从零搭一个通用 Agent，最少需要什么？

我们不用概念开场。先看一个任务：

> **"去少数派（sspai.com）抓一篇今天的帖子，保存到本地。"**

接下来，我们跟着这个任务走一遍，看 Agent 需要什么。

---

## Agent 有哪些类型

在拆任务之前，先看看市面上都有什么。按"自主度"和"工具广度"两个维度，大致能分出几类：

| 类型 | 代表产品 | 特点 |
|---|---|---|
| **代码型** | Claude Code、Codex、Cursor、Devin | 专注写代码，工具围绕编辑器 / 终端 |
| **工作流型** | n8n AI 节点、Dify | 人预先画好流程，AI 在节点里填空执行 |
| **研究型** | Perplexity Deep Research、Manus | 擅长搜索、阅读、总结，输出研究报告 |
| **对话型** | ChatGPT 深度研究模式 | 能调少量工具，但以对话为主 |
| **通用型** | OpenClaw、AutoGPT | 目标是什么都能干 |

它们不是互斥的。Claude Code 是代码型，但底层架构其实是通用的——只是工具集收窄到开发场景。反过来，通用型 Agent 装上代码工具，也能写代码。区别在于设计目标，不在于能力边界。

通用型的 trade-off 也很明显：**什么都能做 = 什么都能搞砸**。效率不如专用型高，安全压力更大。但换来的是一套框架打天下——换工具集就能换场景。

好，回到任务。

---

## 第一步：谁来接这个任务？—— LLM

用户按下回车，"去少数派抓一篇帖子"这句话进入了系统。

接收它的是一个**大语言模型（LLM）**。GPT-4、Claude、Gemini、本地跑的 Qwen，都行。

LLM 是 Agent 的**大脑**。它负责理解用户说了什么、规划怎么做、决定每一步做什么。其他所有组件都是围着它转的——给它看信息、给它工具用、拦住它别闯祸。

在这个例子里，LLM 看到任务后开始推理：

> "用户要我去 sspai.com 抓帖子。我需要先打开网页，找到今天的帖子，读取内容，然后保存成文件。我手头有哪些工具可以用？"

这一步引出了一个关键问题：LLM 凭什么知道自己该做什么、能做什么？

---

## 第二步：它怎么理解任务？—— Context（上下文）

LLM 不是凭空推理的。它能"看到"的所有信息，组成了一样东西——**上下文（Context）**。

上下文包括：
- **系统提示词**："你是一个通用助手，你可以使用以下工具……"
- **对话历史**：用户刚才说了什么、AI 之前做了什么
- **环境信息**：当前工作目录是 `/home/user`，操作系统是 Linux

它就是 AI 的**工作台面**——台面上摆的东西，就是 AI 做判断的全部依据。

在我们的例子里，上下文告诉 LLM：你有浏览器工具可以打开网页，有文件工具可以写本地文件。LLM 据此制定计划：

> 1. 用浏览器打开 sspai.com
> 2. 找到今天的热门帖子
> 3. 读取帖子内容
> 4. 保存到本地文件

上下文有一个硬限制：**窗口有限**。模型能装的信息就那么多。对话越长、工具结果越多，台面越挤。所以框架需要一个"压缩器"，在台面快满的时候智能地精简——保留关键信息，丢掉冗余。

上下文是**一轮对话的临时信息**。对话结束，台面清空。那下次再聊，它怎么记住你的偏好？这就需要另一个组件。

---

## 第三步：它怎么操作网页和文件？—— Tools（工具）

LLM 想好了计划，但它自己不能打开网页、不能写文件。它需要**工具（Tools）**。

工具是 AI 操作外部世界的手段。没有工具，Agent 就是关在盒子里的聊天机器人——能想，但不能做。

典型的工具包括：
- **浏览器工具**：打开网页、点击、截图
- **文件工具**：读、写、搜索
- **命令工具**：跑 shell 命令
- **网络工具**：搜索、调 API

在"少数派抓帖"这个任务里，LLM 会先后调用这些工具：

```
1. browser_navigate("https://sspai.com")     → 打开少数派首页
2. browser_snapshot()                         → 看看页面上有什么
3. browser_click(选一篇帖子)                   → 点进去
4. browser_snapshot()                         → 读取帖子内容
5. file_write("sspai-post.md", 内容)          → 保存到本地
```

工具是**原子操作**——一个工具做一件事。实际使用中经常需要多个工具按特定流程配合，于是有了 **Skills（技能）**：预包装的工具组合 + 执行策略。工具是锤子和螺丝刀，技能是宜家说明书——告诉你用哪些工具、按什么顺序装。最小框架只需要工具，技能是做大之后自然长出来的。

好，工具准备就绪。但等等——Agent 要往硬盘上写文件了，没人拦一下吗？

---

## 第四步：它要写文件，谁拦着？—— Safety（审批）

Agent 能删文件、能发消息、能跑命令。这些操作都有**副作用**。如果 LLM 幻觉了，自信满满地执行 `rm -rf /`，没有审批机制就是灾难。

所以 Agent 需要一个**审批层（Safety）**——门禁卡，防止做出不可逆的事。

审批通常分层：

| 层级 | 行为 | 例子 |
|---|---|---|
| **硬拦截** | 绝对不允许 | 删除系统文件、访问密钥 |
| **需确认** | 问过用户才放行 | 写文件、发外部请求 |
| **自动放行** | 只读操作，直接过 | 读文件、浏览网页 |

回到例子。Agent 执行到第 5 步，要往硬盘写 `sspai-post.md`。审批层检查：

- 写文件到当前目录 → 不在硬拦截名单里 → 但属于"需确认"级别
- 弹出提示："Agent 想要写入文件 sspai-post.md，允许吗？"
- 用户点"允许" → 放行，文件写入成功

关键思路：**默认拒绝，按需放行。** 读操作可以宽松，写操作必须谨慎，危险操作直接拦截。

---

## 第五步：这五步不是一次完成的—— Loop（循环）

回看整个过程，LLM 不是一次性给出答案的。它走了一个循环：

```
第 1 轮：思考 → 决定打开网页 → 调用 browser_navigate → 拿到页面结果
第 2 轮：看到页面 → 决定读取内容 → 调用 browser_snapshot → 拿到帖子文本
第 3 轮：拿到文本 → 决定保存文件 → 审批通过 → 调用 file_write → 写入成功
第 4 轮：任务完成 → 输出总结 → 结束
```

**这就是 Agent 和 Chatbot 的根本区别。**

Chatbot 是一问一答，结束。Agent 是拿到任务后**自己决定"还没做完，继续"**。它可能要调十次工具、思考十轮才能完成。这个过程中不需要人干预——除非触发了审批。

每一轮循环，上一轮的工具结果被追加到上下文里。LLM 基于越来越丰富的信息做下一轮判断。这就是 Agent 越做越准的原因（也是上下文窗口压力的来源）。

没有循环，Agent 就是个带工具的聊天机器人。有循环，它才是真正的"代理"。

---

## 第六步：下次再聊—— Memory（记忆）

任务完成了。用户关掉对话。

第二天，用户又来了："再抓一篇今天的帖子。"

如果 Agent 没有记忆，它和昨天是陌生人。它不知道你偏好少数派，不知道你喜欢存成 Markdown，不知道昨天的文件保存在哪个目录。

**Memory（记忆）是跨对话持久化的知识。**

| | Context（上下文） | Memory（记忆） |
|---|---|---|
| 生命周期 | 一轮对话 | 永久（直到手动删除） |
| 存什么 | 当前对话、系统提示 | 用户偏好、历史经验、长期知识 |
| 类比 | 工作台面 | 笔记本 |

有了记忆，Agent 才有"成长"的可能。第一次你告诉它"保存到 `~/notes/` 目录"，第二次开聊它就记得。你让它记住上次抓帖遇到的反爬机制，下次它会自动换策略。

上下文是"你现在知道什么"，记忆是"你以前记住了什么"。两层配合，Agent 才能既看清当下，又积累经验。

---

## 全景回顾

跟着"抓一篇少数派帖子"这个任务，我们把六个组件走了一遍：

```
用户："去少数派抓一篇帖子，保存到本地"
  ↓
上下文装配（系统提示 + 对话历史 + 环境信息 → 摆上台面）
  ↓
┌─── 循环开始 ───────────────────────────────┐
│  LLM 思考：需要做什么？                         │
│    ↓                                          │
│  要调工具？                                     │
│    ├─ 否 → 输出回答，结束                       │
│    └─ 是 → 审批（安全检查）                     │
│          ├─ 拒绝 → 告诉 LLM，回到思考           │
│          └─ 通过 → 执行工具                     │
│                ↓                               │
│             结果写回上下文                       │
│                ↓                               │
│             回到"LLM 思考"，继续循环             │
└─── 循环结束 ───────────────────────────────┘
  ↓
记忆：记住用户的偏好，下次开聊还能用
```

六个组件，各司其职：

| 组件 | 在例子中做了什么 | 一句话 |
|---|---|---|
| **LLM** | 理解任务、规划步骤、决定调哪个工具 | 会思考的大脑 |
| **Context** | 把系统提示 + 对话历史摆上台面，让 LLM 有据可依 | 当前工作台面 |
| **Tools** | 打开网页、读取内容、写入文件 | 操作世界的双手 |
| **Safety** | 写文件前弹确认，拦住危险操作 | 防闯祸的门禁 |
| **Loop** | 四轮循环：浏览→读取→保存→完成 | 自主推进的引擎 |
| **Memory** | 记住用户偏好目录和文件格式，下次直接用 | 跨对话的笔记本 |

缺了任何一个：没有 Loop 就不是 Agent，没有 Context 就是瞎子，没有 Tools 就是瘫痪的，没有 Safety 就是裸奔的。

有了这六个，你就有了搭任何 Agent 的底座。
