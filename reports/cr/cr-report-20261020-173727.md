## Spec 对照

默认 probeTimeoutMs=15000，宿主 read 使用 AbortSignal.timeout；正常 RPC transport 响应 abort。cleanupTimeoutMs 默认5000，进程终结确认另有等待。失败会被宿主投影为 error，浏览器收到错误后采用五分钟 retryAt；页面可见且有消费者时自动刷新持续运行，当前没有连续失败次数上限。页面隐藏或最后一个消费者释放后停止调度。这里的一分钟/50毫秒计时是本地状态调度，正式查询仍受五分钟 guard 限制。

## 问题详情

### B1: 浏览器读取缺少独立超时

**来源**: 代码路径与隔离反例

**关联不变量**: INV-CAND-01

**文件**: packages/codex-cli/src/client/quota-store.ts

**位置**: 第83、239–265行

**严重程度**: P1

**置信度**: 已确认

**根因分类**: 实现过程偏移

GIVEN 一个永久pending的fetch，WHEN 调用refresh并将注入时钟推进600000ms，THEN loading仍true、error为null，且没有截止计时器。随后100次调用共享同一promise，请求数1。AbortController只在reset/dispose时中止，普通等待路径缺少截止；finally依赖fetch/json完成。宿主的15秒信号仅约束官方连接侧，浏览器与本机HTTP链路仍有独立挂起边界。

反证检查覆盖调用方、generation、fetch signal和宿主abort；这些保护分别处理重复、过期回执和宿主请求，浏览器HTTP截止仍缺失。证据为 [quota-timeout-20261020-173727/hanging-fetch.json](quota-timeout-20261020-173727/hanging-fetch.json)。建议为quota/context及quota读取覆盖响应头和body解析的独立超时，收口为失败状态，冷却保持五分钟，并验证超时后在途锁释放。

**处置结果**：✅已修复

**处置说明**：额度 HTTP 和设置绑定分别覆盖 30 秒总截止；响应正文及公开配置镜像等待均受限。超时释放在途锁，保留成功记录和五分钟冷却。绑定开始时登记连接重建监听，首次绑定超时后仍可恢复。模拟计时器和真实浏览器挂起用例通过。

### B2: 冷却等待被显示为正在读取

**来源**: 状态路径及隔离反例

**关联不变量**: INV-CAND-02

**文件**: packages/codex-cli/src/client/ComposerQuota.tsx

**位置**: 第108–117行；quota.ts 第86–95行

**严重程度**: P1

**置信度**: 已确认

**根因分类**: spec 缺口

GIVEN 只读account/read期间收到account/updated，WHEN invalidate递增epoch并中止旧读取，THEN 返回state=loading、groups=[]、fetchedAtMs=null，下一次冷却内read继续返回该快照。浏览器refresh已经执行finally并设loading=false，输入框statusText仍按view.state落到quotaLoading。该路径会让“正在读取额度…”覆盖五分钟冷却等待，与当前在途状态脱离。

反证检查覆盖状态schema、QuotaStatus与输入框选择；输入框文案没有使用实际loading布尔值。证据为 [quota-timeout-20261020-173727/cooldown-loading.json](quota-timeout-20261020-173727/cooldown-loading.json)。建议在实际在途时显示读取，冷却或空快照显示待更新，并保留允许刷新时间。

**处置结果**：✅已修复

**处置说明**：两端按实际在途状态展示加载，空快照的冷却等待显示“状态待更新”。真实 Web 定位到 CLI 初始 `account/updated` 中断自身读取，现由 `account/read` 回执核对账号身份；额度阶段账号变化继续中止并淘汰较晚回执。同账号刷新失败保留旧数据。补齐模型目录的上下文依赖，并从公开宿主镜像投影四项偏好，详情页与输入框均已读到实际账号数据。
