# Codex CLI 版本与原生工具清单失配

> Report ID: 20261022-160026
> Schema: x-cr-v2
> Mode: known-issue
> Scope: module
> Review 日期：2026-10-22，Asia/Shanghai
> 审查范围：KMH Codex CLI 配置、原生工具发现和回合准备失败路径。

## 问题详情

### B1: 部署的 Codex CLI 版本超出原生工具清单覆盖

**来源**: 用户报错、当前文件状态、真实版本读取和构建产物复现。

**关联不变量**: INV-CAND-01。

**文件**: `packages/codex-cli/src/native-tools/catalog.ts`。

**位置**: 第63–69行；传播点为 `tool-policy.ts` 第461–468行。

**严重程度**: P1。

**置信度**: 已确认。

**根因分类**: 环境/数据问题。

**问题描述**：配置直接引用 ChatGPT.app 内置 Codex，实际版本为 `0.163.0-alpha.10.2`。这个路径会使用桌面应用随附的 CLI；应用替换所附二进制后，KMH 读取到的版本随之变化。当前工具清单仅覆盖 `0.162.0-alpha.17.2`。本次证据确认当前失配，具体更新操作与更新时刻由桌面应用更新记录进一步追溯。

**不变量检查**：CLI 与清单应满足同一已验证版本条件。最小状态为当前程序加当前 vendor 目录，触发 discoverNativeTools 后获得精确版本 JSON 的 ENOENT。部署兼容条件被破坏，明确终止准备的规则保持。

**贝叶斯更新与反证检查**：读取的是程序真实版本；旧清单存在且包清单包含该目录；编译后的 catalog.js 使用相同路径算法。最低版本检查只比较三段版本，允许0.163通过；工具清单仍要求完整 alpha 版本精确匹配。这两个检查分别承担基础可执行条件与原生工具兼容条件。

**影响**：快照缺少 nativeCatalog、需要发现原生目录的 Codex 回合会失败。已有完整目录快照的续聊会跳过该发现分支。该判断来自调用链检查，本轮运行验证覆盖工具发现失败分支。

**验证方式与结果**：

1. 执行 profile 中的 Codex 程序并传入 `--version`，输出 `codex-cli 0.163.0-alpha.10.2`。
2. 检查 `vendor/native-tools/`，仅存在 `0.162.0-alpha.17.2.json`，JSON 包含5项声明。
3. 导入当前 `lib/src/native-tools/catalog.js`，以进程适配器实际运行该程序的 `--version`；返回与用户报错完全一致的 diagnostic，rows 为空。适配器断言只允许这一次版本读取，模型请求数为0。
4. 默认数据目录候选中的近期插件日志及会话文件未检出该错误标识；本报告以用户报错和直接复现作为事故证据。

**修复建议**：近期恢复可将该插件指向独立保存、经过验证的 `0.162.0-alpha.17.2` 程序。继续使用当前0.163版本时，应采集其真实工具声明并验证命令执行、文件修改、查看图片和联网搜索的隔离行为，再加入对应清单。直接复制旧清单改文件名会将缺少验证的版本标为已验证。长期采用插件明确选择的固定版本，更新时同步完成兼容验证。
