# Codex 额度读取修复

> 日期：2026-10-20；执行：Codex，x-fix；来源：[CR 主档 B1、B2](../cr/cr-report-20261020-173727.md)。

额度请求在 30 秒后结束等待，失败保留上次成功记录。输入框和详情页已在独立 Web 展示实际账号额度。官方读取继续遵守五分钟最短间隔。

## 逐条处置

| 问题 | 根因与修复 | 验证 |
| --- | --- | --- |
| B1 / INV-CAND-01 | 浏览器只有生命周期取消，HTTP 头、正文或设置镜像挂起会持续占用在途锁。额度请求与设置绑定分别增加 30 秒总截止，稳定错误映射为“额度读取超时”，终结后释放请求。连接重建监听在首次等待前登记。 | 模拟头/正文/context/镜像挂起和超时重连；真实浏览器 30 秒后两端显示超时，恢复接口后读数恢复。 |
| B2 / INV-CAND-02 | 冷却内空快照沿用 loading 状态，组件据此显示进行中。现以实际在途标记控制加载，空快照显示“状态待更新”。CLI 初始账号通知交给账号回执核对身份，同账号失败保留缓存，额度读取阶段的账号变化继续中止旧请求。 | 初始通知、晚回执、账号变化、失败缓存与五分钟冷却测试；实际 Web 成功展示每周窗口、Credits 和重置卡详情。 |

实际接入还修复了两处阻断：模型目录消费者补齐 `sessions`、`remote`、`remote.session` 上下文依赖；额度偏好从公开配置 describe 镜像投影自身四个键，保留宿主修订与写权限。完整 provider 表单的其他字段继续由所属设置页处理，写入沿用公开 `remote.settings.mutate`。
