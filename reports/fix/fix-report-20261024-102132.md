# Linux CI 固定 Codex 运行包与验证依赖修复

> 验证日期：2026-10-24，Asia/Shanghai
> 修复人：Codex，按 x-fix 执行

## 问题与根因

Linux CI 使用全新检出，原启动器仅接受 macOS arm64，固定程序目录由 Git 忽略。Linux 启动返回 `CODEX_BUNDLED_PLATFORM_UNSUPPORTED`，导致 Codex 真实回归无法执行。

Web profile 声明的 `dsh-context` 位于根工作区之外，流水线安装后缺少该 Bundle；移动助手测试直接依赖维护者 Home 中的技能目录，干净执行机缺少这些文件。

固定 CLI 的原生 `TurnContextItem.summary` 被[官方协议源码](https://github.com/openai/codex/blob/rust-v0.163.0-alpha.10.2/codex-rs/protocol/src/protocol.rs#L3453)定义为值为 `none` 的旧读者兼容占位。原回归将其预期为逐回合摘要选择 `auto`；模型实际收到的 `reasoning.summary` 已为 `auto`。

## 修复内容

- 启动器识别 Linux x64、Linux arm64 和原 macOS arm64 路径，保持完整版本校验、参数及真实退出码。
- 安装器读取固定版本和平台收据，从官方发布页下载完整运行包，核对 SHA-256 与真实程序版本后发布到忽略目录。失败保留既有程序并清理临时目录。
- Linux CI 在构建前安装固定程序，在常规回归后执行访问记录专项及覆盖率检查。
- 将既有 profiles 纳入根工作区和锁文件，安装声明的注册表 Bundle。原有工作区直接依赖的版本保持原值。
- 移动助手测试在独占临时目录准备完整技能夹具，逐一核对六个实际加载的技能正文进入模型；工具清单、文件读写及跨进程恢复断言保留。
- 摘要回归精确检查原生兼容占位值，继续检查原生推理等级、实际模型请求中的摘要设置与推理内容。生产 TypeScript 和 DSH 源码保持原值。

安装与升级入口集中在 [Codex 运行包说明](../../packages/codex-cli/bin/README.md)，工作区依赖归属见[底座说明](../../docs/kmh/README.md#启动与构建)。
