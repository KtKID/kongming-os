# kmh-team

## 概述

你可以把开发者、写手等固定 Agent 角色加入团队，并按任务点名协作。主 Agent 默认接待普通消息，成员仅在被点名时接收上下文并执行任务。团队沿用普通会话的消息列表、气泡、Markdown 和输入框，成员的完整正文带署名显示。每次成员任务使用新的执行会话，接收提交时选定的近期公开对话。

## 创建角色与团队

固定角色保存名称与职责，可加入多个团队。当前 Web profile 已加载本插件；首次使用时，可以先在插件详情页创建角色。

1. 打开侧栏“插件”，进入“团队会话”详情。
2. 填写“Agent 名称”和“职责说明”，点击“创建角色”。页面显示“已保存”后，角色出现在“固定角色”列表。
3. 打开“新建会话”下方的“团队会话”。主 Agent 自动加入并担任团队 owner，弹窗上方选择模型。
4. 点击“可选角色”中的名称，将其加入团队；点击“已加入”中的名称可移回可选列表。
5. 点击“确认”。页面打开新团队，会话头部显示主 Agent 与所选成员。

主 Agent 的身份由当前预设提供，角色列表只包含额外成员。成员列表为空时，也可创建仅含主 Agent 的团队。点击“取消”返回原页面。

你也可以要求主 Agent 创建固定角色，例如：“创建一个名为写手的团队角色，职责是根据已有事实撰写和修改博客。”主 Agent 的 `kmh_team_create_role` 工具成功保存后，该角色可在后续建群时选择。

## 发送与点名

收件人由输入框中的点名选择决定。输入 `@` 后，从候选菜单选中本团队成员，再填写任务内容并发送。

| 输入方式                      | 接收任务的 Agent                   |
| ----------------------------- | ---------------------------------- |
| 普通消息                      | 主 Agent                           |
| 从候选菜单选择主 Agent        | 主 Agent                           |
| 从候选菜单选择一位成员        | 所选成员                           |
| 从候选菜单选择多位 Agent      | 所选 Agent，各自接收同一提交快照   |
| 手工输入或粘贴 `@开发者` 字样 | 作为普通文字处理，默认交给主 Agent |

同一条消息重复选择同一成员时，该成员执行一次。仅有点名且任务内容为空时，页面提示补充任务。未被选中的成员保持静默，收到任务后才创建执行会话。

例如，从候选菜单选择“开发者”后输入：“读取项目的 package.json，告诉我项目名称，并保留 Markdown 格式。”成员完成后，群聊显示带名称的完整正文；成员工具与思考保存在其执行会话。主 Agent 的回复继续沿用原有流式展示。

当前团队输入支持文字和正文中的成果链接。携带附件时，按页面提示移除附件后发送。

## 上下文与能力继承

“传递上下文数量”控制本次提供的公开群聊记录，默认最近 20 条，包含本次用户消息。公开记录包含用户发言、主 Agent 最终正文和成员最终正文，工具与思考留在执行记录中。

打开“插件 → 团队会话”，填写大于零的整数并点击“保存”。页面显示“已保存”后，后续提交使用新数量；已经提交的任务继续使用其原快照。这个设置作用于本插件的全部团队。

每次点名成员都创建新的执行会话。固定角色在多个团队复用名称与职责，各团队分别提供自己的公开记录。成员在同一团队再次被点名时，也从本次快照开始。主 Agent 继续保留其自身会话历史。

成员使用建群时选定的模型，并从主 Agent 继承工具、skill、工作目录和操作范围，执行同时遵循已有子 Agent 权限规则。较小的窗口可减少输入长度；需要引用较早成果时，可以扩大窗口，或在当前消息补充所需材料。

## 停止与失败恢复

头像下方的“工作中”表示该 Agent 正在实际执行任务。等待执行的任务保持普通头像；同一 Agent 的活动任务全部结束后，工作标记清除。

| 场景                     | 恢复方式                                                           |
| ------------------------ | ------------------------------------------------------------------ |
| 默认模型暂时不可用       | 在建群弹窗选择目录中的可用模型；目录为空时检查模型插件后重新打开   |
| 创建团队失败             | 成员与模型选择继续保留，检查提示后再次确认                         |
| 角色或上下文设置保存失败 | 已填写内容继续保留，点击“重试”；配置冲突时重试会读取当前版本后保存 |
| 团队记录读取失败         | 已读消息继续显示，点击“重试”重新订阅                               |
| Agent 执行失败或输入过长 | 调整任务后重新发送或点名；可缩小上下文窗口                         |
| 公开结果保存失败         | 点击“重试”继续保存已完成结果，保留原任务和结果身份                 |

执行期间点击会话头部的“停止”，会停止该团队的活动任务与待执行任务。页面可能显示“停止仍待确认”；工作标记持续到执行实际结束。已保存的成果继续保留，后续发送或点名创建新任务。

重启 KMH 后，团队读回成员、建群模型和已保存公开消息。上次未完成的任务形成中断通知，后续由用户重新发送或点名。

## 插件配置

`@kmh/kmh-team` 是 Cordis 插件，由 KMH 的 Web profile 同时装配 Host 与 Client。已有实例的部署配置位于 [Web profile patch](../../profiles/kmh-web/cordis.patch.yml)，profile 清单声明本地包依赖。

```yaml
- id: kmh-team
  name: "@kmh/kmh-team"
  config:
    contextMessageCount: 20
    memberMaxParallel: 8
```

| 配置键                | 默认值 | 含义                                                                 |
| --------------------- | ------ | -------------------------------------------------------------------- |
| `contextMessageCount` | `20`   | 正整数；提交时固定公开记录窗口，包含本次用户消息；可在插件详情页保存 |
| `memberMaxParallel`   | `8`    | 正整数；本插件所有团队共用的成员执行容量，超出容量的任务排队         |

主 Agent 的任务按团队串行执行，成员任务可并行执行。配置合成与覆盖顺序见 [Web 配置](../../profiles/kmh-web/README.md)；实际生效的窗口数量以插件详情页为准。

## 实现说明

公开对话与执行记录分别由其所属会话保存。团队插件负责选择收件人、冻结上下文和发布成员结果，原生对话界面负责消息呈现。

<details>
<summary>执行、持久化与客户端接入 — 点击展开</summary>

角色库将名称与职责保存到 storage-domain 的 `kmh_team_roles` v1。建群记录保存所选角色的配置，团队事实追加到 owner Session 的 ignorable 事件。提交先持久化用户消息、快照与任务身份，再进入调度；相同提交身份复用原任务。

执行器通过已有 Session 服务使用 owner，通过 DSH subagent 的 `spawn` 提供方启动 fresh 成员。每个成员任务拥有取消信号与独立 child session。执行结束后，完整正文和终态以同一事件保存；保存重试继续原事件。Host 恢复时将未终结任务记录为中断。

客户端通过 `uiConversation.events` 将公开用户消息和成员结果接入原 Chat 列表。成员消息添加署名，再调用已注册的原生 Assistant renderer；owner 继续使用原流式消息来源，内部上下文输入由对应公开用户气泡承接。原列表统一处理排序、滚动和分页。

头像和工作标记通过 `conversation.session.header.actions` 贡献，接入方式参考 DSH Teams 客户端。标记来自活动任务集合；切换会话时取消旧订阅，新连接读取完整视图。Host、Client 的注册和订阅均按 Cordis effect 生命周期清理。

## 验证

在 Kongming 根目录运行以下命令。包测试会先构建 Host、Client 与浏览器产物，再验证插件行为。

```sh
pnpm --filter @kmh/kmh-team test
pnpm --filter @kmh/kmh-team format:check
pnpm config:web
```

测试使用确定性模型夹具，覆盖真实 AgentLoop、fresh spawn、JSONL 持久化、工具与 skill 继承、角色保存、上下文窗口、重复提交、停止和恢复。客户端测试验证公开用户气泡只出现一次、成员 Markdown 完整投影、迟到结果保持署名，以及卸载恢复原生 renderer。`config:web` 用于核对合成配置中的插件挂载与配置值。

真实页面验收依次检查普通发送、菜单选择成员、完整正文、正确头像的工作标记、停止后重新点名，以及刷新后消息恢复。验证成员工具隔离时，同时查看 child 执行记录与父群聊。

独立测试 profile 的 HTTP smoke 和场景执行记录见[任务记录](../../docs/spec/kmh-team-v0.1/tasks/README.md)。
